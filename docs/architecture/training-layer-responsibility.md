# 培训分层职责：每一层只做一层的事

> 长期架构说明。保留培训类型、培训标准、培训模板、培训计划分层，收口「带入后再改」造成的职责重叠。接口收口实施以已确认的
> `openspec/changes/archive/align-training-layer-apis/` 为准；未确认不得改业务代码、API Contract 或数据库结构。
>
> 开课与考试各是一套核心能力、培训只是调用方，见 `docs/architecture/training-course-exam-capability.md`。
> 培训类型封面及学员列表封面展示见 `docs/architecture/cover-access-protocol.md`。

## 1. 目的

现有设计的分层应对齐功能项，而不是再造一条平行产品链。套娃的原因不是层多，而是多层在产出同一种可编辑课表。

本文约束三件事：

1. **遵照功能项**：类型是尺子，模板是可引用方案，计划是本期实例，开课/考试是真实任务。
2. **每一层只做该层的事**：下层不得复制并再编辑上层的同一类产物。
3. **能力拆分后的后端边界**：计划内容不是开课/考试对象；发布或生成时调用开课能力、考试能力。

不取消分层，不把模板锁死成「计划不能改大纲」，不把培训做成另一套开课或考试。

## 2. 功能项对照

真相源：`docs/product/功能项.csv`（中山项为主）。架构文档中的「培训标准可收紧学时」是对类型基线的加严，不是功能项里的单独课表模块。

| 功能项   | 原文要点                                                | 本设计中的层与产物                        |
|-------|-----------------------------------------------------|----------------------------------|
| 5     | 按工种维护培训类型；含初培学时、复审学时、线上最高占比；企业建计划时**选择**类型以规划内容     | **培训类型**：尺子（分类 + 数字），无课表         |
| 2     | 预警按**培训类型所设置的学时**与实际计划对比                            | 类型尺子用于检查计划；标准若加严，叠加在检查上，不另做一张课表  |
| 6、33  | 按工种或类型制定模板；做完**直接引用**，减少反复创建；模板内容含课程、考试、题库、线下（仿真延期） | **培训模板**：可引用课表方案，不是本期班           |
| 34    | 计划上设置**全部内容**：基本信息、线上、线下、人员、附件                      | **培训计划**：本期实例；选类型必选，选标准/模板可选     |
| 16、24 | 考试安排、开课管理各是一次任务（人员、阅卷人、时间等）                         | **开课能力 / 考试能力**：被计划调用，培训不自造已发布对象 |
| 48、56 | 我的课程、我的考试、我的培训是不同入口；培训内仍学习和考试                       | 同一套报名/考生事实，入口查询条件不同              |

功能项 5 的「学时考核标准」是培训类型上的字段，不是独立「培训标准」课表。培训标准作为可发布、可加严的检查口径，来自领域模型（
`docs/architecture/domain-model.md`）与业务流程（`docs/requirement/business-process.md`）：总学时可收紧，不得低于类型对应初培/复审基线。

## 3. 分层与产物

每一层的输出类型必须不同。相同形状的阶段表不得在类型、标准、模板、计划之间接力粘贴。

```text
培训类型          产物：尺子
                  工种、初培/复审学时、线上占比上限
                  不排课，不带入下一层内容

培训标准          产物：检查口径
                  可加严学时/占比；可声明必含课程/考试/线下
                  供计划发布预检和监管预警使用
                  不生成阶段，不把指定资源「带入」成模板课表

培训模板          产物：课表方案
                  阶段 + 课程/考试/题库/线下引用 + 建议学时
                  按类型制定；发布后可供计划引用
                  不加人，不配本期时间/地点/阅卷人
                  不调用开课、不发布开课/考试

培训计划          产物：本期实例
                  必选类型与初培/复审；可选标准（只为检查）；可选模板（只为复制课表）
                  本期课表、人员、附件、本期执行参数
                  带入模板后可改课表，不回写模板

开课能力          产物：一次开课任务
考试能力          产物：一次考试或题库练习任务
                  create → 配置 → publish → 人员
                  独立管理端与培训生成是两个调用方

线下场次          产物：培训自有执行
                  无独立开课/考试对标物，仍由培训承担
```

```text
类型尺子 ──检查──┐
标准口径 ──检查──┼──► 计划发布预检 / 学时预警
                │
模板方案 ──复制──┘──► 计划课表草稿（可改）──调用──► 开课 / 考试
```

## 4. 各层职责

### 4.1 培训类型

**做：** 维护工种分类及学时考核数字：名称、标签、图片、初培学时、复审学时、线上培训学时最高占比。计划必须选择类型和培训性质（初培或复审），以决定使用哪一套学时基线。类型封面对外字段为
`coverFileId`，读取走受控 GET，见 `docs/architecture/cover-access-protocol.md`。

**不做：** 不编排阶段或内容；不把学时数字「带入」标准或模板变成可改课表行；不表达单次计划的时间、地点、人员。

### 4.2 培训标准

**做：**
针对某一培训类型，发布带版本与有效期的检查口径。允许比类型更严的总学时、更严的线上占比上限；可以声明计划必须包含的课程、考试或线下要求（资源标识，不是一份阶段表）。计划发布预检和监管预警读取这些规则。标准总学时不得低于类型对应初培/复审基线。

**不做：** 不生成、不保存、不「带入」模板或计划的阶段内容；不配阅卷人或开课/考试策略；不替代类型成为学时基线的唯一来源（功能项
2 仍以类型学时为预警对照，标准加严只叠加检查）。

指定资源在计划上的正确形态是**检查缺口**（缺则发布失败），不是粘贴进课表后再允许删掉。

### 4.3 培训模板

**做：** 按培训类型（及可选的标准口径所属类型）编排可复用阶段和内容引用：课程、考试、题库练习、线下。发布后形成可被计划引用的方案。目的对齐功能项
6、33：减少反复创建相同培训。

**不做：** 不绑定参训人员；不写本期开班时间、地点、负责人；不配阅卷人、考试时长/次数等本期执行参数；不调用开课能力或考试能力；不在模板工作台完成「生成执行」。

模板与标准的关系：模板必须与所选类型一致；若引用标准，只表示「按该口径检查」，不把标准规则展开成阶段。

### 4.4 培训计划

**做：** 办一期培训。必选培训类型和初培/复审；可选培训标准（发布时按口径检查）；可选来源模板（把方案复制为本期课表草稿）。在计划上设置功能项
34 要求的全部内容：基本信息、线上/线下内容、人员、附件，以及调用开课/考试所需的本期执行参数。发布后冻结类型、性质、适用最低学时、来源标准/模板快照及内容所用课程/试卷/题库版本。

**不做：** 不自己插入已发布开课或已发布考试来旁路正式发布；不把计划内容 ID 冒充开课 ID 或考试 ID（执行关联仍走
`TrainingExecutionLink`）；不在计划上另做一套与开课/考试重复的阅卷人核心模型——阅卷人写在开课/考试对象上，由计划在调用时传入。

评价表单绑定在计划上，属于计划引用已发布表单版本，不是类型/标准/模板的职责。

### 4.5 开课能力与考试能力

**做：** 各一条生命周期：创建草稿、配置（含阅卷人/策略）、发布、人员。独立管理端与培训生成共用。培训生成创建时带入计划冻结版本和
`planContentId`；发布只认对象上的字段。详见 `training-course-exam-capability.md`。

**不做：** 不理解培训类型、标准或模板；不编排计划阶段；不替代「我的培训」入口。

课程章节测验、题库练习属于开课内部考核。计划内容 `EXAM`、`QUESTION_BANK` 属于考试能力。两套对象，不合并。

### 4.6 线下

线下没有独立开课/考试对标物，仍由培训场次承担。场次配置属于计划本期执行，不放在类型或标准里排课，也不由模板调用场次服务。

### 4.7 学员入口

「我的课程 / 我的考试 / 我的培训」读同一套报名或考生事实，查询条件不同。培训课、培训考从「我的培训」进入，学习与作答仍用报名
ID、Attempt ID。这是入口分层，不是第三套学习引擎。

## 5. 带入规则

**唯一合法的「复制后再改」：** 已发布模板 → 计划草稿课表。

- 空草稿选择模板：直接复制阶段与内容引用。
- 已有课表再换模板：确认后覆盖。
- 复制后计划可增删改内容（功能项 33 的引用 + 功能项 34 的本期设置）。
- 计划改课表不得回写模板。模板改版不影响已发布计划（计划已冻结来源快照）。

**禁止的带入（即套娃来源）：**

| 从          | 到            | 为何禁止                                        |
|------------|--------------|---------------------------------------------|
| 类型学时       | 标准或模板的可编辑内容行 | 类型产物是尺子，不是课表                                |
| 标准指定课/考/线下 | 模板或计划的阶段内容   | 标准产物是检查口径；应在预检中卡缺口，不应粘贴后可删                  |
| 模板上的本期执行参数 | 计划再改一套执行参数   | 执行参数是计划与开课/考试的事；模板若保存默认值，只能当复制提示，不得成为模板必填职责 |

更换计划的类型或标准时：失效课表需确认后处理；新标准只更新检查口径，不自动把规则展开成新阶段。

## 6. 发布检查与预警

计划发布预检读取：

1. 培训类型 + 培训性质 → 适用最低学时、线上占比上限。
2. 若选择了培训标准 → 叠加加严学时/占比，并检查必含资源是否出现在计划内容中。
3. 计划内容自身可执行性 → 资源属于本机构、已发布可冻结版本；课程/考试调用前所需的本期执行参数齐全。

监管预警（功能项 2）继续按计划发布时冻结的适用最低学时与类型口径对比，不以类型或标准的当前值重算历史计划。

缺少必含资源时必须成为预检失败项，而不是前端「带入」成功后的可选项。

## 7. 后端边界（能力拆分之后）

```text
TrainingPlan（编排与检查）
  COURSE 内容 ──调用──► CourseOfferingService
                        create（冻结 courseVersionId、planContentId）
                        → 写入阅卷人等开课配置
                        → publishOffering
                        → enroll(source=TRAINING)
  EXAM / QUESTION_BANK ──调用──► ExamService
                        create（冻结试卷/题库/策略、planContentId）
                        → replaceReviewers
                        → publish
                        → bindCandidates(source=TRAINING)
  OFFLINE ──培训场次──► TrainingOfflineSession
```

`TrainingExecutionProvisioner` 只编排调用顺序，不旁路 `publish`、不直接把新开课/考试标为已发布。

计划内容行表示「这期要有这门课/这场考」，不是开课对象或考试对象。真实任务在开课表、考试表；关联在 `TrainingExecutionLink`。

本期执行参数（完成规则、阅卷人、时长、次数、线下教师、地点、时间和及格线）在计划内容上收集，调用时写入开课/考试/场次。它们不属于标准，也不作为模板的核心职责。

## 8. 现状越界（后续 Change 对照）

下列行为与本文冲突，由 `openspec/changes/archive/align-training-layer-apis/` 收口，确认前不得改业务代码：

1. 类型学时带入标准规则行后继续当可编辑课表维护。
2. 标准指定课程/考试「带入」模板阶段，用户仍可删，且发布预检不卡必含资源。
3. 模板工作台配置完整执行参数，作为计划带入的主数据。
4. 培训 Adapter 插入已发布开课/考试，旁路正式发布（能力拆分 Change 已按调用方收口，新代码不得回退）。
5. 把「生成执行」理解成培训自造的第四份课表，而不是对开课/考试能力的调用。

## 9. 非目标

- 不删除培训类型、标准、模板或计划中的任何一层。
- 不把模板改为「计划不能改大纲」。默认可改；若将来监管要锁大纲，须单独 OpenSpec，且不得改变类型/标准的产物类型。
- 不把课程章节测验合并为计划考试，也不把计划考试改成章节。
- 不在本文规定页面、Mock 或前端联调；契约仍以 `docs/api/*.openapi.json` 为准，前端另开。
- 不回迁存量已发布培训开课为草稿。
- 仿真、人脸识别仍按路线图延期。
