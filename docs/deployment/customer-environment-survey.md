# 安全教育培训系统部署前客户环境调研方案

编制日期：2026-08-27

状态：可直接用于客户访谈与问卷回收；结论未回收前不得据此开工生产部署。

## 1. 为什么必须先调研

本系统的业务流量与普通管理后台不同：学员端课程学习会持续拉取 **HLS 音视频切片** 和 PDF 预览 Range
请求。高峰时带宽、无线接入、对象存储出口和安全策略会直接决定能不能播、卡不卡、能不能出园区。音频切片约 AAC 128
kbps，峰值仍由 720p 视频主导。

当前产品已确认的媒体技术边界（调研时必须当作约束，不能按“以后随便改”承诺）：

| 项    | 当前口径                              | 对部署的含义                                                        |
|------|-----------------------------------|---------------------------------------------------------------|
| 点播格式 | 视频：单码率 720p H.264/AAC HLS，约 5 秒切片；音频：AAC 128kbps、约 5 秒 HLS | **非实测带宽。** 视频未锁 `-b:v`，实际码率随画面变化；2.0～2.5 Mbps/路只作规划假说。音频约 0.13 Mbps/路，不单独撑满培训室容量 |
| 存储   | 私有 MinIO bucket，预览/播放走鉴权代理，禁止公开对象 | 默认 **不是公网 CDN 直链**；要上 CDN 必须先确认安全和架构变更                        |
| 转码   | 园区内 FFmpeg + OnlyOffice，不绑云厂商转码   | 纯内网可落地；云转码在“不能出网”场景不可用                                        |
| 直播   | 业务上是“挂外部直播链接”，本系统不自建直播推流          | 直播带宽通常由腾讯会议/园区直播平台承担，需单独确认                                    |
| 访问端  | PC Web + 移动 H5/企业微信预留             | 要问清学员是园区内网、4G、还是家里看                                           |

调研目标不是收集“感觉”，而是拿到能做 **部署拓扑二选一/三选一** 的硬数据。没有下列四类答案，不得出具最终部署方案：

1. 同时在线看视频的峰值人数
2. 学员是否必须只在园区内网学习，还是允许公网/4G/居家
3. 培训视频、课件是否允许离开内网（含公网 CDN、云 OSS）
4. 园区出口带宽、内网核心交换能力和无线 AP 容量

## 3. 四种候选部署拓扑（先让客户理解选项）

调研问题是为了在下面四种里做选择，而不是开放发挥。向客户讲解时用这一页即可。

### 方案 A：纯内网私有化（默认起点）

```text
园区内网
  学员 PC / 无线 AP
       │
  接入交换机 / 核心
       │
  [应用 + 网关] ── [MySQL/Redis]
       │
  [MinIO 私有桶]  ← HLS/PDF 只走内网鉴权代理
  [FFmpeg / OnlyOffice]
```

- **适用**：视频不能出园区；学员主要在厂区、办公楼学习；等保或保密要求高。
- **带宽瓶颈**：通常不是互联网出口，而是 **楼栋无线、汇聚交换机、MinIO 所在主机网卡**。
- **不做**：公网 CDN、云 OSS、云转码。
- **代价**：远程/居家学习困难；要自建存储与转码容量；多园区要专线或分别部署。

### 方案 B：同一个域名，园内/园外靠 DNS 走到不同出片点

不是两套系统，也不是播放器探测局域网。业务仍是一个 STS：同一个登录、同一条 `play-info`。播放地址用**同一个主机名**（例如
`media.客户域名`），由 **DNS** 决定解析到哪：

```text
play-info 返回 https://media.客户域名/.../index.m3u8

园内 DNS：media.客户域名  →  园区机房 MinIO（局域网，不占上网专线）
公网 DNS：media.客户域名  →  CDN 节点（家里/4G 看，不占园区上行出片）
```

这叫分裂 DNS（内网一套解析、公网一套解析）。学员无感知，入口还是同一个网站。

- **适用**：课件允许出域；既要在园里看、又要在家里/4G 看；园区上网专线扛不住「从机房往外推流」。
- **必须先确认**：出域书面许可、CDN 厂商、防盗链/签名、源站回源。
- **与现状差距**：当前片子全部经应用代理读私有桶；要上 CDN 需签名 URL 等架构变更，不能当配置开关。
- **不做**：两个 App、两套用户库、把 MinIO 改成公开桶、靠播放器判断 Wi‑Fi。

交付时判断走不走这条：见第 3 节决策顺序。装好后播放过程不再判断，只信 DNS。

### 方案 C：公有云 / 托管（SaaS 或单租户云上私有化）

- **适用**：客户接受数据上云；自己不想养 MinIO/转码；学员分散。
- **带宽瓶颈**：客户侧只剩上网出口；媒体由云厂商 CDN 承担。
- **必须先确认**：数据驻留地、等保测评主体、账号与审计、是否允许公网访问管理端。

### 方案 D：园区缓存 + 公网回源（多园区或弱出口）

```text
园区 A MinIO/缓存 ←── 专线/VPN ──→ 中心存储或云源站
园区 B 同上
远程学员走公网 CDN
```

- **适用**：多个化工园区、出口不对称、或“白天厂区看、晚上家里补课”。
- **代价**：最高；要先有 A 或 B 的安全结论，再谈缓存同步。

**决策顺序（强制）：先问安全出域，再问人数带宽，最后才谈机器规格。**

```text
视频/课件能否离开内网？
  ├─ 不能 → 方案 A（纯内网）
  │         再问：是否必须居家学习？必须则需 VPN/零信任，否则不做远程点播
  └─ 能   → 学员是否大量在公网/4G？
              ├─ 否，且内网核心/无线足够 → 仍优先 A（简单、安全边界清晰）
              ├─ 是，或出口明显不够     → 方案 B 或 C
              └─ 多园区 + 专线已有     → 评估 D
```

## 4. 带宽与容量怎么算（给内部用，也可给客户信息化看）

### 4.1 点播（决定性）

**2.0～2.5 Mbps/路不是培训室压测，也不是客户课件均值。** 当前 FFmpeg 只把画面缩到最高 720p（不放大），音频固定 AAC 128
kbps，视频走 libx264 质量模式（未设 `-b:v` / `-maxrate`）。实际播放码率随画面可压程度变化，见下面 2026-08-27 同命令测算。

发给客户的规划码率按 **720p H.264 行业经验 + 下表量级** 取值，并必须标明“假说，待用客户真实课件实测”：

| 档位              |       规划码率 | 说明                |
|-----------------|-----------:|-------------------|
| 保守（课件、PPT 录屏为主） | 2.0 Mbps/路 | 行业经验，非本系统实测       |
| 推荐规划            | 2.5 Mbps/路 | 含余量，用于出口/核心交换桌面推演 |
| 恶劣（实拍、运动画面）     | 3.5 Mbps/路 | 压力上限假说，不作为采购唯一依据  |

**峰值媒体带宽（Mbps）≈ 同时观看人数 × 2.5 × 1.2**

一个人在线看 720p 时，按上式就是 **3 Mbps**。单位必须写清：

| 写法                  | 是否采用          | 换算                            |
|---------------------|---------------|-------------------------------|
| **3 Mbps**（兆比特/秒）   | **采用，单人规划保障** | 2.5 Mbps 画面规划 × 1.2 开销        |
| **375 KB/s**（千字节/秒） | 同一值的字节写法      | 3 ÷ 8 = 0.375 MB/s = 375 KB/s |
| 3 MB/s（兆字节/秒）       | **不要用**       | 那是 24 Mbps，大约 8 倍             |
| 375 kb/s（千比特/秒）     | **不要用**       | 那是 0.375 Mbps，差一个数量级          |

这不是编码器承诺的恒定码率（未锁 `-b:v`，会随画面涨落），而是给网络/出口的**单人保障假说**：PPT/口播往往用不满 3
Mbps；复杂实拍和起播突发可能贴近或短时超过。Wi‑Fi 侧建议按 3 Mbps 预留，不要按 375 kb 去限速。

`1.2` 覆盖 HLS 切片请求开销、TCP 慢启动和少量 PDF/接口流量，同样是经验系数。考试、刷题、管理端 CRUD 相对可忽略，但 **集中开课第一分钟
** 会有连接风暴，交换机会话数和网关并发要比“平均码率”更紧。最终方案应抽客户真实 720p 产物，用体积÷时长得到平均码率，再在培训室做并发样片，而不是沿用本表。

#### 4.1.1 源分辨率与 HLS 平均码率测算（2026-08-27）

目的：核对「La Paloma 约 0.4 Mbps」能否代表高清课，以及 1080p/4K 源会不会按更高像素去拉播放带宽。

方法：用与生产一致的 `FfmpegCommandFactory.video` 参数（`scale=-2:min(720,ih)`、libx264 `medium`、AAC 128k、HLS 5 秒切片、强制
5 秒关键帧）。源片由 FFmpeg `lavfi` 生成，时长 10 秒、30 fps；平均码率 = HLS `.ts` 总体积 × 8 ÷ 时长。这是**单文件转码后的平均码率
**，不是 N 人同时播放压测，也不是客户真实课件。

历史样片（切片策略文档，不是本次合成）：`La Paloma.mp4` 为 640×360、约 153 秒、HLS 约 7.02 MiB，折合约 **0.37 Mbps**。源高度低于
720，转码**不会放大**，学员仍看 360p。

源分辨率如何变成播放分辨率：

| 源分辨率             | 学员实际看到的         | 对带宽的含义                              |
|------------------|-----------------|-------------------------------------|
| 640×360 一类亚 720p | 仍是 360p（不放大）    | 码率会明显低于 720p 课                      |
| 1280×720         | 720p            | 点播上限档                               |
| 1920×1080 / 4K   | **先缩成 720p 再播** | 不会按 1080p/4K 去拉播放带宽；多出来的是源存储和转码 CPU |

本次合成结果：

| 源                        | 转完 HLS 分辨率   |   TS 总体积 |          平均码率 | 说明                                  |
|--------------------------|--------------|---------:|--------------:|-------------------------------------|
| 640×360 `testsrc2`（复杂图案） | 640×360      | 1.07 MiB | **0.90 Mbps** | 与 La Paloma 同为亚 720p，码率仍明显低于 720p 档 |
| 1280×720 `testsrc2`      | 1280×720     | 3.52 MiB | **2.95 Mbps** | 点播上限分辨率；复杂画面可到约 3 Mbps              |
| 1920×1080 `testsrc2`     | **1280×720** | 1.92 MiB |     1.61 Mbps | 先缩小再编码，播放不是 1080p                   |
| 3840×2160 `testsrc2`     | **1280×720** | 1.21 MiB |     1.02 Mbps | 4K 同样缩到 720p；缩小等于先糊一层，本图案更好压        |
| 1280×720 纯色 / SMPTE 色条   | 1280×720     | 0.22 MiB | **0.18 Mbps** | 极好压；接近 PPT/静止画面下限量级                 |

结论（可写进给客户的建议书，但必须带边界）：

1. 源像素高于 720p **不会**按 1080p/4K 播放带宽计；学员侧最高 720p。
2. La Paloma 的约 0.4 Mbps **不能**代表 720p 培训课；低像素源会一直以低分辨率播出。
3. 同样 720p，画面可压程度比源像素影响更大：静止约 0.2 Mbps 量级，复杂图案约 3 Mbps 量级。安全培训口播/PPT
   预期落在两者之间；实拍运动可能达到或超过 2.95 Mbps。
4. 1080p/4K 源主要增加**存储和转码 CPU**，不自动增加每人播放带宽。`testsrc2` 缩小后码率低于「原生 720p
   复杂图案」，是合成图案被低通滤波的结果；真实摄像头 1080p 缩到 720p，一般接近同场景原生 720p，而不是接近 La Paloma。
5. 2.0～2.5 Mbps 规划仍作桌面推演假说；与本次 720p 复杂图案 2.95 Mbps 同一量级，但不能替代客户课件「体积 ÷ 时长」。

转码命令基线见 `docs/architecture/asset-transcode-design.md` 附录 B.1 与 `FfmpegCommandFactory.video`。实现未写 `-crf` 时
libx264 使用默认质量档（与附录中的 `-crf 23` 同量级）。

同时观看带宽速算（仍用 2.5 Mbps 规划假说 × 1.2，不是上表实测均值）：

| 同时观看 |     推荐规划带宽 | 常见对照                       |
|-----:|-----------:|----------------------------|
|   50 | ≈ 150 Mbps | 百兆出口会卡，需千兆内网               |
|  100 | ≈ 300 Mbps | 普通百兆互联网出口不够                |
|  200 | ≈ 600 Mbps | 需万兆到 MinIO 或上 CDN          |
|  500 | ≈ 1.5 Gbps | 纯内网也要规划存储网卡与核心交换           |
| 1000 | ≈ 3.0 Gbps | 优先 CDN 或分区缓存，不宜单机 MinIO 出口 |

同时观看 ≠ 账号总数。必须拆开问：**注册学员、日活、同一小时内看视频的人数、同一分钟内起播人数**。

经验系数（无客户数据时只作访谈追问，不作承诺）：

- 日常分散学习：同时观看 ≈ 日活的 5%～15%
- 入园培训/三级教育集中开班：同时观看可到当班人数的 50%～80%
- 全园区统一“某日完成某课”：按最坏班次人数规划，不要按年平均

阿里云 OSS 与 CDN 按「人数 × 人均每月视频学时」的费用算法见
[aliyun-oss-cdn-cost-estimate-300-users.md](./aliyun-oss-cdn-cost-estimate-300-users.md)（官网案例单价，非报价）。裕龙项目内部署与云费用汇报见
[yulong-onprem-vs-oss-cdn-briefing.md](./yulong-onprem-vs-oss-cdn-briefing.md)。

### 4.2 上传与转码（次要但会卡管理端）

- 管理员上传按分片（默认约 10MB/片），不会一条 HTTP 打满 3GB。
- 转码默认单节点约 2 路并发、单任务约 20～30 分钟超时；高峰集中上传会排队，要问“是否开课前一周集中导课”。
- 存储粗算：1 小时 720p HLS 约 1.0～1.2 GB；源文件另计。保留源+派生，按 **课件时长小时数 × 2.5 GB** 估容量，再加 30% 余量。

### 4.3 经常被忽略的瓶颈

1. **车间/培训室 Wi‑Fi**：核心万兆也救不了 80 人挤在 2 个 AP 上看 720p。
2. **网关 HTTP/2**：PDF 渐进预览依赖浏览器到网关的 HTTP/2；内网自签证书、老 Nginx 可能导致预览慢，被误报成“带宽不够”。
3. **鉴权代理**：片文件若全部回源应用进程，应用会先于网卡打满 CPU/连接数。纯内网大并发时要评估 **对象存储直出 + 短时签名**
   （仍属方案确认项，不是现状默认）。
4. **跨 VLAN / 防火墙一次性会话**：HLS 每 5 秒一片，200 人约 40 请求/秒量级，小防火墙状态表可能先爆。

## 5. 调研原则

1. 数字必须带单位和时间窗，例如“出口 200 Mbps 共享，工作日 9:00–11:00 已用 60%”。
2. “大概很多”一律追问到区间：20 / 50 / 100 / 200 / 500 / 1000。
3. 安全题只接受书面策略口径，口头“应该可以上 CDN”不能作为方案 B 的依据。
4. 直播、人脸、仿真本期不作为点播带宽的替代方案；有需求单列，不混进 HLS 规划。
5. 多园区必须分园区填，不能只填集团总数。

## 7. 访谈时必追问的“会改方案”的问题

下面任一条为“否/不能”时，方案 B/C 基本出局，回到方案 A，并明确远程学习怎么做（VPN 或放弃）：

1. 课件能否出内网？
2. 公网 CDN 是否在安全名录内？
3. 学员设备能否访问公网 HTTPS？
4. 能否为媒体颁发公网证书和域名？

下面任一条为“是”时，即使选方案 A，也必须把无线和教室交换机当成一等公民设计，而不是只堆服务器：

1. 是否存在单教室 ≥30 人同时看视频？
2. 是否存在“全员同一天完成某课”？
3. 学员是否主要用手机连车间 Wi‑Fi？

## 8. 回收后的内部判定表

| 条件                         | 倾向方案                       | 还要补的证据            |
|----------------------------|----------------------------|-------------------|
| K1 不能出域                    | A                          | K27～K29、教室无线 K28  |
| K1 能出域，且 K18 高峰 ≥200，且出口不够 | B 或 C                      | K6/K7 书面约束、C12 域名 |
| K10/K11 家里或 4G 看课，且 K1 能出域 | B 或 C                      | 终端 B12、K14        |
| K23 多园区、K31 有专线、出域受限       | A 每园部署或 D 的内网缓存            | 专线与运维 E 节         |
| K17～K19 均未知                | **不出方案**，先按开班表 K21 桌面推演或试点 | 开班表               |

带宽不满足时的处理顺序（写进建议书，避免一上来加 CDN）：

1. 错峰开课、分班、限制同时开播课数（管理手段，零成本）
2. 教室有线 + 加 AP（方案 A 最常见真因）
3. 存储与网关万兆、播放直出对象存储（仍内网）
4. 二期多码率（弱网降到 540p/360p，需产品变更）
5. 最后才是公网 CDN（必须过 D 节）

## 9. 现场可做的最小验证（有条件再做）

不替代问卷。用于客户说不清带宽时：

1. 培训室做一次：30～50 台终端同时播同一段 720p HLS 样片，记录 AP 信道、丢包、起播时间。
2. 从学员 VLAN 到拟定 MinIO/网关测 iperf 或同等工具，看实际不是标称。
3. 看出口流量图：已有监控、办公视频会议是否已经占满。
4. 确认一台学员电脑访问内网 HTTPS 是否被 SSL 解密成 HTTP/1.1。

## 10. 建议书目录（调研结束后撰写）

1. 客户环境摘要（人数、并发、出域结论、出口与无线）
2. 选定拓扑及否决其他方案的原因
3. 带宽与存储估算（含假设）
4. 服务器与网络清单
5. 安全边界（证书、CDN、下载、审计）
6. 与现状产品的差距（若选 B/C：签名 URL、CDN 回源、多码率等需单独立项）
7. 风险与客户需书面确认的事项
8. 上线节奏（先小范围开班验证并发，再全员）
