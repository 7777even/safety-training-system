# 业务流程

## 端到端培训业务闭环

### 1. 培训标准制定

园区监管端维护培训类型、初培 /
复审学时基线、培训标准和计划模板，并向受监管的企业/培训机构提供可采用的规则输入。培训类型提供学时尺子；培训标准只作为可加严的检查口径，不编排课表；计划模板提供可引用方案。培训标准可以追加更严格的
总学时要求，但不能降低培训类型对应的初培 / 复审基线；各层产物与禁止越界带入见
`docs/architecture/training-layer-responsibility.md`，其他下发机制仍按对应 OpenSpec 确认。

### 2. 培训计划

企业/培训机构端准备教学资源，分别选择培训类型和本次培训性质（初培或复审），再选择适用标准或模板，编排课程、考试和培训阶段，确定人员范围后发布
培训任务。发布前按培训性质选择培训类型对应学时，叠加适用标准并校验计划总学时；发布后冻结培训性质和适用最低学时。

### 3. 课程学习

学员接收任务并完成在线学习；如计划包含线下培训或仿真练习，则同步对应参与记录，具体执行方式为“暂定”。

### 4. 考试

学员参加理论考试或仿真考试（暂定）。系统对客观题自动评分，对需要人工判断的内容进入批阅流程；考试次数、时限和防作弊规则为“暂定”。

### 5. 成绩分析

企业/培训机构端基于学习记录与考试结果形成个人、课程、计划或机构维度的成绩与考情分析；具体指标口径为“暂定”。

### 6. 档案

系统将计划、人员、学习、签到、成绩、附件等信息归集为个人档案、企业/机构档案与期次档案。归档触发条件和修改规则为“暂定”。

### 7. 证书

当学员达到已确认的培训或考试条件时，企业/培训机构端生成并下发证书，学员端可查看或下载。签发规则为“暂定”。

### 8. 监管预警

园区监管端接收计划、学习、成绩与档案等监管数据。计划学时检测使用计划发布时冻结的初培 / 复审适用最低学时，不以培训类型或标准的当前值重算历史
计划；预警等级、通知和处置流程仍按对应 OpenSpec 确认。

## 关键数据流

```text
培训类型 + 培训性质 + 培训标准 → 培训计划（冻结适用最低学时）→ 培训任务 → 学习记录 / 答卷
学习记录 / 答卷 → 成绩分析 → 培训档案 → 证书
培训计划 / 学习记录 / 成绩 / 档案 → 监管预警
```

## 流程边界

本流程用于说明业务顺序和责任交接，不构成状态机、接口调用顺序或数据库事务设计。此类细节必须在对应业务能力的 OpenSpec design 中明确。
