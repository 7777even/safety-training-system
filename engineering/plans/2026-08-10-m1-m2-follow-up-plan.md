# M1/M2 后续开发计划

## 2026-08-10 阶段复核状态

- 阶段 A：代码与静态验收完成。superAdmin 租户信息已由用户成功录入；系统管理、租户上下文、已删除能力清理和 OpenAPI 同步检查通过。
- 阶段 A：真实运行时验收待在后端可访问环境执行。本机本轮检查时后端未监听 8080，因此不将静态通过等同于端到端通过。
- 阶段 B：已创建 `openspec/changes/2026-08-10-complete-m1-course-frontend-loop/`，进入 M1 课程闭环实施。
- 阶段 B 首个修复：移动端课程列表 GET 请求已改为使用 `params`，定向测试 3/3 通过，移动端兼容参数类型检查通过。

## 当前判断

- 系统管理基础页面和登录多租户字段已有实现，但真实联调和可重复业务数据仍未形成闭环。
- 租户、用户、角色的主要契约已同步；标签、岗位、部门仍需区分 superAdmin 的跨租户管理视角与普通企业的当前租户视角。
- 课程管理、素材管理、课程运营和学习接口已有较多代码，但生产路径仍默认使用 Mock，学员 PC/移动学习闭环未完成。
- 题库、试卷、考试和练习仍未形成后端 migration、OpenAPI、前端真实页面和端到端闭环。

## 阶段 A：收口系统管理与测试数据

1. 按后端 OpenAPI 逐项修正标签、岗位、部门和角色的租户选择逻辑；superAdmin 可选择租户，普通企业用户不显示跨租户选择。
2. 删除系统管理中残留的旧机构成员描述、手工 ID 输入和无效组织筛选；保留接口明确要求的只读 `organizationId` 展示字段。
3. 补齐登录错误码、用户扩展字段、角色权限和监管菜单测试。
4. 按 [superAdmin 验证样例数据](../../docs/requirement/superadmin-validation-data.md) 在开发环境录入 `SAFE_ACME`
   企业及组织数据。

验收：superAdmin 能创建完整企业；企业管理员登录后只能看到本租户数据；用户、部门、角色、标签、岗位 CRUD 使用真实
API；无后端已删除页面或接口引用。

## 阶段 B：完成 M1 课程闭环

1. 创建独立 OpenSpec Change，确认课程真实联调范围和验收口径。
2. 关闭素材和课程生产路径 Mock，先联调分类、素材、课程、章节、内容项、版本、开课和报名。
3. 完成学员 PC/移动端“我的课程、课程详情、目录、学习会话、进度上报、完成判定”。
4. 完成管理员查看学习事实和课程完成情况；验证租户隔离、权限、乐观锁和删除保护。
5. 课程内容项本阶段只接入文档和既有可用内容，不等待真实转码；转码继续后置。

验收：`trainer01` 建课开课，`operator01` 报名学习并上报进度，`manager01` 或管理员可查看学习事实，PC 与移动端结果一致。

## 阶段 C：建设 M2 题库与考试闭环

1. 先完成题库与试卷 OpenSpec、migration 和 OpenAPI：知识点、题库、题目版本、导入导出、固定/随机/自定义试卷、不可变试卷版本。
2. 后端先完成题库和试卷真实 CRUD、版本冻结、随机卷种子和权限测试。
3. PC 管理端实现题库、题目、试卷和版本工作台；删除课程阶段遗留的 `organizationId` 请求参数和租户选择器，改由服务端上下文派生。
4. 再建设考试安排、作答快照、自动判分、人工批阅、成绩发布、补考/练习 API 和页面。
5. 学员 PC/移动端实现考试作答、提交、结果查看；教师端实现批阅和成绩发布。
6. 将课程考试内容项回接到已完成的考试安排和成绩事实，不在前端保留另一套 Mock 规则。

验收：完成“建题 → 组卷 → 安排考试 → 学员作答 → 教师批阅 → 发布成绩 → 课程回显结果”的真实闭环，并覆盖权限、重复提交、快照不可变、版本和租户隔离。

## 阶段 D：M1/M2 之后

M2 通过端到端验收后，再进入培训标准/模板/计划和培训执行（M3）。暂不提前开发档案、证书、运营分析、监管预警和真实转码；这些能力依赖稳定的课程、考试和培训事实。

## 每个阶段的固定交付门槛

- OpenSpec 的 proposal/design/tasks/spec-delta 完成并确认。
- API Contract、migration、Mock 和调用方同步。
- 先写失败测试，再实现，再重构。
- 前端 lint、typecheck、目标构建、目标测试和 `git diff --check` 通过。
- 完成规格符合性与代码质量双轴 Review，并更新 QA、进度表和使用文档。
