# Retro：全系统参与人员选择简化

## 有效做法

- 将“怎么选人”和“业务最终绑定谁”拆开，避免部门、标签或规则变化反向改写既有业务事实。
- 先统一解析当前机构启用用户，再由课程、考试、培训、问卷分别写入领域人员表，边界清晰。
- 用 Testcontainers 临时数据库验证破坏性 migration，既覆盖真实 MySQL DDL，又不接触现有数据。

## 发现的问题

- 原模型把 Audience 同时用于报名资格、考生、参训人、问卷参与人、结果可见范围，导致考试也被迫跟着范围模型改造。
- migration 专项测试第一次使用普通测试账号清理临时库时权限不足；第二次的最小旧表夹具缺少保留列，暴露了夹具需要保持真实 DDL
  形状。

## 改进

- 后续所有“按部门选人”需求默认只把部门作为交互输入，提交后保存具体 userId，除非 OpenSpec 明确要求动态规则。
- 破坏性 migration 必须同时验证当前初始化 schema 和最小旧结构迁移；临时库创建、执行、清理均限定在 Testcontainers 内。
- 前端改造单独以新 OpenAPI 开 Change，不在后端 Change 中维护 Mock 或兼容旧字段。
