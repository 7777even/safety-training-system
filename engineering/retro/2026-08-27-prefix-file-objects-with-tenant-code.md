# Retro：文件对象统一增加租户编码根目录

日期：2026-08-27

## 做得好的地方

- 把租户根目录收敛到单一组件，避免 Local、MinIO、multipart 和转码各自硬拼前缀。
- 读取、删除和失败清理继续以已保存对象键为真相源，避免给历史键二次加前缀。
- 真库 IT 直接读取 DEMO 机构主数据，而不是在测试里写死错误编码。

## 问题与原因

- 初版 IT 把示例租户编码写成 `DEFAULT`，实际种子是 `DEMO`，会在真库层失败。
- HLS 播放原先按无前缀路径拼 manifest，新对象写入后必须同时兼容两种布局。
- OpenAPI 仍展示无前缀 `objectName`/`fileUrl` 示例，会误导前端按旧路径理解新对象。

## 改进

- 对象键相关 IT 必须断言真实机构主数据编码，或使用 `DEMO_ORG_CODE` 常量，禁止另造默认值。
- 派生文件读取以数据库已登记 manifest 为锚点推导同目录文件，不要在读取路径硬编码当前租户前缀。
- 对象键布局变化即使不改 HTTP 路径，也必须同步字段说明和成功响应 example。
