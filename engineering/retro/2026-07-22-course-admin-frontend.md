# Retro：课程模块 PC 管理端前端

## 做得好的地方

- 以 OpenAPI Contract 和已确认 OpenSpec 为边界，三个 Task 均先观察失败测试，再完成最小纵向实现。
- 素材、课程基础和课程运营拆分为独立 API 模块，页面统一收敛到用户指定的业务中心目录。
- 双轴 Review 及时发现并修正素材选择、课程版本刷新、内容规则字段和模板可读性问题。

## 问题与原因

- 初版曾按历史后端菜单组件字符串创建兼容入口，与用户最终明确的手动菜单配置方式不一致。
- Task 3 初版使用手输素材 ID 和版本号，虽然能调用接口，但没有形成可靠的管理端操作闭环。
- 原因是实施前只确认了业务范围，未把组件目录、素材选择和版本获取方式作为显式验收点。

## 改进措施

- 后续业务模块在编码前同时确认菜单组件路径和“页面/内嵌组件”关系，并写入 OpenSpec design。
- 所有关联实体优先使用受 Contract 约束的选择器；版本操作始终从详情接口读取最新值，禁止要求用户手工输入。
- Task Review 继续分别检查规格符合性与代码质量，发现问题后完成回归验证再更新任务状态。

## 2026-07-23 Mock 补充复盘

- 有效做法：保持 API 导出签名和真实请求分支不变，在 API 边界切换 Mock，页面无需跟随数据源调整。
- 暴露问题：按领域拆分 Mock 时容易遗漏跨域约束，例如课程素材引用保护、发布版本冻结和下线后重发状态恢复。
- 后续改进：Mock 验收除单接口 CRUD 外，必须覆盖“创建课程 → 编排 → 发布 → 开课 → 报名”和“素材引用 → 删除保护 → 解除引用”的跨页面状态链。
