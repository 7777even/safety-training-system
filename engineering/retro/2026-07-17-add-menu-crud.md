# Retro：系统菜单管理 CRUD

## 做得好的地方

- 在复用现有 `SysMenu` 表和乐观锁基础上完成 CRUD，未引入不必要的表结构变化。
- 将子菜单和角色菜单关联作为删除前置条件，避免级联删除或自动解绑造成意外授权变更。
- 同时覆盖 Mockito 无数据库校验与 Testcontainers 真 MySQL 持久化路径。

## 问题与原因

- 受限沙箱阻止 Mockito 的 Byte Buddy 自附加代理，单元测试需要在获准的测试环境中运行。
- MyBatis 一级缓存会同步已加载实体的乐观锁版本；集成测试初版直接读取可变对象计算期望值，导致断言偏差。

## 改进措施

- 后续 JVM 单测优先在可使用测试代理的 CI/受控环境执行，并保留受限环境下的编译检查。
- 验证乐观锁时在更新前保存版本快照，避免以可能被 ORM 同步更新的实体对象计算期望值。
