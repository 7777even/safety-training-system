# Retro：学员课程简介与受控附件下载

日期：2026-08-13

## 做得好的地方

- 复用报名关联的开课冻结快照，避免课程简介和附件随当前课程草稿漂移。
- 识别到历史快照没有 `courseDownloadAssetId`，改用已冻结的 `assetId` 作为稳定附件标识。
- 把页面元数据聚合与二进制文件下载分离，既减少页面请求，又保持下载授权边界清晰。
- 本人校验和冻结附件归属均在素材/存储读取之前执行，降低越权信息泄漏。
- Review 发现非 MinIO 环境的虚假下载地址后，增加 `STORAGE_UNAVAILABLE` 并锁定不可用原因优先级。

## 遇到的问题

- 初版详情只依据数据库事实计算可下载状态，没有把实际受控下载路由是否注册纳入判断。
- 初版 OpenAPI 只在 description 罗列业务码，没有为 403 与多个 404 分支提供准确示例。
- 文件下载需要在上层授权后再次验证素材与原始源文件关联，通用素材预览接口不能直接承担这条安全边界。

## 原因

- 详情聚合与下载 Controller 的条件注册分属不同组件，初版缺少显式的存储能力连接点。
- 文件流接口和普通 Result 接口的响应结构不同，容易只描述成功流而弱化错误外壳。
- 通用素材文件接口允许源文件或派生文件，权限语义与课程附件的“仅原始上传文件”不同。

## 改进

- 条件注册的能力若会出现在页面可用状态中，必须把能力开关纳入状态计算，并测试开关关闭场景。
- OpenAPI 对一个 HTTP 状态包含多个业务错误时使用具名 `examples`，不得只在文字中罗列。
- 跨域复用文件读取能力时，先定义业务授权和文件关联的不变量，再提供最小专用底层方法。
- 快照附件与当前素材关联采用批量查询并按快照遍历，持续避免 N+1 和当前配置污染冻结事实。
