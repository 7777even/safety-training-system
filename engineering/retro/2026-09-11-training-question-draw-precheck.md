# Retro：培训题库公共抽题与发布预检

## 有效做法

- 把候选查询、判定能力派生和纯抽题分开后，发布预检与开考能够共享同一机械口径，又没有把培训状态或错误码塞进公共引擎。
- 用最大匹配替代顺序随机截取，消除了宽规则抢占窄规则候选导致的随机失败。
- 候选 SQL 用真实 MySQL 验证最新已发布版本、状态、归档和知识点，避免用 Mockito 证明 SQL 正确。

## 发现的问题

- 旧预检把整库题型等同于规则候选，既误伤未命中的简答题，也无法提前发现真实候选不足。
- 原开考候选是逐题查询版本和知识点，既有口径分裂，也有 N+1 查询；统一候选池后改为一次查询。
- “练习不评分”会穿透执行快照、Attempt、Candidate 和培训投影，不能只删除预检中的及格线校验就宣称完成。

## 后续改进

- Task 2 必须用新快照 schema 冻结计划题池并复制执行题池，历史执行继续旧路径，禁止回退实时题库。
- Task 3 必须让 `RECORD_ONLY` 形成 `NOT_EVALUATED`，并去除新练习的分数、及格和人工批阅语义；不能用零分代替未评分。
