# Retro：统一课程源文件下载模式

日期：2026-08-14  
Owner：lims

## 做得好的地方

- 从课程创建 DTO、数据库字段和课程快照反查真实枚举，确认问题是下载链路契约漂移而不是数据或存储故障。
- 用真实 `ALL/PARTIAL` 夹具先复现失败，避免只改字符串后留下另一条下载路径继续误判。
- 将课程级门禁集中为共享白名单，详情状态与实际文件下载不再各自维护枚举。
- 保留冻结附件归属和当前文件有效性校验，修复没有扩大到任意素材下载。

## 发现的问题

- 原学员下载 Change 在设计、代码、测试和 OpenAPI 中同时引入虚构的 `ALLOW`，形成了脱离课程真实输入的假绿闭环。
- 成功测试全部使用同一个非法夹具，未覆盖课程创建接口实际会产生的 `ALL/PARTIAL`。
- Review 时发现不可变集合对 null 的处理不能直接假设为 false，需要显式失败关闭。

## 原因

- 新下载能力没有复用课程定义侧已有枚举或统一策略。
- 测试从新设计中的示例反推夹具，没有用课程创建/更新契约做交叉核对。
- OpenAPI 同一文件中的创建 schema 与学员响应 schema 缺少枚举一致性检查。

## 后续改进

- 跨写入端、快照和读取端传播的业务枚举，应集中复用或至少在测试中使用写入端真实合法值。
- 新增读取/授权能力时，应把成功夹具来源追溯到真实创建契约，避免测试与生产输入各自自洽。
- 若后续要求 `ALL` 自动收集课程内容项或辅助材料，应先明确素材范围并另开 Change；本次仅恢复冻结附件清单内的下载能力。
