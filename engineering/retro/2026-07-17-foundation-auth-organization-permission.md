# Retro：认证、组织与权限前端基础能力

## 完成内容

- 建立 PC 与移动端基础登录会话，完成 PC 门户、后台框架及系统设置入口。
- 完成用户、角色、菜单、组织、字典的 PC 管理页面与 Contract API 模块。
- 修复登录完成后 profile 请求缺少 token 的时序问题。
- 补充由 profile 菜单树驱动的 PC 动态路由与系统设置按钮级权限展示。

## 过程发现

- API 调用依赖会话状态时，应先写入 token，再调用受保护的资料接口；否则请求拦截器会读取到旧的空值。
- Element Plus 表格插槽的行类型未自动收窄，需要在组件边界做最小类型适配。
- 树形批量可见性需要避免默认级联改写子节点状态，严格勾选能保持当前可见 ID 集合。
- 后端菜单配置不应直接作为任意运行时 import 来源；应由构建期 `import.meta.glob` 收集本地页面模块，再按菜单层级和组件目录约定解析，跳过不存在的叶子页面。
- 菜单树可能同时包含门户和多个并列后台一级菜单；所有顶层 `/admin` 页面都必须以后台壳承载，不能只对含子菜单的目录节点套用布局。Element Plus 的函数式组件还需要在入口显式加载样式，避免消息提示退化为未定位文本。

## 后续建议

- 在开发环境补齐真实登录和系统设置 CRUD 联调。
- 后续如恢复测试框架，优先覆盖登录 token 注入、后台入口权限、各管理页编辑版本号和删除确认。
