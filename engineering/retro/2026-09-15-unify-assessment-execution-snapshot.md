# Retro：统一考核执行快照与完整性校验

## 根因

课程执行按 Jackson 写入前的规则 JSON 原文计算摘要，而 MySQL JSON 会重排对象键并规范化空白和数字；读取端又对数据库返回文本直接计算，导致业务语义未变化也可能误报
`7063`。培训后续加入统一读取校验时，把课程原有的不稳定摘要暴露了出来。

更深层原因是冻结事实被拆成七个普通列和一个规则 JSON，课程、独立考试、培训各自维护序列化/hash 分支，没有单一版本化边界。

## 修正

- 用强类型 v1 完整 JSON 作为唯一冻结事实，查询列只承担关联和索引并与快照核对。
- 把规范化 JSON 与 SHA-256 收口到单一 hasher/Codec，拒绝原始文本 hash 和来源特判。
- 把执行刷新改为事务内的“语义相同复用；语义变化且无事实时删除重建”，并覆盖参与、作答、阅卷、结果和冻结题池。
- 用真实 MySQL JSON 往返、篡改、空库 migration 与非空拒绝测试锁定边界。

## 后续

版本化 JSON 的新版本必须新增明确 DTO、版本分支和测试，不得放宽为未知字段猜测读取。任何需要保留既有执行事实的环境都不能直接应用本
migration，必须另建并人工确认数据迁移 Change。共享 VPN 恢复后，只需做真实 H5 登录态冒烟，不以共享库查询替代现有
Testcontainers SQL/完整性证据。
