## 2026-09-23 第三轮补充（三角色真实验收收口）

### 做得好的地方

- **把"没账号"当成可解问题而不是阻塞终点**：经人工授权后用 `POST /api/system/users` 建了 3 个非生产验收账号（密码传 SHA-256 摘要、服务端 BCrypt，不落明文），三角色路径全部跑通。
- **自造角色被及时撤除**：第一版为专家验收临时新建了 `m4_expert_review`，人工指出「没有专家的角色就复用现有的」后，用 `PUT /api/system/users/{id}` 改绑 role 1、`DELETE /api/system/roles/{id}` 删除自造角色，并核对 `us_sys_role` 回到 3 个、`us_sys_user_role` 无 role 4 残留。**验收不该在共享库里留下语言上不存在的权限模型。**
- **迁移前先核对既有数据形态**：执行 `V20260923130000` 软删前逐行核对了 9566～9605 的 `deleted` 取值与 `role_cnt`，确认 32 条有效行确实零角色绑定，才敢整段软删。
- **区分"接口 403"与"探针调错端点"**：学员证书首探 403/1003，查后端发现本人端点是 `certificate:cert:list` **OR** `training:learner:task`，而探针调的是管理端 `/certificate/certificates`；改调 `/certificate/my-certificates` 后 200。**报错先看是不是自己问错了问题，再判断是不是系统缺口。**
- **冷启动时序是浏览器验收的主要噪声源**：查课表数据未加载完就找按钮 → `NOT_FOUND`；把"找按钮"从一次性查询改成 30 秒轮询后稳定。另外据截图识破了"提交其实已成功、只因按钮变成了「查看详情」而误判失败"。

### 发现的限制

- **`nohup ... &` 起的后端进程在命令返回后会被回收**，长跑服务必须用可持久的后台方式启动；判据是"日志停在某行且端口未监听"。
- **专家侧没有独立角色可复用**：`us_sys_role` 三个角色里只有 `admin` 有 `evaluation:record:*`，因此"复用现有角色"在专家场景等价于"用管理员身份查课"，测的是链路可达性而非角色隔离。这一点必须如实标注，不能写成"专家角色验收通过"。
- **证书全链的数据缺口不是实现缺口**：库内模板版本/规则/证书全 0，"上传→设计→发布→绑定→自动签发→预览下载"无数据可跑；把这类缺口与代码缺口分开列，才不会误判完成度。
- 真实库数据在本轮**被他人并行操作过**（档案记录 14:09 出现、证书模板由 0 变 1），说明共享库验收期间的状态可能非我方独占，结论宜以"我方操作对应的证据"为准。

### 后续约束

- 复用现有角色做验收时，必须在 QA 里写清"该角色在库内的真实身份"，避免把管理员上下文记成业务角色上下文。

### 发现的限制

- **菜单数据用绝对路径会绕过布局的模块判定**：后台布局靠 URL 前缀认模块，而成果菜单沿用后端遗留绝对路径 `/result`，两者口径不一致时表现为"页面能打开但整条侧栏消失"。新增任何非标准前缀的后台菜单都需回归侧栏。
- **`menu_type` 决定谁能成为模块**：只有顶层 `D` 类型节点进 `getAuthorizedAdminModules`，成果节点是 `M` 且非顶层，因此永远不会成为模块，只能靠归属回退。
- 侧栏缺陷无法用"页面是否能打开"发现——五个成果页的接口与渲染全部正常，缺陷只在布局层，说明**浏览器验收必须同时断言外壳（布局/侧栏/高亮）而不只是页面主体**。

### 发现的限制

- **Jackson 默认命名策略会把驼峰 getter 压成全小写**：`getXPosition()` → `xposition`。契约写 `xPosition` 时前端发送被**静默丢弃**，只在服务端 `@NotNull` 处爆出来。**这类缺陷过不了编译/类型检查，只能靠"运行时字段名"断言发现。**
- **init 快照吸收增量后，历史 IT 的硬编码基线必然过期**：`file_info_id` 已在 init 里，旧基线用例再跑一遍增量就 `Duplicate column name`；版本号必须有单一来源。
- **上传弹窗确认按钮文案是「完成」**：候选文案缺它就会超时，外观上等同"上传卡死"，实为脚本问题——**"上传超时"先看截图**。
- 设计器坐标是**以底图像素为坐标系**、前端按 `stageScale` 等比缩放渲染；底图尺寸一变，元素的视觉位置就变，所以底图与坐标必须一起版本化（本项目用"改底图 → 生成新版本"承载）。
- 共享库留下了本轮验收数据（模板 5 / 规则 4,5 / 证书 3,4 及若干上传文件记录），是否清理需人工决定。
