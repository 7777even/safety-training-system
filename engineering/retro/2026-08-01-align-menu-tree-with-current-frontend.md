# Retro：菜单展示树与当前前端路由树对齐

日期：2026-08-01

## 做得好的地方

- 先用测试固化前端展示树，再转换后端扁平数据，避免人工比对遗漏层级字段。
- 展示菜单与功能权限分开处理：前端决定 D/M/C，Controller 决定 F 权限全集。
- 复用权限 ID，使菜单重排不破坏自定义角色已有功能授权。

## 问题与原因

- migration 初稿使用全表排除删除，可能误删用户自建菜单；原因是把“种子集合对齐”错误扩大成“菜单全表覆盖”。
- 前端文件未列出 85 个真实后端权限，不能直接作为完整 RBAC 数据源。
- 当前环境无 Docker socket，无法实际执行 MySQL migration IT。

## 改进

- 种子数据 migration 只能操作可枚举的历史种子 ID，不得用 `NOT IN` 清理可能包含用户数据的整张表。
- 后续菜单调整继续保留展示树与权限集合两条独立一致性测试。
- Docker 可用后补跑 migration IT，验证幂等、角色授权和自定义菜单保护。
