# Retro：PC Web 培训接口分层适配

## 做得好的地方

- 前端复制路径收口到创建与 `apply-template`，没有继续在页面拼装模板嵌套阶段。
- 标准、模板、计划按检查、复用课表、本期编排三层职责拆开，避免标准规则悄悄生成资源。
- 来源展示只消费 `planContentId`，学员跳转只消费培训 enter 的返回 ID，保住独立能力与培训引用的边界。

## 问题

- 当前开发会话没有真实登录态和联调数据，无法替代真实课程、考试、题库、线下场次的端到端验证。
- 门户两页已有未提交视觉调整存在两条 HTML 自闭合 lint warning，本次未做无关格式化。

## 改进

- 后续联调发现字段或层级与 OpenAPI 不一致时，记录为契约待对齐项，不在页面猜测兼容字段。
- 在可登录环境补录完整正向、模板覆盖与缺标准资源的验收证据后，再关闭本 Change 的真实链路任务。
- 模板内容这类可选版本字段必须同时在 API 类型、详情回填、资源选择、类型切换、保存请求和请求级回归中出现；仅在发布确认页局部补类型不能算契约同步。
