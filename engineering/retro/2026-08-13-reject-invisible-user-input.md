# 系统用户不可见 Unicode 输入校验 Retro

日期：2026-08-13  
Owner：lims

## 做得好的地方

- 将字符规则收敛为可复用 Jakarta Validation 约束，避免在 DTO、Controller 和 Service 到处分散扫描逻辑。
- 按 Unicode code point 而不是 UTF-16 `char` 遍历，补充平面格式字符也纳入自动化测试。
- 非法输入在调用 Service 前失败，保留原始文本，不通过静默删除字符制造账号、显示值和登录凭证差异。

## 发现的问题

- 既有 Java DTO 只声明密码非空，未落实 OpenAPI 已声明的 64 位小写 SHA-256 摘要格式，导致短字符串也能进入 Service。
- 初始 Web Slice 只覆盖创建接口的统一错误外壳；自审时补齐了更新和重置密码的 400/1001 契约断言。
- “不可见字符”不能依赖肉眼或少量零宽字符清单，需要以明确 Unicode 类别和空白规则定义边界。

## 后续改进

- 新增用户资料类字符串字段时，继续复用该约束并在 DTO 元数据测试中显式登记，避免字段扩展后漏校验。
- 历史脏数据治理若有需要，应独立评估账号标识和外部引用影响后另开 Change，不在写入校验中自动改值。
