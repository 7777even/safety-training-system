# M4 PC 培训成果闭环 Retro（2026-09-21）

## 做得好的地方

- PC 页面以五份当前 OpenAPI 为唯一契约，未补造模板/规则详情以外的接口或历史计算批次。
- 档案、证书下载分别使用管理员与本人端点，业务对象主键不再由用户手工输入。
- 将证书接口的文件和时间字段收敛为 `certificateFileId`、`issuedTime`，避免旧字段造成真实下载入口失效。

## 发现的限制

- 当前开发环境没有管理员、专家、学员的可用登录验收上下文，自动化验证不能证明服务端授权、一次提交和下载文件实际可用。
- 归档服务曾硬编码 `ATTENDANCE`，这与既定“教师评分即完成”规则冲突；现已移除该伪前置，并将真实生成文件 ID 持久化到归档版本，避免前端拿到空文件 ID。Flyway IT 仍受本机 Docker/Testcontainers 不可用阻断。

## 后续约束

- 真实角色验收完成前，Change 各 Task 保持“实现与自动化完成、角色验收待执行”，不得标记为全量完成。
- 归档不得再次引入签到、出勤、扫码或位置等事实；若业务日后需要恢复，必须另建并人工确认 Change。
- 后续若扩展个人/企业档案列表、证书版本历史或规则编辑，必须以新增 OpenSpec 和对应 OpenAPI 为前提。
