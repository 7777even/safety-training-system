# Retro：开考类型由服务端派生

## 做得好的地方

- 把「能不能再开一卷」收口到 `startInternal`，培训 enter 和课程开考共用，避免只拦培训入口。
- HTTP `attemptType` 用 `@JsonIgnore`，旧客户端继续传也不生效。
- 补考仍走专用接口和既有策略，没有把再次进入偷偷升级成补考。

## 问题

- 开考把请求里的 `FIRST` 当真，唯一约束只在令牌。前端每次新 token + 默认 FIRST 就能无限首考。

## 原因

- 课程测验单独做了终态复用，正式考试和培训题库没有套同一条。补考护栏绑在请求类型上，等于把状态机交给了调用方。

## 改进

- 前端只传令牌和设备信息；作答类型由已有答卷派生。
- 明确意图（补考、练习重置）用专用接口，不要写进普通进入的请求字段。
