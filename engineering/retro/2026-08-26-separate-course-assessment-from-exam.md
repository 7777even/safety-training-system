# 课程考核与独立考试来源分离复盘

## 做得好的地方

- 把“可复用资源”“业务任务”“执行快照”“作答与结果事实”拆开后，课程不再依赖已发布考试充当模板，题库练习也不再被错误地要求绑定试卷版本。
- 课程和独立考试共用作答、判分和批阅引擎，但入口、来源校验、阅卷人、成绩规则和结果事实保持分域。
- 数据库同时维护 init 最新完整 SQL 和 Admin 增量 SQL，并用真实 MySQL 验证空库与上一版本升级两条路径。

## 问题与原因

- 原模型让 `exam_id` 同时表达模板与任务，导致 Candidate、Attempt、Reviewer 和课程进度需要依赖上下文字段猜测归属。
- 原批阅 SQL 使用了 Attempt 状态名 `PENDING_REVIEW` 查询 Answer，实际 Answer 状态是 `PENDING_MANUAL`，因此真实待阅答案可能不可见。
- 最初的执行归属增量只改列结构，没有先迁移旧行；真库升级测试补充数据后暴露了该问题。

## 改进

- 后续考核能力一律先确定 `sourceType + sourceBusinessId + resourceType + resourceId`，再创建 Candidate 和 Attempt。
- 状态枚举按实体层分别命名并测试，禁止在 SQL 中复用相似但不同层级的状态字符串。
- 数据库增量涉及归属列替换时，固定采用“加可空新列 → 回填并断言 → 改为非空 → 删除旧列”的顺序。
- 课程自动生效结果继续作为不可变事实扩展统计，不从独立考试发布流水反推课程进度。
