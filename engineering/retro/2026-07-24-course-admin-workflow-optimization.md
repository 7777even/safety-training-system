# 课程管理端工作流优化 Retro

## 做得好的地方

- 将新增、编排、发布和开课集中在同一工作台，通过查询参数保留刷新和前进后退状态。
- 将章节、内容项、材料规则、直播和开课表单改为页内编辑，明显减少业务弹窗层级。
- 素材选择和上传分别形成单一职责组件，并保留现有 API Contract 边界。
- 浏览器验收覆盖了真实文件选择和 Object URL 图片预览，不只停留在静态结构检查。

## 遇到的问题

- 上传队列对象在进入响应式数组前被持有，后续完成态修改没有触发界面更新。
- 当前动态菜单仍指向旧组件路径，无法直接通过正式菜单打开新页面；视觉验收使用临时、已删除的本地组件入口完成。
- 全量前端 Node 测试存在与课程无关的门户路径和移动端样式基线失败。

## 原因

- 上传组件首次实现时关注了队列流程和资源释放，但没有验证 Promise 完成后的最终渲染状态。
- 用户明确选择手动配置菜单，因此代码交付和运行态菜单配置存在时间差。
- 仓库基线已有测试与当前目录结构不一致，未在本次业务 Task 内扩大范围修复。

## 后续改进

- 涉及异步队列时，自动化测试和浏览器验收都必须检查最终状态，而不只检查进度回调。
- 菜单配置完成后，补一次从真实菜单进入课程中心的壳层级回归检查。
- 后端补齐文件详情 Contract 后，再增加历史文件刷新后的预览测试。
- 另开维护任务处理门户测试路径与移动端样式基线，不混入课程业务 Change。
