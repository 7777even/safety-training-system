# Retro：课程封面上传与受控读取

日期：2026-08-27

## 做得好的地方

- 在实现前发现了“数据库和 OpenAPI 有 `coverFileId`、运行期 DTO 却不接收”的纵向断点。
- 真库测试及时暴露 MyBatis 跳过 null 更新的问题，避免“接口返回成功但封面无法清空”。
- 独立 Review 发现通用文件接口可伪造保留目录，最终把上传来源、对象键和受控读取边界一起收紧。

## 问题与原因

- `us_sys_file_info` 没有内容类型和业务来源字段，单靠 `bucket_name` 不能证明文件经过课程封面签名校验。
- 对象存储写入和数据库事务不是同一事务，数据库失败后需要显式补偿。
- 零 DB Mockito 无法证明租户插件对 `organization_id` 的真实注入，也无法证明 null 字段 SQL 更新行为。

## 改进

- 独占业务目录必须同时封住通用上传入口，并严格校验对象键结构，不能只检查目录字符串。
- 涉及可空字段清空语义时，必须使用真库测试观察实际 SQL，不能只断言 Java 对象值。
- 私有二进制读取接口统一以业务资源作为授权边界，返回稳定缓存校验信息，不接受任意系统文件 ID。
