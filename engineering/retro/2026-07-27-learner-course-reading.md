# Retro：学员课程入口与学习任务读取接口

日期：2026-07-27

## 做得好的地方

- 在开发前先核对 Controller、Service 和 OpenAPI，确认不是路径别名问题，而是完整的学员读取模型缺口。
- 先确认“剩余状态”不等于剩余人数，避免在没有容量字段时发明名额业务规则。
- 三个接口都复用开课冻结版本，使课程名、分类、章节和内容项与报名时的学习事实保持一致。
- 本人校验在开课和快照读取之前执行，减少越权信息泄漏。
- 按 Red → Green 完成行为测试，并执行完整零 DB 与真 MySQL 回归。

## 遇到的问题

- 沙箱内 Mockito/Byte Buddy 无法附加测试 JVM，所有用例会在 `setUp` 前失败。
- 初版可报名课程组装中，为从 VO 反查版本使用了线性查找，形成不必要的 O(n²) 路径。
- 旧学习详情只包含内容项 ID 和进度，容易被误认为已经具备学习任务读取能力。

## 原因

- Mockito inline mock maker 依赖 JVM agent attach，受沙箱进程权限限制。
- 初版优先完成资格过滤和分页正确性，组装阶段的数据关联结构不够直接。
- 既有 COURSE-04 以“学习事实”为后端关闭口径，没有单独验证学员页面所需的读取模型。

## 改进

- 遇到 Byte Buddy attach 错误时先识别为环境失败，再在获得授权后于沙箱外运行同一目标命令；不得把它记录为业务测试失败或通过。
- 列表组装优先建立主键 Map，并在 Entity 仍可用时完成过滤，避免从 VO 反查领域对象。
- 后续关闭纵向能力时，同时检查写入事实和角色读取入口，尤其区分“详情事实”与“页面任务模型”。
- 对快照型业务新增读取接口时，测试必须覆盖“当前草稿变化不影响既有报名”的冻结语义。
