# m4-minimum-closure Specification

## Purpose

M4 只保留中山 50 功能项 19、35、39、40、42、43、44、50 所需的最小成果闭环：问卷、自动综合分、专家查课、三级档案查询护栏和证书自动签发。机器可读契约见
`docs/api/survey.openapi.json`、`docs/api/evaluation-form.openapi.json`、`docs/api/evaluation-result.openapi.json`、
`docs/api/training.openapi.json`、`docs/api/archive.openapi.json`、`docs/api/certificate.openapi.json`。

## Requirements

### Requirement: M4 必须只暴露中山 50 功能项要求的产品能力

系统 MUST 只保留可追溯到功能项 19、35、39、40、42、43、44、50 且构成最小闭环所必需的对外能力。无功能项依据、且不是必要内部机制的既有能力
MUST 删除业务代码、API、菜单、权限和 OpenAPI；既有数据库结构与历史数据 MUST 保留并明确标注隐藏状态。

以下产品入口已移除，数据库结构保留：综合成绩人工计算批次、正式确认、替代重算和批次历史；档案版本历史、快照哈希查看和异步导出任务中心；证书撤销、人工重发、到期管理和客户端任意手工签发；问卷独立版本管理、匿名高级规则和复杂目标绑定；无功能项依据的通用人员评价、课程质量评价产品入口。

#### Scenario: 收口无功能项依据的既有能力

- **GIVEN** 既有代码提供人工计算批次、档案版本历史、证书撤销或重发等能力
- **WHEN** 本能力实施
- **THEN** 系统删除对应公开代码、API、菜单、权限和 OpenAPI
- **AND** 保留既有数据库结构和历史数据
- **AND** 使用标准 COMMENT 标注原用途、隐藏状态和重新启用条件

### Requirement: 问卷必须形成设计到扫码统计的最小闭环

系统 MUST 支持问卷创建、查看、编辑、复制、删除、电脑/手机预览、投放、二维码、本人填写、结果可见性和基础统计。系统 MUST
阻止同一用户对同一投放重复提交。

#### Scenario: 问卷投放与填写

- **GIVEN** 管理员已完成题目和答案设计并通过电脑和手机预览
- **WHEN** 管理员发起投放并由用户扫码提交
- **THEN** 系统保存一份有效答卷并阻止同一用户重复提交
- **AND** 管理员能够查看基础结果统计
- **AND** 填写人结果可见性服从管理员设置

### Requirement: 综合分必须根据考试与奖惩自动计算

系统 MUST 根据培训绑定的综合评分表、考试正式成绩和奖惩记录自动刷新参训人当前综合分。系统 MUST NOT 要求管理员创建、确认或替代计算批次。

#### Scenario: 来源事实变化

- **GIVEN** 培训已绑定启用的综合评分表
- **WHEN** 参训人的考试正式成绩或奖惩记录变化
- **THEN** 系统自动刷新当前综合分
- **AND** 不要求管理员执行计算批次操作

#### Scenario: 查看已结束培训结果

- **GIVEN** 培训已经结束
- **WHEN** 管理员查看培训结果
- **THEN** 系统展示计划整体信息、学员成绩与详情、奖惩和基础统计

### Requirement: 专家查课必须形成表单引用与意见记录闭环

系统 MUST 支持专家查课表的新建、管理、培训引用、专家意见提交和培训内查看，不扩展评分排名、整改审批或多轮复查。

#### Scenario: 专家提交查课意见

- **GIVEN** 培训已引用一个专家查课表
- **WHEN** 专家提交查课意见
- **THEN** 系统保存提交人、提交时间和完整意见
- **AND** 管理员能够在对应培训中查看

### Requirement: 档案必须提供个人、企业和一期三个视角

系统 MUST 只从结果完整的已结束培训形成正式档案，并在个人、企业和一期三个视角展示一致的计划、人员、成绩、评价、奖惩、影像、附件和统计事实。系统 MUST NOT 要求签到、出勤、扫码、定位或现场证据；存在结果待补全参训人时
MUST 拒绝生成正式可下载档案，不得写空快照。系统 MUST 将真实生成文件的受控 `fileInfoId` 持久化在当前归档版本，并在查询与下载时回读该文件。

#### Scenario: 结束培训归档

- **GIVEN** 培训状态为 `ENDED` 且参训结果完整
- **WHEN** 管理员更新档案
- **THEN** 系统在个人、企业和一期三个视角展示一致事实
- **AND** 生成真实可下载档案文件并持久化当前版本文件 ID

#### Scenario: 未结束培训归档

- **GIVEN** 培训状态不是 `ENDED`
- **WHEN** 请求形成或更新正式档案
- **THEN** 系统拒绝请求

#### Scenario: 结果待补全

- **GIVEN** 培训状态为 `ENDED` 且存在 `INCOMPLETE` 参训结果
- **WHEN** 请求形成或更新正式档案
- **THEN** 系统拒绝请求且不写空快照
- **AND** 三个视角查询返回 `missingItems` 中的 `RESULTS`

### Requirement: 证书必须按来源合格结果自动生成真实文件

系统 MUST 支持图片底图、证书编号、学员姓名等元素的模板设计与预览，MUST
支持将模板配置到课程、理论考试和培训，并在学员达到既有合格标准时自动、幂等签发真实证书文件。管理员可查询、预览和下载证书；学员只能查看和下载本人证书。

证书的达标来源 MUST 是三类彼此独立的来源：**独立课程、独立理论考试、培训结果**。判据为该来源对象
MUST NOT 属于任何培训计划。每类来源 MUST 以自身主数据标识触发对应规则：课程 MUST 使用 `course_id`，
理论考试 MUST 使用 `exam_id`，培训 MUST 使用 `training_plan_id`。系统 MUST NOT 使用开课实例、考核执行
实例等运行期标识作为规则来源标识。

培训计划内引用的课程与考试 MUST 只参与该培训的结果判定，MUST NOT 因此单独触发课程或理论考试的证书；
课程内考核 MUST 归属课程，MUST NOT 触发理论考试证书。

#### Scenario: 学员首次达标

- **GIVEN** 课程、理论考试或培训已配置启用的证书模板
- **WHEN** 学员第一次达到来源对象的合格标准
- **THEN** 系统自动且幂等地签发证书
- **AND** 生成可预览、可下载的真实图片或 PDF 文件

#### Scenario: 独立课程完成发证

- **GIVEN** 一门不属于任何培训计划的课程已配置启用的 `COURSE` 规则
- **WHEN** 学员的该课程学习状态首次达到 `COMPLETED`
- **THEN** 系统以该课程 `course_id` 为来源签发证书
- **AND** 同一学员、同一课程、同一模板重复判定时 MUST NOT 产生第二张证书

#### Scenario: 独立理论考试通过发证

- **GIVEN** 一次不属于任何培训计划的线上理论考试已配置启用的 `EXAM` 规则
- **WHEN** 该独立指派考生的正式结论达到 `PASSED`
- **THEN** 系统以该考试 `exam_id` 为来源签发证书
- **AND** 无论成绩经人工发布还是自动生效，MUST 都能触发且只签发一次

#### Scenario: 培训内引用内容不单独发证

- **GIVEN** 培训计划引用了课程和理论考试内容，并为该计划配置了启用的 `TRAINING` 规则
- **WHEN** 计划内课程完成或计划内考试通过，而培训整体结果尚未合格
- **THEN** 系统 MUST NOT 为学员签发课程或理论考试证书
- **AND** 仅当该培训整体结果达到合格标准时，系统 MUST 以 `training_plan_id` 为来源签发证书

#### Scenario: 学员查看证书

- **GIVEN** 学员已获得证书
- **WHEN** 学员进入个人中心“我的证书”
- **THEN** 系统只返回该登录学员本人的证书
- **AND** 支持在线查看和下载

### Requirement: lims 协作方以后端可交互为 M4 归档标准

lims 协作方 MUST 以问卷、综合结果、专家查课、三级档案查询与真实文件端点、证书的后端可交互 API 与 OpenAPI 为 Change 归档标准。系统 MUST
NOT 用空档案快照或占位证书文件伪装完成。前端页面验收不在 lims 范围。

#### Scenario: 后端可交互后归档

- **GIVEN** 问卷、自动综合分、专家查课、档案查询和文件端点、证书后端 API 可交互，且 OpenAPI 已对齐
- **WHEN** lims 确认归档本 Change
- **THEN** 允许按后端口径归档
- **AND** 不把空档案快照或占位文件当作正式档案完成

### Requirement: 档案事实必须完整覆盖功能项清单

系统 MUST 在一期、企业、个人三个视角返回同一份培训档案事实，字段一致，且 MUST 至少覆盖：培训计划、企业、培训内容、参训人员、签到情况、学员成绩、综合评价、奖惩记录、影像记录、附件、证书与数据统计。系统 MUST NOT 以“后端已查但契约未声明”的方式丢弃事实，MUST NOT 写空快照。

#### Scenario: 三视角事实一致

- **GIVEN** 一期已结束且结果完整的培训
- **WHEN** 分别按一期、企业、个人查询该培训的档案
- **THEN** 三者返回相同的事实字段集合与相同取值
- **AND** 结果可直接展示培训内容、成绩、奖惩、影像、附件与统计

#### Scenario: 契约不得静默收窄事实

- **GIVEN** 服务端已组装完整档案事实
- **WHEN** 调用方按机器可读契约解析响应
- **THEN** 契约声明的字段与响应体一致
- **AND** 不存在已组装但未声明的档案事实字段

### Requirement: 签到情况必须由线下成绩映射呈现

系统 MUST 以已录入的线下成绩映射档案中的签到情况：教师为参训人录入线下成绩即视为该参训人在线下培训到场。系统 MUST NOT 为此新增签到表、签到记录、签到列或扫码、定位、现场证据采集。计划不含线下培训内容时，签到情况 MUST 标记为不适用。签到情况 MUST NOT 进入 `missingItems`，MUST NOT 成为归档、档案文件生成或下载的前置条件。

#### Scenario: 录入线下成绩视为到场

- **GIVEN** 一个含线下培训内容且已结束的培训计划
- **WHEN** 教师为某参训人录入线下成绩后查询档案
- **THEN** 该参训人的签到情况为已到场
- **AND** `missingItems` 中不含签到相关项

#### Scenario: 无线下内容的培训

- **GIVEN** 一个不含线下培训内容的已结束培训计划
- **WHEN** 查询该培训档案
- **THEN** 所有参训人的签到情况为不适用
- **AND** 不影响该档案的可归档性

#### Scenario: 未录入线下成绩不新增阻塞

- **GIVEN** 一个含线下培训内容的已结束培训计划
- **WHEN** 某参训人尚未录入线下成绩
- **THEN** 该参训人的签到情况为未记录
- **AND** 系统不因签到情况本身在 `missingItems` 中新增条目

### Requirement: 归档快照与档案素材必须写入真实事实

归档时系统 MUST 写入真实的奖惩快照与证书快照，MUST NOT 写入空对象。系统 MUST 把培训资料登记为档案素材并保留来源资料关联，同一文件 MUST NOT 被重复登记。快照哈希 MUST 覆盖参训人事实快照，使档案是否发生变化可判定。

#### Scenario: 重复更新档案

- **GIVEN** 一期已归档的培训
- **WHEN** 在事实变化后再次更新档案
- **THEN** 生成新版本且快照哈希与上一版本不同
- **AND** 同一文件不产生重复档案素材行

#### Scenario: 奖惩与证书快照非空

- **GIVEN** 一期存在奖惩记录与已签发证书的已结束培训
- **WHEN** 更新该培训档案
- **THEN** 对应参训人的奖惩快照与证书快照写入真实事实
- **AND** 不存在写入空对象的快照

### Requirement: 档案文件必须是可交付的 PDF 正本

一期档案与个人档案 MUST 输出 `application/pdf` 正本。系统 MUST NOT 以纯 JSON 或纯文本作为对外档案文件，MUST NOT 使用占位文件 ID 或空快照冒充档案。一期档案 MUST 持久化当前版本的受控 `fileInfoId` 并在下载时回读同一文件；个人档案 MUST 按当前可见的已结束培训事实即时组装。PDF MUST 呈现封面信息、数据统计、培训内容、参训人员成绩（含签到情况）、综合评价、奖惩、影像记录清单、附件清单与证书清单。影像与附件原件 MUST NOT 内嵌进 PDF，MUST 经受控端点另行获取。既有以 JSON 生成的历史档案 MUST NOT 被迁移改写；系统 MUST 在档案查询结果中标注该当前文件不是 PDF 正本，提示需重新更新档案。

#### Scenario: 下载一期档案正本

- **GIVEN** 一期结果完整并已归档的培训
- **WHEN** 管理员下载档案文件
- **THEN** 得到 `application/pdf` 文件且可打开、中文正常显示
- **AND** 文件内含数据统计、成绩表（含签到情况）、奖惩、影像与附件清单、证书清单

#### Scenario: 结果待补全时拒绝并无所残留

- **GIVEN** 培训已结束但存在结果待补全的参训人
- **WHEN** 请求更新档案或下载档案文件
- **THEN** 系统拒绝请求且不生成占位文件或空快照

#### Scenario: 影像与附件只出清单

- **GIVEN** 一期培训存在影像与附件资料
- **WHEN** 下载该期档案正本
- **THEN** 文件中包含影像与附件清单
- **AND** 不内嵌影像与附件的二进制原件

#### Scenario: 历史 JSON 档案提示重新更新

- **GIVEN** 一期培训曾以 JSON 生成过档案文件且尚未重新归档
- **WHEN** 查询该期档案
- **THEN** 结果标注当前文件不是 PDF 正本
- **AND** 提示重新更新档案后即可下载 PDF 正本
- **AND** 已生成的 JSON 文件不被改写或迁移

### Requirement: 个人档案必须提供详情与证书入口

个人档案 MUST 提供个人培训记录、参训情况、奖惩记录与综合评价的详情内容，并 MUST 为具备证书查询权限的调用方提供证书清单与下载入口。证书 MUST 复用既有证书查询与文件端点；系统 MUST NOT 在档案中复制证书文件，MUST NOT 因档案查询而新签发证书。个人档案 MUST 支持导出为 PDF。

证书清单 MUST 受权限门控：调用方缺少 `certificate:cert:list` 时，档案响应 MUST NOT 包含证书清单字段，MUST NOT 以“返回清单但禁用下载”代替。

#### Scenario: 查看与下载证书

- **GIVEN** 某人员在一期已结束培训中获得已签发证书，且调用方具备 `certificate:cert:list`
- **WHEN** 查询该人员个人档案
- **THEN** 档案返回该人员的证书清单
- **AND** 可在线查看并下载证书原件

#### Scenario: 缺少证书权限

- **GIVEN** 调用方仅具备 `archive:training:list` 而不具备 `certificate:cert:list`
- **WHEN** 查询该人员个人档案
- **THEN** 档案响应不包含证书清单字段
- **AND** 个人档案的其余详情内容仍正常返回

#### Scenario: 导出个人档案

- **GIVEN** 某人员存在已结束且结果完整的培训记录
- **WHEN** 导出该人员个人档案
- **THEN** 得到 `application/pdf` 个人档案文件

### Requirement: 企业档案必须可筛选并可下载档案文件

企业档案 MUST 支持按培训名称、培训编号、开始时间、结束时间、培训类型筛选当前租户内已结束培训，MUST 支持从列表进入该期档案详情，并 MUST 支持下载该期档案文件。企业档案 MUST NOT 跨租户返回其他机构档案。

#### Scenario: 筛选并下载

- **GIVEN** 当前租户内存在多期已结束培训
- **WHEN** 管理员按培训类型与结束时间范围筛选，并下载其中一期的档案文件
- **THEN** 列表只返回符合条件且属于当前租户的已结束培训
- **AND** 下载得到该期的 PDF 档案正本

#### Scenario: 不跨租户

- **GIVEN** 其他机构存在已结束培训
- **WHEN** 当前租户管理员查询企业档案
- **THEN** 结果中不含其他机构的培训

### Requirement: 档案数据统计口径必须与综合结果一致

档案 MUST 提供数据统计，且至少包含：培训内容项数与必修项数、参训人数、已完成人数、通过人数、未通过人数、结果待补全人数、通过率、平均综合分、线上与线下学时合计、影像与附件数量、奖惩数量与已到场人数。统计判定 MUST 与既有综合结果口径（`PASSED` / `FAILED` / `INCOMPLETE`）一致；分母为 0 的比率 MUST 返回空值，MUST NOT 以 0 冒充。

#### Scenario: 通过率与完成情况

- **GIVEN** 一期已结束培训，参训人结果包含 `PASSED`、`FAILED` 与 `INCOMPLETE`
- **WHEN** 查询该期档案统计
- **THEN** 通过人数、未通过人数与结果待补全人数与综合结果一致
- **AND** 通过率按通过人数除以已判定人数计算

#### Scenario: 无已判定参训人

- **GIVEN** 一期已结束培训中所有参训人均未形成判定结果
- **WHEN** 查询该期档案统计
- **THEN** 通过率与平均综合分为空值
- **AND** 不使用 0 冒充缺失值

### Requirement: 签发来源候选必须与培训派生对象隔离

证书规则的可绑定来源候选 MUST 只包含可供跨计划复用的稳定来源对象，MUST NOT 把培训运行期自动派生的
对象作为新规则的可选项。

- `COURSE` 候选 MUST 只包含已发布的独立课程主数据。
- `EXAM` 候选 MUST 只包含已发布的线上理论考试主数据，且 MUST 排除由培训计划派生的考试
  （`plan_content_id` 非空者）。
- `TRAINING` 候选 MUST 只包含已发布或进行中的培训计划。

#### Scenario: 培训派生考试不出现在候选中

- **GIVEN** 某培训计划已生成运行期派生考试
- **WHEN** 管理员在签发规则页选择 `EXAM` 来源类型并查询候选
- **THEN** 候选列表 MUST NOT 出现该派生考试
- **AND** 既有已绑定此类来源的历史规则详情 MUST 仍按原 ID 返回并尽力解析名称，不因候选收窄而报错

### Requirement: 同一来源对象只能绑定一条启用规则

签发规则 MUST 保证同一来源对象在启用状态下唯一，避免同一课程、理论考试或培训被配置为向学员签发
多张语义重复的证书。

- 同一 `source_type` 与 `source_id` 组合 MUST 至多存在一条 `status=1` 且未删除的规则。
- 新建规则或更新规则为启用状态时，若该来源已存在其他启用规则，系统 MUST 拒绝该操作并返回明确错误。
- 禁用状态的规则 MUST NOT 参与唯一性约束；管理员 MUST 能通过先禁用旧规则、再启用新规则的方式替换
  来源所绑定的模板。

#### Scenario: 重复配置同一来源的启用规则被拒绝

- **GIVEN** 某独立课程已存在一条启用中的签发规则
- **WHEN** 管理员再为同一课程新建一条启用规则，或把另一条已禁用规则改为启用
- **THEN** 系统 MUST 拒绝该操作并返回「该来源已存在启用规则」类错误
- **AND** MUST NOT 产生第二条启用规则

#### Scenario: 禁用后换绑模板

- **GIVEN** 某来源已有一条启用规则
- **WHEN** 管理员先将其禁用，再为同一来源新建一条启用规则
- **THEN** 系统 MUST 允许新建
- **AND** 同一来源在启用态下仍然只有一条规则
