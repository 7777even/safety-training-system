# 设计：前置阻止不合规的培训标准、模板与计划编排

## 1. 设计原则

1. 资源选择、实时摘要、保存校验使用同一套规则语义，避免页面显示合规但保存失败。
2. 前端只做体验层的提前反馈；机构隔离、资源状态、试卷版本、发布状态和权限仍以后端为准。
3. 模板和计划的线上占比使用阶段/内容的现有学时汇总；比例统一兼容 `0~1` 和百分数两种接口历史数据表达。
4. 不新增平行接口。优先复用 `GET /api/training/reference-resources` 返回的当前机构可执行资源及 `versionId`。

## 2. 规则边界

### 2.0 培训模块表单必填标识

- 所有用户可编辑表单 MUST 对必填字段显示统一的必填标识；不能只依赖保存后错误提示。
- 必填标识必须与实际提交校验保持一致，禁止出现“界面标为非必填但提交必填”或“界面标为必填但接口允许留空”的不一致。
- 适用范围包括培训类型、培训标准、培训模板、培训计划、阶段与内容、内容执行配置、评价表单绑定、参训人员、线下活动及结果相关可编辑表单。
- 必填字段必须有中文 `label`、中文 `placeholder`/说明和中文校验提示；条件必填项须在选择对应内容类型或规则类型后即时显示必填标识。
- 必填标识只表达用户需要填写或选择的字段，不把系统自动生成的 ID、版本号、执行关联和结果计算字段伪装成用户输入项。

### 2.1 指定考试

培训标准 `EXAM` 规则只能从当前机构可引用资源中选择，并且资源必须具备可冻结试卷版本（`versionId` 非空）。

模板和计划的考试内容也必须从同一类可执行资源中选择；保存时再次校验当前选择仍在可执行资源集合内，防止页面打开后资源状态变化导致脏数据写入。

### 2.2 线上占比

- 培训类型的 `onlineMaxRatio` 是基础上限。
- 已选培训标准的 `ONLINE_RATIO` 只能进一步收紧，不能放宽培训类型上限。
- 模板和计划阶段内容保存时，当前线上学时 / 当前总学时不得超过有效上限；总学时为 0 时不因比例计算阻止保存，但必须提示仍需补齐内容。
- 采用“当前值、上限、超出值”的中文提示，并定位到“阶段与内容”。

### 2.3 总学时和指定资源

- 已配置有效标准总学时时，模板和计划保存时当前总学时不得低于要求。
- 标准指定课程、指定考试和线下要求，在模板/计划保存时必须检查是否已覆盖；缺少时提示具体规则名称。
- 对草稿允许暂存的场景，是否强制总学时完整需与现有工作台步骤一致：阶段内容“保存”即执行合规校验，未满足则不提交；不通过时保留草稿供用户调整。

### 2.4 执行配置

继续沿用既有四类内容配置要求：课程需选择完成规则，考试需选择测验/正式考试模式，题库练习需完整配置时长/及格线/次数/抽题规则，线下活动需完整配置教师、地点、时间和签到规则。

上述条件字段在对应表单中必须即时显示“必填”，保存失败时定位到具体阶段、内容和字段。

## 3. 链路设计

### 3.1 标准工作台

- 使用可执行资源接口加载课程和考试选项；考试选项显示“已发布，可冻结试卷版本”等用户提示。
- 当资源不再可执行或版本为空时，清空失效选择并提示重新选择。
- 保存规则前执行字段完整性、比例不超过 100%、指定考试版本可用性校验。
- 发布标准前复用保存校验，并展示未通过的规则名称和调整建议。
- 基础信息、规则字段和条件资源字段显示必填标识；规则类型切换时同步更新必填状态。

### 3.2 模板工作台

- 保留现有标准规则摘要和资源选择。
- 阶段内容保存前执行内容基础校验、执行配置校验、线上占比、总学时和标准指定资源覆盖校验。
- 保存按钮附近展示合规摘要；失败时不调用阶段保存接口。
- 模板发布确认只允许进入已保存且合规的阶段快照。
- 基础信息、阶段字段、内容资源和条件执行配置显示必填标识；阶段保存失败时定位具体字段。

### 3.3 计划工作台

- 保留模板带入时的完整内容配置复制。
- 计划阶段内容保存前执行与模板一致的合规校验，并以计划培训性质对应的类型最低学时计算有效要求。
- 发布预检前刷新计划详情、阶段和资源上下文；预检 issues 按 `planContentId` 定位到阶段/内容。
- 对 8115 提示“考试没有可用的冻结试卷版本，请返回阶段内容重新选择已发布考试”；对 8121 提示当前占比、上限和需要降低的线上学时。
- 基础信息、阶段内容、评价绑定和参训人员相关可编辑字段显示必填标识；必填状态随培训类型、培训性质和内容类型变化。

### 3.4 后端最终校验

后端现有 `publish-precheck` 和 `publish` 校验继续保留。前端提前校验不能替代后端，因为资源状态、机构权限和版本可能在页面打开后发生变化。

## 4. 数据与 API 影响

- 不新增 API，不修改现有请求字段和响应字段。
- 读取 `GET /api/training/reference-resources` 的 `resourceType=EXAM`、`resourceId`、`versionId`、`publishStatus`、`executable`。
- 保持 `PUT /api/training/standards/{id}/rules`、模板阶段保存和计划阶段保存的原有请求结构。
- 如实现过程中发现现有 OpenAPI 缺少前置校验所需字段，必须先单独补充契约并暂停实现，不在本 Change 中猜测字段。

## 5. 风险与取舍

- 资源列表接口默认分页大小有限；本 Change 只在现有分页能力范围内实现，若生产数据超过上限，应另行增加搜索/分页选择方案，不在本次偷偷扩大接口。
- 前端校验与后端规则重复，但这是用户体验校验与服务端安全校验的必要分层。
- 标准规则是定义层，模板/计划是编排层；不能把标准的“指定考试”误认为计划中的考试执行实例。
