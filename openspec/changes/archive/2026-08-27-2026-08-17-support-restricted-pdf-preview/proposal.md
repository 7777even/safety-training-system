# Proposal：支持无打开密码但限制修改的 PDF 预览

## 背景

当前 PDF PREVIEW 生成链会先使用 PDFBox 重建 Page Tree，再由 qpdf 线性化。对于设置了空用户密码、可以直接阅读，但仍携带加密字典并禁止修改或文档组装的
PDF，PDFBox 能正常读取页面，却会在保存规范化结果时抛出异常。任务最终只记录“PDF
页面树规范化失败”，导致这类合法可读文档无法生成在线预览，也无法从现有失败原因定位实际问题。

真实样本约 63.86 MiB、2517 页，`qpdf --check` 无语法或流编码错误；移除测试副本的加密后，现有 Page Tree 规范化、qpdf
完整性检查和线性化检查均能通过，页数保持 2517。

## 目标

1. 允许系统为无需输入密码即可读取、但带权限限制的 PDF 生成在线预览。
2. 仅移除派生 PREVIEW 的加密和文档权限限制，上传的 SOURCE 始终保持原文件字节和保护状态。
3. 派生 PREVIEW 继续通过既有鉴权文件代理访问，不暴露对象存储地址或新增匿名访问路径。
4. 对确实需要非空打开密码或无法读取的 PDF 保持失败，不猜测、保存或绕过未知密码。
5. 保留底层异常的服务端诊断信息，同时对任务失败原因继续使用稳定、安全的中文描述。

## 用户价值

- 用户本地可以直接打开的权限受限 PDF，也能在系统内生成渐进式在线预览。
- SOURCE 的原始保护状态不被覆盖，下载原文件时仍获得上传版本。
- 转码失败可在服务端日志中定位真实原因，减少只能依靠泛化错误反复试验的问题。

## 功能范围

- 原生 PDF 的 DOCUMENT_PREVIEW 生成链。
- PDFBox Page Tree 规范化保存前对已成功读取的加密文档显式移除派生文件保护。
- 空用户密码、禁止修改/组装的加密 PDF 自动化回归。
- 2517 页真实样本的本地 PDFBox/qpdf 验收。
- 转码失败的服务端安全日志及既有任务失败原因。

## 非目标范围

- 不修改或覆盖 SOURCE，不生成解密后的 SOURCE 下载文件。
- 不接收、存储或尝试破解非空 PDF 密码。
- 不修改 API Contract、权限模型、数据库结构、对象存储访问策略或 Range 响应语义。
- 不修改前端页面、Mock 或联调实现；前端以既有 OpenAPI 为准另开。
- 不改变 Word、Excel、视频等其他转码链路。
- 不顺带调整 PDF 压缩率、页面内容、批注、签名或打印能力。

## 风险与约束

- PREVIEW 将不再携带源 PDF 的内部加密权限，因此必须继续只通过既有 Bearer 鉴权和租户隔离文件代理访问；不得产生公共对象 URL。
- PDF 数字签名可能因派生文件结构变化而失效；SOURCE 保持原样，PREVIEW 只用于阅读，不声明保留签名有效性。
- 只有 PDFBox 已使用空密码成功打开文档后才移除派生保护；需要密码的文档仍按 SOURCE_INVALID 失败。
- 真实大文件验收必须同时检查页数、Page Tree、qpdf 完整性和线性化，不能只以“能打开”作为通过依据。

## 已确认决策

- 2026-08-17：用户选择方案 1，仅对系统生成的 PREVIEW 移除加密限制，SOURCE 保持不变。
