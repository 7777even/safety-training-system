# Proposal：按中山 50 功能项重整 M4 最小闭环

## 状态

- 状态：已确认，Task 1～4、6 后端已完成；Task 5 受签到事实阻塞未完成；Task 7 后端 QA 已回填且 M4 不关闭
- 风险级别：L4（删除既有业务 API/代码、调整权限与 OpenAPI、修改数据库 COMMENT）
- 原则：不删除现有表、列、索引和历史数据；确认后只删除超范围业务代码，并通过新 migration 修改 COMMENT。

## 背景

既有 M4 将问卷、评价记录、综合成绩批次、三级档案和证书一次性设计为完整领域模型，并以“纯后端完成”关闭里程碑。该设计一方面引入了中山
50 功能项未要求的人工确认批次、替代重算、撤销重发、档案版本历史等能力，另一方面没有交付证书文件、档案下载、三级档案页面、问卷扫码和学员证书等原始功能。

本 Change 以 `docs/product/功能项中山50.csv` 为唯一原始范围上限，废止“先完成后端大模型、前端以后另开即可关闭 M4”的验收口径。M4
必须以用户可操作的真实纵向闭环验收。

## 覆盖功能项及原文语义

|-----|-----------------------------------------------------------------------|

| 35  | 在线发起问卷，用户扫码填写，并按管理员设置查看结果和统计。                                         |

| 42  | 问卷设计、编辑、查看、复制、删除，预览手机和电脑模式，并用于线下培训调查或学员评价培训机构。                        |

功能项 36 中已有的影像、附件、奖惩和综合评价资料是 M4 结果与档案的输入，本 Change 只消费既有事实，不重复建设上传能力。功能项
37、41 的专项考试分析和图表分析不并入本 Change；应按各自功能项另行确认最小闭环。

## 目标

1. 只实现上述功能项明确要求的最小用户闭环。
2. 删除没有功能项依据、且不是最小闭环必要内部机制的业务代码、API、权限、菜单和测试。
3. 已经落库的超范围表和字段不删除；在 init SQL 和新增 migration 中将 COMMENT 标注为暂时隐藏及原用途。
4. 纠正 M4 进度状态，只有管理端、学员端、后端、数据库、权限和真实文件链路全部验收后才能关闭。

## 非目标

- 不提供综合成绩人工确认、正式批次、替代重算和批次历史页面。
- 不提供证书撤销、重发、到期管理、防伪、签章或复杂编号规则。
- 不提供档案版本历史、哈希校验、异步导出任务中心或档案审批流。
- 不提供问卷匿名策略、复杂矩阵题、附件题、条件跳题或高级图表。
- 不在 M4 新建统计大屏、监管预警、消息中心或仿真能力。
- 不删除数据库表、列、索引或历史记录。

## 对既有规格的影响

本 Change 经确认并实施后，取代归档 Change `2026-07-24-implement-result-archive-certificate` 的产品范围、验收口径和完成结论。原
Change 仅作为历史实现记录，不再作为 M4 已完成的依据。

## 人工确认关卡

确认本 Change 表示接受以下决策：

1. “功能项存在”是产品能力的必要条件；无功能项依据的能力默认不对外提供。
2. SQL 保留不等于功能保留；隐藏能力不得保留可调用的 Controller、公开 Service、菜单、权限或 OpenAPI。
3. 为数据一致性必须保留的内部快照或内部版本可以继续存在，但不得形成额外产品操作。
4. 数据库 COMMENT 统一标记隐藏状态、原用途和重新启用条件。
5. M4 当前状态从“已完成”调整为“部分完成”，直至真实端到端验收通过。
