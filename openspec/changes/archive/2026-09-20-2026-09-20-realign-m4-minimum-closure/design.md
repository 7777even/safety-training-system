# Design：M4 中山 50 最小闭环与超范围能力收口

## 1. 文档地位

本文件是 M4 重整的主设计文档。经人工确认后，M4 的页面、API、权限、代码、测试和验收均以本文件及同目录 `spec-delta.md` 为准。归档的旧
M4 Change 仅用于追溯，不再提供新增范围或完成依据。

在本 Change 获得人工确认前，不得删除代码、修改 OpenAPI、修改数据库 COMMENT、调整权限或更新 M4 完成状态。

## 2. 设计原则

### 2.1 范围判定

每项对外能力必须同时满足：

1. 能反向追溯到 `docs/product/功能项中山50.csv` 的明确语义；
2. 是形成该功能最小用户闭环所必需；
3. 有真实页面、真实 API、真实持久化和可执行验收；
4. 不依赖占位文件、永久 `PENDING` 任务、Mock 或仅后端接口。

缺少任一条件时，不得计为 M4 已完成。

### 2.2 三类处置

| 分类     | 判定                         | 处置                                              |
|--------|----------------------------|-------------------------------------------------|
| 最小产品能力 | 功能项明确要求，用户完成闭环必需           | 保留或补齐页面、API、Service、数据和测试                       |
| 必要内部机制 | 用户不直接操作，但用于快照一致性、渲染或历史数据兼容 | 可保留内部实现和 SQL；不提供独立页面、权限或公开 API                  |
| 超范围能力  | 功能项未要求，且不是最小闭环必需           | 删除业务代码、公开 API、菜单、权限、OpenAPI 和专属测试；SQL 保留并标注暂时隐藏 |

“前端不展示”不等于完成收口。超范围接口即使没有菜单，只要仍能被调用，就必须按本 Change 删除或变为不可从 Controller 到达的内部机制。

## 3. M4 最小业务闭环总览

```text
问卷：管理员设计/复制/预览 → 发起并生成二维码 → 用户扫码填写 → 管理员按设置查看结果和基础统计

综合结果：管理员配置综合评分表 → 培训引用 → 考试/奖惩事实变化后自动计算
        → 培训结束 → 管理员查看整体结果、个人详情、奖惩和基础统计

专家查课：管理员维护查课表 → 培训引用 → 专家记录查课意见 → 管理员查看记录

档案：培训结束且结果完整 → 形成一期一档 → 可按个人/企业/期次查看 → 生成并下载档案文件

证书：管理员设计模板 → 绑定课程/考试/培训合格条件 → 学员达标自动签发真实证书文件
      → 管理员查询 → 学员在个人中心查看/下载
```

## 4. 功能一：问卷最小闭环（功能项 35、42）

### 4.1 管理端

管理员能够：

- 创建、查看、编辑、复制和删除未投放问卷；
- 设计题目和答案选项；最小支持单选、多选和文本题；
- 分别预览电脑和手机展示效果；
- 创建一次问卷投放，选择用途为“线下培训调查”或“培训机构评价”；
- 设置结果可见方式：仅管理员可见，或提交后填写人可见；不增加其他可见性规则；
- 获得可访问链接和二维码；
- 查看答卷数量、单选/多选选项计数及文本答案列表。

### 4.2 填写端

- 用户通过二维码或链接进入问卷；需要登录时沿用现有登录能力。
- 同一投放对同一用户只接受一份有效答卷。
- 提交成功后按管理员设置决定是否展示统计；未授权时不得通过直接调用接口读取统计。

### 4.3 保留的内部机制

投放后必须避免管理员修改题目导致历史答卷失真，因此允许内部保存投放时的问卷快照。该快照不形成“发布版本管理”页面，也不提供版本列表、归档版本或版本回退操作。

### 4.4 删除或隐藏

- 删除独立的问卷版本管理 API、版本历史操作和对应权限；投放快照仅由投放流程内部使用。
- 删除匿名问卷、附件题、矩阵题、评分均值、高级图表、复杂目标绑定等没有功能项依据的代码入口。
- 相关 SQL 表/列若已存在则保留，并按第 9 节标注暂时隐藏。

### 4.5 最小验收

管理员创建三题问卷并完成 PC/手机预览，创建投放后生成二维码；学员扫码提交；重复提交被拒绝；管理员看到真实计数；填写人是否能看到结果严格服从投放设置。

## 5. 功能二：综合评分与培训结果（功能项 39、40）

### 5.1 综合素质评分表

管理端只提供功能项需要的配置：

- 评分表名称；
- 考试成绩占比；
- 奖惩分计入方式；
- 综合分计算规则；
- 启用状态。

培训计划可选择一个已启用评分表。已开始培训沿用其开始时的规则快照，避免后续编辑改变本期结果；快照属于内部一致性机制，不提供版本管理页面。

### 5.2 自动计算

- 考试正式成绩或奖惩记录变化后，系统自动刷新对应参训人的综合分。
- 培训结束前必须完成最终刷新；缺少规则所需成绩时明确显示“结果不完整”，不得用 0 分代替。
- 管理员不需要创建计算批次、逐个确认正式批次或执行替代重算。
- 参训人当前综合分和结果状态是页面唯一读取口径。

### 5.3 已结束培训结果页

仅已结束培训展示正式结果，内容包括：

- 培训计划整体信息；
- 参训人数、通过人数、未通过人数、结果不完整人数；
- 学员成绩列表；
- 学员培训详情，包括已纳入本期的考试成绩、综合分和结果状态；
- 学员奖惩信息；
- 本次培训基础结果统计。

附件和影像只展示功能项 36 已存在的数据，不在结果页重复提供上传流程。

### 5.4 删除或隐藏

- 删除计算批次分页、手工 calculate、confirm、supersede 和批次来源追溯的公开 API、权限、DTO/VO、菜单及页面代码。
- 删除“正式批次唯一”“人工确认后才成为结果”等产品规则代码。
- `sts_evaluation_calculation_run`、`sts_evaluation_calculation_source` 及相关字段保留，不再由当前业务写入，并标注暂时隐藏。

### 5.5 最小验收

创建包含理论考试并绑定综合评分表的培训；学员取得考试成绩并产生一条奖惩记录；系统自动得到综合分；培训结束后管理员可从结果页查看计划汇总、学员详情、奖惩和统计，且不存在人工确认批次步骤。

## 6. 功能三：专家查课（功能项 43）

### 6.1 最小能力

- 管理员新建、查看、编辑、删除未使用的专家查课表；
- 培训计划引用一个查课表；
- 专家在对应培训中填写查课意见并提交；
- 已提交意见只读，管理员可在培训详情查看。

不增加专家评分排名、整改流程、审批、消息提醒或多轮复查。

### 6.2 复用边界

可以复用评价表单的题目和记录存储，但对外只暴露“专家查课表”和“查课意见”语义。通用人员评价、课程质量评价等没有被功能项 43
或问卷功能明确要求的入口应删除。

### 6.3 最小验收

管理员创建查课表并绑定培训；专家登录后提交一次意见；管理员在该培训内看到提交人、提交时间和完整意见。

## 7. 功能四：三级档案（功能项 44）

### 7.1 归档条件

- 只有状态为 `ENDED` 的培训可以形成档案。
- 培训结果不完整时不得生成正式档案，应返回缺失项目。
- `DRAFT`、`PUBLISHED`、`RUNNING` 培训均不得归档。

### 7.2 一期一档

展示全部已结束培训，可查看：

- 培训计划；
- 企业信息；
- 参训人员；
- 签到情况；
- 学员成绩；
- 综合评价和奖惩；
- 影像记录与附件；
- 基础数据统计。

当前上游已删除线下签到采集能力。功能项 44 的“签到情况”仍是验收要求，M4 不得用空 JSON 或固定文案伪装完成；必须在实施该 Task
前，由独立且已确认的上游 Change 提供最小签到事实。本 Change 不自行定义签到业务规则。

### 7.3 个人档案

- 按人员查询个人档案；
- 展示个人基本信息、培训记录、参训情况、奖惩、综合评价和证书；
- 支持生成并下载个人档案文件。

### 7.4 企业档案

- 按企业名称查询；
- 查看企业下培训计划列表；
- 按培训名称、培训编号、开始时间、结束时间和培训类型筛选；
- 查看与一期一档相同口径的培训详情；
- 支持在培训结束后更新档案并下载文件。

### 7.5 更新与文件生成

“更新档案”的产品语义是重新读取当前已结束培训事实并更新用户可见档案。内部可以新增快照记录以保留数据一致性，但不得向用户提供版本历史、版本回退、哈希验证或封存审批。

下载操作必须生成真实可下载文件。不得以只创建 `PENDING` 任务或只返回文件 ID 作为完成。

### 7.6 删除或隐藏

- 删除档案版本列表、历史版本详情、哈希查看、异步导出任务中心等公开功能。
- 删除允许 `PUBLISHED`、`RUNNING` 培训归档的代码。
- 版本表、哈希列和导出任务表可保留；如果真实文件生成无需任务表，则整表标注暂时隐藏。

### 7.7 最小验收

结束一期具有人员、签到、成绩、奖惩、评价、影像和附件的培训；更新档案后，管理员能从一期、企业和个人三个入口查询同一事实；生成真实档案文件并下载；进行中的培训不能归档。

## 8. 功能五：证书最小闭环（功能项 19、50）

### 8.1 模板设计

管理员能够：

- 上传任意图片作为模板底图；
- 添加至少证书编号、学员姓名两类变量，也可添加静态文字和图片；
- 调整元素位置和基础样式；
- 使用示例数据预览证书；
- 保存、查看、编辑和删除未被使用的模板。

模板内部快照可用于保证已签发证书不随模板修改而变化，但不提供模板版本历史、回退和归档操作。

### 8.2 签发配置

- 证书可分别配置到理论考试、课程和培训。
- 最小合格条件只复用来源对象已经存在的“完成/通过”结论，不新增复杂条件表达式。
- 一个来源对象可以选择一个启用模板。

### 8.3 自动签发与文件

- 学员第一次达到来源合格标准时自动、幂等签发。
- 签发时生成真实证书图片或 PDF，保存真实文件关联，不允许占位 `fileId`。
- 同一学员、来源和模板重复触发时返回同一张证书，不重复生成。
- 签发前必须验证来源、学员、结果和模板属于当前租户且相互匹配；不得信任客户端提交任意 ID 直接签发。

### 8.4 管理端和学员端

- 管理员可按学员、来源类型和来源名称查询已签发证书，并在线查看或下载。
- 学员只能查看和下载本人证书。
- 学员个人中心增加“我的证书”入口。

### 8.5 删除或隐藏

- 删除证书撤销、人工重发、到期状态、有效期、领取说明和复杂条件值等业务代码/API/权限。
- 删除手工传入持有人、来源结果和模板版本进行任意签发的公开接口。
- `sts_certificate_revocation`、撤销时间、有效期、重发相关约束或字段保留并标注暂时隐藏。

### 8.6 最小验收

分别为一门课程、一次理论考试和一期培训配置证书；三名学员达标后均自动生成真实证书文件；重复处理不重复签发；管理员可查询预览下载；学员仅能在个人中心查看下载本人证书。

## 9. SQL 保留与 COMMENT 标准

### 9.1 禁止事项

- 不删除既有表、列、索引和历史数据。
- 不修改或重命名已经执行过的 migration。
- 不因字段隐藏而从 Entity 强行移除仍被 MyBatis、租户插件、唯一约束或历史查询依赖的映射。

### 9.2 注释格式

完全不再使用的表，表 COMMENT 统一为：

```sql
COMMENT='【暂时隐藏】原用于：<原用途>；当前中山50最小闭环不启用，不得作为当前页面、API或业务规则依据；后续启用须新建并确认 OpenSpec Change'
```

保留表中的隐藏列，列 COMMENT 统一为：

```sql
COMMENT '【暂时隐藏】原用于：<原用途>；当前中山50最小闭环不读取、不写入、不展示；后续启用须新建并确认 OpenSpec Change'
```

仍被最小闭环内部使用、但不向用户暴露的字段，COMMENT 统一为：

```sql
COMMENT '【内部保留】用于：<当前必要用途>；不提供独立页面或对外操作'
```

不得只写“预留”“备用”等无法解释原用途的注释。

### 9.3 必须标注的首批对象

实施前须逐表核对，至少包括：

- 综合计算批次与来源表，以及参训人 `official_calculation_run_id`；
- 档案版本历史、快照哈希、异步导出任务相关表和字段；
- 证书撤销记录、有效期、撤销时间及仅服务于重发的字段；
- 问卷高级目标绑定、匿名和当前最小题型未使用的字段；
- 评价记录中通用人员评价、课程质量评价等不再暴露的类型或字段。

COMMENT 变更必须同时进入最新 init SQL 和新的 Admin Flyway migration，并同步 `sts.init.schema-version`。不允许只改 init
快照而不处理已部署数据库。

## 10. 代码删除规则

### 10.1 删除范围

确认后，对每项超范围能力同时删除：

- Controller 路径和权限注解；
- 仅服务该能力的 Service 方法与实现；
- DTO、VO、枚举和转换代码；
- Mapper 自定义查询；
- 前端 API、类型、Mock、路由、菜单、按钮和页面；
- 菜单种子与角色权限；
- OpenAPI path、schema、错误码和示例；
- 仅验证已删除行为的测试。

公共代码只有在没有任何最小闭环调用者后才删除，不顺带重构其他业务域。

### 10.2 保留代码边界

以下代码可保留，但必须没有独立产品入口：

- 投放时生成问卷内容快照；
- 培训开始时冻结评分规则；
- 档案更新时生成当前快照；
- 证书签发时冻结模板内容；
- 读取历史数据所需的兼容映射。

## 11. API 与权限收口原则

- 对外 API 必须按功能项组织，不继续暴露“计算批次”“档案版本”“撤销/重发”等技术资源。
- 管理端接口使用现有租户隔离并校验业务对象归属。
- 学员问卷、证书接口必须从登录身份派生用户 ID，不接受客户端查询其他用户。
- OpenAPI 必须与 Controller 一一对应；不得保留“核心路径已登记、其余以后补”的状态。
- 删除路径属于不兼容契约变更，实施前必须列出调用方并同步 PC、移动端和 Mock。

建议收敛后的业务资源如下，准确 URL 在实施 Task 的 OpenAPI 评审中确认：

| 资源   | 最小操作                           |
|------|--------------------------------|
| 问卷   | CRUD、复制、双端预览、发起、二维码、本人提交、结果/统计 |
| 评分表  | CRUD、培训绑定；自动计算无人工批次 API        |
| 培训结果 | 已结束计划汇总、人员列表、个人详情              |
| 专家查课 | 查课表 CRUD、培训绑定、专家提交、培训内查询       |
| 档案   | 个人/企业/期次查询、更新、生成下载文件           |
| 证书   | 模板设计预览、来源配置、管理员查询、本人查询/预览/下载   |

## 12. 状态迁移与兼容

- 实施开始时将进度表 M4 从“已完成”改为“实施中”；不能沿用 2026-07-24 的后端关闭日期。
- 既有综合计算批次、档案版本、撤销证书等历史记录不删除、不改写。
- 历史隐藏数据默认不在新页面显示，也不参与新规则；确需迁移时必须在具体 Task 中列出确定性映射。
- 旧 API 删除前必须检索真实调用方。没有调用方可直接随 Task 删除；存在调用方必须在同一 Task 内同步，禁止长期双轨。

## 13. 测试与验收策略

每个业务 Task 均执行 Red → Green → Refactor：

1. 先增加覆盖功能项验收场景的失败测试；
2. 删除超范围入口并完成最小实现；
3. 只重构本 Task 新产生的重复；
4. 运行受影响前端定向测试/typecheck、后端目标测试及真实 MySQL IT；
5. 涉及文件生成时使用真实文件存储和可下载文件验收，不允许 Mock 或占位 ID；
6. 核对 Controller 与 OpenAPI 路径完全一致；
7. 执行 OpenSpec strict、`git diff --check` 和双轴 Review。

M4 关闭必须至少完成五条真实角色链路：问卷、综合结果、专家查课、三级档案、证书。任一链路只有后端、只有页面、使用
Mock、使用空快照或占位文件，都不得关闭里程碑。
