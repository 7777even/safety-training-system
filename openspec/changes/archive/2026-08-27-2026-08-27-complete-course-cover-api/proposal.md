# Proposal：补齐课程封面上传与受控读取

## 背景

课程表、课程实体、课程详情 VO、发布快照和 `docs/api/course.openapi.json` 已存在 `coverFileId`，但实际
`CourseCreateRequest`、`CourseUpdateRequest` 没有接收该字段，也没有课程语义下的封面上传及受控查看/下载接口。当前契约示例与运行期保存能力不一致，
调用方即使上传了图片，也无法可靠地把图片设为课程封面或通过课程权限读取。

对象存储现有源文件使用 `source/{yyyy}/{MM}/...`，素材派生文件使用既有 `derivative/...` 结构。用户已确认保留当前日期层级与既有目录效果，
本 Change 不调整 `source`、`derivative`，仅为课程封面增加独立业务目录。

## 目标

1. 提供课程封面图片上传接口，文件保存到私有 bucket 的 `course-cover/{yyyy}/{MM}/...` 目录。
2. 课程创建和更新能够保存 `coverFileId`，并校验文件属于当前机构、属于课程封面目录且为允许的图片。
3. 提供按课程读取封面的受控接口，支持浏览器内查看和显式下载，不暴露 bucket、对象键或永久地址。
4. 同步 `docs/api/course.openapi.json`，使请求字段、接口、权限、错误码和示例与运行期一致。

## 用户价值

- 管理员可以上传并设置真实课程封面，不再出现契约有字段但后端无法保存的情况。
- 管理端和学员端可以通过稳定的受控地址展示课程封面，需要时可下载原图。
- 封面、素材源文件和素材派生文件在私有 bucket 中职责清晰，同时保持现有文件兼容。

## 覆盖功能项

- 功能项 21：管理员创建课程并通过课程基本信息向学员呈现课程概况、目标、大纲和考核方式。本 Change 补齐其中现有课程基本信息模型已经定义、
  但尚未形成真实保存与读取闭环的课程封面。
- 功能项 48：学员查看已分配课程的课程详情。本 Change 只交付其课程封面受控读取后端能力，不包含前端页面实施。

## 功能范围

1. 新增课程封面单文件上传 API；只接收项目确认的图片格式和大小范围。
2. 新上传封面的对象键使用 `course-cover/{yyyy}/{MM}/{uuid}.{ext}`，与现有年月目录习惯一致。
3. `CourseCreateRequest`、`CourseUpdateRequest` 接收可空 `coverFileId`；写入前执行机构、目录、文件类型和有效性校验。
4. 新增按 `courseId` 读取当前课程封面的 API，默认 `inline` 查看，可通过明确参数切换为附件下载。
5. 读取时先校验当前机构内课程可见性及课程与文件的真实关联，不允许仅凭 `fileInfoId` 读取任意系统文件。
6. 同步课程 OpenAPI、自动化测试、QA、Retro 和开发进度记录。

## 非目标范围

- 不修改任何前端页面、Mock、联调或 UI；前端以 OpenAPI 为准另开。
- 不修改 `source`、`derivative` 对象键，不增加日目录，不迁移或重命名任何既有对象。
- 不新增 bucket；`course-cover` 是现有私有 bucket 内的对象键前缀。
- 不新增或修改数据库表、字段、索引、初始化数据或 Flyway migration；复用既有 `cover_file_id` 和 `us_sys_file_info`。
- 不生成缩略图、不裁剪、不压缩、不转码课程封面。
- 不自动删除未引用或被替换的封面文件；孤儿文件治理另行设计，避免误删仍被其他记录引用的文件。

## 人工确认点

确认后实施以下契约：课程封面上传到 `course-cover/{yyyy}/{MM}/...`；课程创建/更新通过 `coverFileId` 关联；读取接口以
`courseId` 为资源边界，默认内联查看并支持显式下载；`source`、`derivative` 和旧对象全部保持不变。
