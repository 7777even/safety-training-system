# 设计：考试发布后批阅锁定与工作台页签

## 成绩发布后的批阅锁定

1. 以作答的正式成绩发布事实为唯一判定依据：作答状态为 `PUBLISHED` 且已记录正式成绩发布时间时，视为已发布。
2. 服务端在既有教师提交人工评分的业务入口加载作答后先校验该事实；已发布时返回既有业务异常，不写入答案评分、总分、及格结果或作答状态。
3. PC Web 批阅页读取现有作答详情中的成绩发布状态；已发布时展示“正式成绩已发布，当前作答不可再批阅或改分”提示，将评分控件与提交操作置为只读或不可用。
4. 前端限制仅改善交互，服务端校验仍是最终边界；竞态下服务端拒绝后保留既有错误反馈。

## 工作台资源级页签

后台 tabs-card 继续保留普通页面以 `fullPath` 区分的现有行为。仅对以下工作台生成稳定的页签标识：

- 考试工作台：`/admin/business-center/exams/exam/{examId}`，忽略 `stage` 查询参数。
- 课程工作台：`/admin/business-center/course/center`，按 `courseId` 归并，忽略 `stage` 与创建态 `mode` 查询参数。

切换工作台阶段时，保留当前路由完整参数以驱动工作台面板；tabs-card 只更新同一稳定页签的可点击地址，而不追加同名页签。列表、创建态和不同资源
ID 仍是独立页签。试卷工作台不改动，以其当前单页签交互作为一致性参照。

## 考试基础信息展示

考试工作台的基础信息使用既有 `admin-detail-page` 主内容卡：

1. 常规字段按两列信息组显示，标签和内容使用固定的详情层级，不产生页面级长滚动条。
2. 考试说明、注意事项等长文本使用独立整行区块，文本在内容区域内自然换行；不使用嵌套表格滚动条。
3. 保留原有字段、数据来源、操作与发布状态，不变更保存语义或接口调用。

## API、数据与权限边界

- API：继续使用现有作答详情与人工批阅接口；不新增字段、路径、错误码或 OpenAPI 变更。
- 数据：不新增表、字段或迁移；已发布拦截只阻止后续更新。
- 权限：沿用 `exam:review` 及既有服务端授权；只读 UI 不替代权限校验。

## 风险与取舍

- 将发布后改分完全禁止，符合正式成绩不可变语义；若未来需要成绩更正，必须单独确认更正、审计和重新发布流程。
- 页签归并只忽略工作台阶段性查询参数，避免误合并不同资源或其他详情页。
