# Proposal：补齐学员课程入口与学习任务读取接口

## 背景

现有课程后端已经支持开课、指派/自助报名、学习会话上报、报名进度和评价，但学员读取侧只有单条报名进度详情：

- 没有按当前登录人分页查询“我的课程”的接口。
- 现有开课分页是管理端接口，需要管理权限，不能作为学员选课入口。
- 现有报名详情只返回报名及内容项进度事实，不返回冻结版本中的课程、章节、内容项和素材引用，无法构建学习任务清单。

上述缺口使调用方无法从后端契约完成“找到课程 → 进入本人报名 → 读取冻结任务 → 上报学习”的纵向链路。

## 目标

1. 提供仅查询当前登录人报名记录的“我的课程”分页接口。
2. 提供仅展示当前用户此刻可以自主报名的开课分页接口。
3. 提供仅允许报名本人访问、基于开课冻结版本快照组装的学习任务清单。
4. 将三个接口及字段、过滤规则、本人访问边界、错误码和示例同步到 `docs/api/course.openapi.json`。

## 用户价值

- 学员可以获得稳定的课程入口、选课入口和学习目录。
- 学习任务来自开课发布时冻结的课程版本，不会被后续课程草稿修改污染。
- 本人报名边界由后端执行，调用方无需依赖前端隐藏来保护其他学员数据。

## 功能范围

- `GET /api/course/learning/my-enrollments`
- `GET /api/course/learning/offerings`
- `GET /api/course/learning/enrollments/{enrollmentId}/tasks`
- 课程名称、开课名称、报名和学习状态、进度、时间、封面等学员读取 VO。
- 关键字、课程分类、开课状态、学习状态和分页过滤。
- 当前机构隔离、当前登录人报名归属、参与范围和自主报名资格校验。
- 零 DB Controller/Service 测试，以及真实分页、分类过滤和版本快照读取所需的带 DB 测试。

## 非目标范围

- 仅后端；前端以 OpenAPI 为准另开，不包含页面、Mock、UI 或前端联调。
- 不新增报名容量、名额、候补或抢课模型；当前无容量字段，“剩余状态”只表达当前记录是否仍可报名，不返回虚构的剩余人数。
- 不修改既有自助报名、退选、完成判定、学习会话或评价业务规则。
- 不提供未报名课程的完整课程内容预览。
- 不实施素材转码、派生文件、在线预览或播放地址。
- 不新增角色权限码；三个学员接口保持“登录即可 + 后端本人/资格校验”。
- 不修改数据库结构，不创建 migration。
