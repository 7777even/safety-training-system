# Proposal：补齐系统菜单管理 CRUD

## 背景

系统菜单管理当前只提供菜单树查询和可见性调整，管理员无法通过 API 新增、编辑或删除菜单，导致菜单维护能力不能形成闭环。

## 目标

- 在既有 `/api/system/menus` 资源下新增菜单、新增、修改与删除接口。
- 保持既有菜单树、可见性和权限查询能力兼容。
- 为菜单 CRUD 提供一组不依赖数据库的单元测试和一组基于 Testcontainers MySQL 的集成测试。
- 将新增接口同步到唯一 API 契约 `docs/api/system-admin.openapi.json`。

## 用户价值

系统管理员能够通过受权限保护的 API 完成菜单维护，并能通过自动化测试确认业务约束和真实 MySQL 写入行为。

## 功能范围

- 新增 `POST /api/system/menus`、`PUT /api/system/menus/{menuId}`、`DELETE /api/system/menus/{menuId}`。
- 新增对应 DTO、Service 方法、Controller 权限与操作审计。
- 校验父菜单存在性、禁止将菜单移动到自身或其后代。
- 删除前检查子菜单和角色菜单关联，避免留下不可达树或脏授权关系。
- 新增无数据库单元测试与真 MySQL 集成测试各一组。
- 同步 OpenAPI 请求、响应、权限、字段说明与示例。

## 非目标范围

- 不修改 `us_sys_menu` 表结构，不新增 migration。
- 不改变现有菜单树、可见性批量更新和侧边栏查询接口。
- 不新增或修改角色、用户授权模型。

## 待确认

- 暂定：删除有子菜单或已被角色关联的菜单时返回冲突错误，不做级联删除或自动解绑。该策略须经开发人员确认后才可实现。
