# Design：同次开课评价列表

## 读取路径

学员从 PC「我的课程」卡片或移动端课程详情进入「课程评价」。客户端以本人 `enrollmentId` 请求分页列表；服务端先验证登录人拥有该报名且报名有效，再从报名读取 `courseOfferingId` 查询 `sts_course_evaluation`。客户端不传开课 ID、机构 ID 或用户 ID 作为查询范围。

契约：`GET /api/course/learning/enrollments/{enrollmentId}/evaluations?pageNum=1&pageSize=20`，`x-permission: authenticated`。返回 `total` 与列表项 `rating`、`content`、`submittedTime`、`displayName`、`isAnonymous`。按提交时间倒序、评价 ID 倒序稳定分页；仅返回正常、未逻辑删除记录。匿名项的 `displayName` 固定为「匿名学员」，提交时间仅返回日期，响应不含用户 ID、报名 ID。实名项展示 `SysUser.userName`；姓名缺失时展示「学员」，不由前端拼接。

## 页面

- PC：`学习中心 → 我的课程` 的每张有效报名卡片均显示「课程评价」按钮，沿用当前卡片按钮位置；点击打开独立评价抽屉。抽屉顶部展示本人的评价或已完成且未评价时的提交表单，下方展示「同次开课学员评价」分页列表和空态；原仅完成课程可见的提交弹窗入口归并到此抽屉，不放进「学习任务」抽屉。
- 移动端：`学习 → 我的课程 → 课程详情` 中，在课程标题/进度区之后、课程目录之前展示「课程评价」区；所有有效报名都能查看同次开课评价。已完成课程在同一区顶部提交或回看本人评价，下方分页展示其他学员评价；学习中的学员只看到列表，不显示提交表单。现有已完成卡片「查看课程与评价」进入此详情页。
- 提交成功后刷新同课列表和本人详情；失败不伪造评价。匿名仅影响同课展示，不影响本人回看。

## 风险与取舍

现有本人详情接口只返回本人的评价，不能替代同课列表。匿名项仅展示日期，以降低小班级按精确时间推断评价人的风险。旧数据按现有记录读取，不迁移。
