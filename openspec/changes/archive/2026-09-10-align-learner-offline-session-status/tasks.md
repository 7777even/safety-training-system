# Tasks：对齐学员端线下场次状态

> Owner：待人工确认。

## 1. 学员结果项返回线下场次状态

- [x] **输入**：学员培训详情结果投影、线下场次状态和 Training OpenAPI。
- [x] **输出**：`OFFLINE` 结果项返回可空 `sessionStatus`；其他内容类型不伪造场次状态。
- [x] **前后端影响**：后端只读结果 VO/查询与 OpenAPI；PC Web 以更新后的契约读取。
- [x] **API 依赖**：学员培训详情、学员线下场次详情。
- [x] **数据影响**：无数据库结构变化。
- [x] **验收标准**：教师开始场次后，学员结果项 `resultStatus` 仍可为 `PENDING`，同时 `sessionStatus=IN_PROGRESS`；无场次时字段为空。
- [x] **测试方式**：先添加后端零 DB 测试覆盖进行中场次与未评分个人结果并存；运行受影响后端测试。

## 2. 学员端区分场次状态与个人完成状态

- [x] **输入**：学员培训详情 `OFFLINE` 结果项的 `sessionStatus`、`resultStatus`。
- [x] **输出**：线下内容卡展示实际场次状态；线下场次详情分别展示场次状态和完成状态。
- [x] **前后端影响**：仅 PC Web 页面、类型和定向测试。
- [x] **API 依赖**：学员培训详情、学员线下场次详情。
- [x] **数据影响**：无。
- [x] **验收标准**：进行中而未评分的线下卡显示“进行中”且不计入已完成；课程/考试/题库状态不变；线下详情不再把完成状态作为场次状态。
- [x] **测试方式**：先添加 PC Web 状态选择回归测试，运行定向 Node 测试与 PC typecheck。
