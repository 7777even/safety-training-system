# Proposal：收紧培训综合成绩配置、计算门禁与来源追溯

> 状态：已确认。Owner：fxw11。确认日期：2026-09-15。

## 覆盖的功能项

- 功能项 39：支持在线设置综合素质评分表，根据奖惩或考试成绩自动计算得分。
- 功能项 40：综合素质评价表模板支持表单规则、综合分数设置，并可在培训管理过程引用。

本 Change 将“培训计划引用的 `COMPOSITE` 表单”收敛为有真实、可追溯来源的成绩公式；奖惩等尚无本计划可追溯正式成绩来源的能力不纳入本次正式计算。

## 背景

当前表单编辑器允许任意项目、任意来源和多个规则，项目权重与规则权重并存但计算服务只读取规则权重。计划中同一类型的多个考试或线下内容虽已有 `scoreWeight` / `scoreAggregationMode` 字段，但 PC 未完整配置，后端也未禁止混用聚合方式。计算时，缺失的课程、考试或线下来源会按 0 参与公式，容易生成看似有效但实际不可解释的综合成绩。

## 目标

- 明确两层权重：计划内容层先将多门课程、多项考试或多个线下活动汇总为类别成绩；表单规则层再将类别成绩计算为综合成绩。
- 将可绑定到培训计划的 `COMPOSITE` 表单限制为唯一、可追溯且权重闭合的课程/考试/线下公式。
- 任一被公式引用的类别存在未出正式成绩的计分内容时，拒绝创建计算批次；不以 0 补位，也不允许确认不完整成绩。
- 计算批次保存逐内容来源、类别汇总和公式快照，PC 结果抽屉据此展示多项成绩的构成和权重，而不是只显示一条模糊类别分数。

## 范围

- `COMPOSITE` 表单发布校验、计划绑定校验、计划内容计分/聚合配置、计算与确认门禁、计算来源查询接口和 PC 对应界面。
- 仅允许 `COURSE`、`EXAM`、`OFFLINE` 三类 `WEIGHT` 规则；一个来源至多一条规则；规则权重合计必须为 1；每条规则必须关联唯一的分数项目。
- 计划中被评分表引用的类别必须至少存在一个 `isScored=1` 内容；同类别的计分内容只能统一为 `AVERAGE` 或 `WEIGHTED_AVERAGE`。加权平均的每项权重大于 0 且合计为 1；算术平均不允许填写内容权重。
- 每个被引用类别的全部计分内容必须已有正式成绩，才可创建和确认该参训人的综合成绩批次。
- 历史批次的来源明细按 `planContentId` 保存并只读展示，包含单项正式分、类别内汇总方式/权重、类别汇总分和表单层权重。

## 非目标

- 不引入人工录入、奖惩加减分、批量计算、自动确认或跨计划成绩中心。
- 不修改已确认的正式综合成绩、已结束计划冻结结果或历史批次。
- 不为旧的无效表单或已发布计划自动修复配置或补写分数；管理员须新建合规表单版本或在草稿计划中调整后重新发布。

## 前后端与数据影响

- 后端：修改表单发布、计划绑定与计算服务；新增计算来源只读查询；更新 OpenAPI、错误码、单元测试和 MySQL 集成测试。`calculation_source` 复用既有表，不新增数据库表或字段。
- PC：将 `COMPOSITE` 编辑器收敛为来源规则配置；在草稿计划阶段补齐类别内聚合设置；结果抽屉展示计算阻塞原因和逐内容来源历史。
- 已发布计划兼容：可以读取既有结果；若绑定的表单/内容配置不合规，新的计算请求返回明确配置错误，绝不以 0 分计算。

## 成功标准

一名学员有两项考试 80/90、两项线下评分 70/100，计划分别配置考试加权 40%/60%、线下算术平均，表单配置考试 60%、线下 40% 时，页面和批次均能显示：考试类别 86、线下类别 85、综合成绩 85.6；若其中任一计分内容未发布正式分数，计算接口不创建批次并返回缺失内容名称和类别。
