# Design：严格的培训综合成绩规则

## 已确认的业务口径

### 两层计算

1. **计划内容层**：只处理同一来源类别的多个 `isScored=1` 内容。`AVERAGE` 为算术平均；`WEIGHTED_AVERAGE` 按内容 `scoreWeight` 加权平均。题库练习固定 `isScored=0`，不属于任何类别成绩。
2. **表单规则层**：只处理类别成绩。`COURSE`、`EXAM`、`OFFLINE` 各最多一条 `WEIGHT` 规则，使用规则 `weight` 相加得到综合成绩。

因此，多个考试的权重配置在草稿计划的每个考试内容；考试类别占综合成绩的比例配置在评价表单。两者不再混淆。

### 严格完成门禁

`COMPOSITE` 表单中每一条来源规则都表示必需来源。计算前服务必须同步该参训人的内容投影，并检查每个被引用类别：

- 计划至少有一个该类别的 `isScored=1` 内容；
- 所有这些内容都有正式、可计分的分数；
- 类别聚合分非空。

任一检查不通过，`POST calculate` 返回 409 / 新增业务码 `8806`，响应消息列出类别及缺分内容名称；不得插入 `CALCULATED` 记录。真实 0 分是有效正式成绩，不视为缺分。确认接口再次按同一规则校验，防止旧批次在来源失效后被确认。

本 Change 采用“未齐全即不创建批次”的严格模式，不保留试算批次，以免 `CALCULATED` 被误认成可确认成绩。

## 表单约束

仅在 `formType=COMPOSITE` 时应用下列发布校验；`EXPERT_INSPECTION` 维持现有通用项目能力。

- 每个计分项目必须是 `SCORE`，满分固定 100、必填，且恰好对应一条规则；禁止孤立项目、文本项目和多个规则引用同一项目。
- 规则必须是 `WEIGHT`，`sourceType` 仅允许 `COURSE`、`EXAM`、`OFFLINE`；禁止 `MANUAL`、`REWARD_PENALTY` 与 `ADJUSTMENT`。
- 同一来源只能出现一次；至少一条规则；每条权重大于 0，全部规则权重按两位小数精度合计 1。
- 项目 `weight` 不再是独立编辑值：PC 从对应规则权重只读展示；服务端要求其为空或与规则权重一致，以兼容既有存储并消除双重真相。

PC 创建 `COMPOSITE` 表单时只提供三种固定来源卡片，管理员勾选所需来源并填写表单层权重；每种来源自动生成唯一的项目与规则。发布前显示权重闭合和“要求计划具备全部来源正式成绩”的说明。

## 计划配置与绑定校验

草稿计划阶段表中，对 COURSE、EXAM、OFFLINE 的“计入综合成绩”内容显示类别内汇总方式和内容权重。

- 一个类别的全部计分内容必须选择同一种汇总方式。
- `AVERAGE` 不显示且不保存内容权重。
- `WEIGHTED_AVERAGE` 的每项权重范围为 `(0, 1]`，同类别合计为 1。
- QUESTION_BANK 始终不计分，不显示汇总配置。

计划绑定 `COMPOSITE` 版本以及计划发布预检均执行匹配校验：评分表每个来源都必须在计划中找到至少一个计分内容；计划存在的其他计分类别可以不被该表单引用，但页面明确标记“已计分但未纳入本表单”。计划进入 `PUBLISHED` 后配置冻结。

## 计算来源与历史展示

计算服务不再仅以 `planContentId=0` 写三条类别伪来源。每个合规的计分内容写入一条 `calculation_source`，`sourceSnapshotJson` 包含内容名称、正式成绩、类别内汇总方式、内容权重、类别汇总分以及表单规则权重；规则快照继续保存在 calculation run。

新增 `GET /api/evaluation/calculation-runs/{calculationRunId}/sources`，权限沿用 `evaluation:calculation:list`，只返回当前机构且调用方可见的批次。PC 历史记录按批次可展开，分组显示课程/考试/线下：单项名称、正式分、类别内权重、类别汇总和计入综合成绩的贡献。顶部只显示最新待确认或已确认批次的综合分，避免将多项考试压成一个不可解释的“考试成绩”。

## 兼容性与错误边界

- 旧版本若有重复来源、`MANUAL`、调整项、权重不闭合，不能再绑定到草稿计划；已绑定计划计算时返回 409 / `8807`“综合评价表单规则不合规”，不改动历史。
- 已发布计划若同类别混合汇总方式、加权权重不闭合或表单所需来源未配置，计算时返回 `8807`；管理员不能在执行中修改冻结计划，只能保留历史并按受控更正流程重新建计划。
- 401、403、8802、8803、8804、8805 保留现有语义；前端原样显示后端中文错误，不伪造计算成功。

## TDD 测试边界（已确认）

1. `EvaluationFormService.publishNewVersion`：拒绝重复来源、非真实来源、调整规则、权重不闭合和项目/规则不一致；合规课程+考试+线下规则可发布。
2. 计划绑定/发布预检：拒绝表单来源在计划没有计分内容、同类混合聚合方式或加权权重不闭合；合规多考试、多线下配置可发布。
3. `CalculationRunService.calculate` / `confirm`：缺任一来源内容的正式分数时返回 `8806` 且不写批次；两项考试与两项线下的类别汇总和表单层加权正确，且来源明细可查询。
4. PC：固定来源编辑器、计划类别内汇总配置及结果抽屉的阻塞/历史明细按 OpenAPI 正确渲染。
