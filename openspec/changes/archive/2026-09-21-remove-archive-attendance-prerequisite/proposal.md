# Proposal：移除正式培训档案的伪出勤前置条件

## 状态与范围

- 状态：实现完成、验收待补；归档伪 `ATTENDANCE` 前置已移除，真实文件 ID 已持久化到归档版本。
- 覆盖功能项：44 三级档案中的一期一档正式生成与下载。
- 业务基线：线下培训为“管理员配置、学员只读、教师按学员评分；评分决定线下培训完成”。不需要签到、签退、扫码、定位或现场证据。

## Why

当前归档服务无条件把 `ATTENDANCE` 加入 `missingItems`，即使培训已结束、结果完整也会永久返回 `409/9204`，导致正式档案无法生成。这是遗留技术前置，不是既定业务规则。

## What Changes

- 删除归档服务对 `ATTENDANCE` 的无条件缺失判定。
- 保留 `ENDED` 与结果完整性校验；存在 `INCOMPLETE` 参训结果时继续返回 `RESULTS`，不得生成正式档案。
- 归档仍冻结既有计划、机构、参训人、结果、评价、奖惩、证书和附件快照，并生成真实文件供授权下载。
- 同步 `archive.openapi.json` 中“签到等必需事实”和 `ATTENDANCE` 相关描述、examples、9204 说明；不新增 HTTP 路径、DTO/VO 字段或权限。
- PC 仅移除针对 `ATTENDANCE` 的特定阻塞文案，仍按服务端 `missingItems` 和 `fileInfoId` 控制下载。
- 新增 `sts_archive_version.file_info_id`，并同步 Flyway migration、init schema、`ArchiveVersion` Entity 和归档服务回读；只保存真实生成文件的受控主键。

## 实施中发现的范围差异

既有归档创建会生成文件，但没有在档案或版本记录持久化文件 ID，下载读取路径无法定位该文件。经人工确认，已增加版本文件 ID 及 migration/init schema，并同步 Entity、服务和归档 IT；真实数据库与对象存储下载验证仍待可用环境执行。

## 非目标

- 不新增任何签到实体、表、接口、权限、页面、扫码、定位、签退、图片证据或移动端流程。
- 不改变教师评分、培训完成、获得学时、综合成绩、证书签发和档案版本语义。
- 不删除真实缺失事实的拒绝逻辑；`RESULTS` 等已有缺失项仍必须阻止归档。

## 验收目标

结果完整的 `ENDED` 培训无需签到即可生成并下载真实档案；结果不完整仍返回 `409/9204` 且 `missingItems` 含 `RESULTS`；PC 不伪造文件或绕过服务端错误。
