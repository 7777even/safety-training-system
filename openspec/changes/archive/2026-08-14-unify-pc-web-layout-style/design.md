# 设计方案

## 1. 长期 UI 标准

本 Change 的设计结论同步沉淀到 `docs/design/pc-web-ui-standard.md`。该文档是后续 PC Web 门户、后台页面和通用组件开发的长期视觉与布局标准；新增页面必须优先复用其中的 token、壳层结构和列表结构。

## 2. 布局结构

后台采用固定视口结构：顶部工具栏、侧栏与工作区。工作区内部由 tabs-card、breadcrumb 和页面内容组成，内容区使用 `min-height: 0`，避免页面级长滚动；表格滚动仅发生在 `ElTable` 容器内。

旧 `admin-page-header` 不再渲染。页面标题由面包屑和列表卡片标题承担，业务页面中已有的自定义标题仅在不重复时保留。

## 3. 全局视觉 token

- 页面背景、卡片背景、边框、主色和文字颜色沿用现有 Element Plus 映射，不新建第二套颜色体系。
- 正文 14px、辅助文字 12px、页面标题 18px、卡片标题 16px；控件高度统一为 32px，按钮间距统一为 8px。
- 工作区外间距 16px，卡片间距 12px，卡片内边距 16px。

## 4. 列表高度

页面通过常量绑定 `ElTable` 的 `height`，不在页面中散落计算式。若页面存在额外工具条，先通过统一内容容器的布局吸收，不私自引入第三种高度。

## 5. 面包屑

根据当前路由的 `matched` 记录和动态菜单树生成完整路径，例如“系统管理 / 机构组织 / 岗位管理”。菜单节点的标题来自授权菜单数据，面包屑末项不可点击，父级可点击时跳转到对应落地页。

## 6. tabs-card

由后台布局维护当前已访问的菜单页面。标签 key 使用路由 name 或完整 path，标题使用路由 meta.title。当前页刷新、关闭当前、关闭其他、关闭全部为布局级操作；首页或当前默认落点不可被关闭。tabs 状态仅保存在前端会话存储，不改变服务端状态。

## 7. 兼容与风险

- 动态菜单路由继续作为导航和权限展示的唯一来源。
- 没有分页的树表继续保留现有树展开能力，只替换容器高度和布局。
- 先改布局组件和具有代表性的后台列表页，再通过全局搜索清理不一致的分页 layout、旧 page-header 和操作按钮类型。
