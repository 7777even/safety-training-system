# Design：课程模块 PC 管理端前端

## 1. 依据与边界

- API 唯一依据：`docs/api/asset.openapi.json`、`docs/api/course.openapi.json`。
- 业务依据：`FR-ENT-CRS-001`～`FR-ENT-CRS-010`，以及已归档的课程素材、编排、发布和开课 OpenSpec。
- UI 依据：`docs/design/`、已确认的 Figma Design System 和现有 PC 管理端业务中心布局。
- 本 Change 不修改 API、权限语义、数据库结构或后端实现。

## 2. 页面信息架构

### 2.1 素材库

- 列表筛选：素材名称、类型、处理状态、启停用状态。
- 表格字段：编码、名称、类型、处理状态、启停用状态和操作。
- 操作：创建、编辑、删除、失败转码重试、查看转码任务。
- 创建仅登记 Contract 已定义的素材元数据；文件上传继续使用已有 `/system/files` 能力取得 `fileInfoId`，不虚构预览或下载地址。

### 2.2 课程分类与机构设置

- 分类使用树形列表维护新增、修改、移动、排序、启停用和删除。
- 机构设置使用独立表单维护默认学习时长、媒体完成比例、断点续播、防快进、水印相关默认值、离页暂停和转码通知。
- 所有更新提交后端返回的 `version`；冲突时提示刷新，不静默覆盖。

### 2.3 课程中心与课程编辑器

- 课程中心提供名称、分类、发布状态和启停用状态筛选，以及创建、编辑、删除、发布、下线、版本查看入口。
- 课程编辑器分为基本信息、目录与内容、下载资料三个区域。
- 目录与内容按“章节 → 内容项”展示；仅允许创建 `ASSET`、`LIVE`。
- 素材内容项通过素材选择器引用 `SUCCEEDED` 素材；直播内容项维护场次；材料规则支持使用机构默认、保存自定义和恢复默认。
- 内容项支持跨章节移动；章节创建遵从当前 Contract 的根级章节约束。

### 2.4 发布版本与开课学习管理

- 版本页提供发布、下线、版本历史和只读快照查看。
- 开课页提供列表、创建、编辑、发布、取消、结束和删除。
- 开课详情提供指派报名、报名筛选、移除报名和管理员学习详情。
- 参与范围仅传递既有 `audienceId`；没有已确认的范围选择接口时不自行构造组织授权 UI。

## 3. 前端模块设计

- `src/api/asset.ts`：素材与转码任务 Contract 类型和请求函数。
- `src/api/course.ts`：课程配置、编排、版本、开课、报名和学习管理 Contract 类型和请求函数。
- `src/constants/course.ts`：素材类型、状态、课程状态和显示文案；禁止页面散落魔法值。
- 课程业务页面统一放入 `views/admin/business-center/class/`；素材库放入 `views/admin/business-center/resource-library/`。
- 不创建兼容历史后端 `component` 字符串的薄入口；菜单组件路径由管理员按交付关系表配置。
- 只在两个以上页面语义完全一致时提取业务组件；首期不引入新的生产依赖或全局业务 Store。

## 4. 状态、权限与错误处理

- 列表页使用 `DEFAULT_LIST_PAGE_SIZE`，查询参数必须采用 Contract 的 `query.*` 字段名。
- 按钮通过 profile 菜单树权限点展示；后端仍是授权边界。
- `2040` 乐观锁冲突统一提示“数据已被更新，请刷新后重试”。
- 业务错误沿用统一请求错误处理；页面仅补充删除保护、状态不允许等需要用户采取行动的中文提示。
- 发布、下线、删除、取消开课、结束开课和移除报名使用二次确认。

## 5. TDD 与验证设计

公开测试缝：

1. API 请求封装：请求方法、URL、查询字段和请求体与 OpenAPI 一致，统一响应正确解包。
2. 管理端页面用户行为：筛选使用统一分页、权限决定入口、危险操作需要确认、乐观锁携带版本。
3. 业务组件关系：课程中心能打开课程编排与版本工作区，各独立菜单页面有稳定的 `business-center` 组件路径。

每个 Task 按一个失败测试对应一个最小实现的纵向循环推进；完成后运行 PC Web `lint`、`typecheck` 和 `build`。

## 6. 风险与阻塞

- 本轮已确认沿用现有 PC 管理端 Design System；独立 Figma 页面不再作为 Task 1～3 的实施阻塞项。
- 现有两个未跟踪页面目录属于用户工作树，实施时只在确认后精准替换其占位内容，不删除目录。
- 学员端、文件预览下载、课程授权和考试类内容项受 Contract 阻塞，不进入本 Change。

## 7. 临时 Mock 方案

- 素材与课程 API 的导出函数、参数和返回类型保持不变，页面不感知数据源切换。
- Mock 放入 `frontend/pc-web/src/mock/`，通过统一开关在 API 边界选择 Mock 或现有真实请求实现。
- Mock 使用模块级内存保存会话内变更，提供契约内的分页筛选、状态流转、版本递增和业务错误；刷新页面恢复种子数据。
- 所有 Mock 入口标记 `TODO replace real api`。后端完成时删除 Mock 分支并复用已保留的真实请求代码。
