# Proposal：补全学员考试查询与答案契约

## 背景

现有考试后端已支持考生绑定、开始作答、答案暂存、交卷、判分、人工批阅和成绩发布，但面向学员的读取契约尚未形成完整闭环：

1. 缺少按当前登录学员查询本人考试任务的分页接口。
2. Attempt 详情只返回题目和选项，未返回已经暂存的答案，刷新或重新进入后无法恢复作答现场。
3. OpenAPI 缺少完整的 `ExamAnswerVO` / `ExamAnswerItemVO`，成绩发布状态及发布前后的字段可见性也不明确。
4. Attempt 详情目前仅按主键读取，尚未把“本人执行链”校验作为学员访问规则落实。

这些缺口会阻断 PC / 移动端基于 OpenAPI 完成真实考试联调，并可能导致未发布成绩或非本人 Attempt 被不当读取。

## 目标

交付纯后端的学员考试读取闭环：

1. 当前登录学员可分页查询本人的考试任务，并获得开始、继续作答、等待批阅、查看已发布结果所需的稳定状态。
2. 当前登录学员可读取本人的 Attempt 详情，恢复已暂存的文本、多选、填空等答案。
3. 提供完整、可复用的 `ExamAnswerVO` / `ExamAnswerItemVO` OpenAPI schema。
4. 服务端依据成绩发布状态和答案详情策略裁剪评分、正确性、正确答案与解析，不依赖前端隐藏敏感字段。
5. 学员读取必须校验当前登录用户与 `sts_exam_candidate` / `sts_exam_attempt` 的本人执行链；管理与阅卷访问继续按既有业务权限和任务归属控制。

## 用户价值

- 学员能够从“我的考试”进入任务，在刷新、断线重进或跨端继续时恢复已暂存答案。
- 学员只能查看本人的考试事实，并且只能在成绩发布及考试策略允许后查看成绩和答案解析。
- 前端可直接依据机器可读 OpenAPI 完成任务列表、作答恢复和结果展示，无需猜测字段或拼装管理端接口。

## 功能范围

- 学员本人考试任务分页查询。
- 学员 Attempt 详情的本人访问校验。
- Attempt 详情返回题目、选项及其已暂存答案。
- 明确成绩发布状态、发布时间和成绩可见性。
- `ExamAnswerVO`、`ExamAnswerItemVO` 及关联 OpenAPI example。
- 学员、管理端、阅卷端读取场景的字段可见性和权限边界。
- 对应零 DB Controller / Service 测试；涉及真实 Mapper 查询与分页时补充最小 MySQL IT。
- 同步 `docs/api/exam.openapi.json`、OpenSpec Task、进度记录和 QA / Retro。

## 非目标范围

- 任何 `frontend/` 修改、页面、Mock、UI 或前端联调。
- 新增或修改数据库表、字段、索引及 migration。
- 改变既有判分、批阅、补考、练习重置或成绩计算规则。
- 新增消息通知、考试提醒渠道或完整任务中心聚合。
- 提前开放正确答案、正确选项、题目解析或未发布成绩。

## 前后端影响

仅后端；前端以 OpenAPI 为准另开。
