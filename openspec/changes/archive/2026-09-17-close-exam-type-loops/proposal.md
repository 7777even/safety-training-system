# Proposal：补齐四类考试类型的闭环缺口

## 背景

考试工作台的四类考试（`examType` = ONLINE / SPECIAL_PRACTICE / BANK_PRACTICE / OFFLINE）在前端只在
`ExamDefinitionForm.vue:39-40` 有三行差异（是否必绑已发布试卷版本、是否必绑题库），此后全部收敛到同一条
作答链。2026-09-17 在本地 MySQL + 后端的真实环境跑通了四类考试全链路（建库→建卷→建考试→绑学员→开考→
答题→交卷→教师批阅→发布成绩→学员看分），实测结果：

| 类型 | 出现「我的考试」 | 开考后冻结题数 | 交卷后 | 批阅 | 发布 | 学员最终分 |
|---|---|---|---|---|---|---|
| ONLINE | 是（给 START） | 3 | PENDING_REVIEW | 可批阅 | 可发布 | 70，及格 |
| SPECIAL_PRACTICE | 是（给 START） | 3 | PENDING_REVIEW | 可批阅 | 可发布 | 70，及格 |
| BANK_PRACTICE | 是（给 START） | 3（题库全量，每题 1 分） | PENDING_REVIEW | 可批阅 | 需人工 | 2，不及格 |
| OFFLINE | 是（给 START） | **0** | PENDING_PUBLISH | 无批阅项 | 可发布 | **0，不及格** |

ONLINE 与 SPECIAL_PRACTICE 已闭环；其余三类存在必须修复的缺陷。

## 覆盖的功能项

| 编号 | 原文语义（节选） | 本变更如何覆盖 |
|---|---|---|
| 14 | 「支持管理员通过题库创建专项训练和题库练习，企业学员可通过练习熟悉掌握对应的专业能力」 | 为独立 BANK_PRACTICE 提供抽题规则配置，取代「全题库全量冻结」 |
| 16 | 「考试管理模块能够实现管理员在线安排考试的功能……设置阅卷人；设置考试有效时间段、有效时长、有效次数」 | 线下考试成绩录入入口纳入考试安排闭环 |
| 17 | 「成绩批阅：学员参与考试提交试卷后，系统可以对客观题进行自动评分，主观题部分由阅卷人进行在线手动阅卷」 | 已闭环，不改；仅受益于答案可见性修复 |
| 49 | 「(1)我的练习……②题库练习 按列表展示所有已分配的练习」；「(2)在线考试」 | 学员端「我的练习」不再出现不可作答的空卷 |
| 55 | 「我的考试：展示学员的考试信息……提供进入考试的入口……记录已完成考试的考卷详情」 | 提供入口前先确保可作答；「考卷详情」依赖答案可见性修复 |
| 64 | 「展示线下培训课堂考试所添加的考试内容，并对学员考试结果进行统计分析」 | 线下考试结果由管理端录入，不再由学员空考产生 |

## 变更范围

1. **线下考试（OFFLINE）闭环**：学员端不再把 OFFLINE 考试当作可作答考试；新增管理端线下成绩录入接口；
   学员端按录入结果展示成绩与是否合格。
2. **题库练习（BANK_PRACTICE）抽题规则**：复用培训模块既有的抽题规则能力（`QuestionBankDrawEngine` +
   `drawRules` 快照），管理端可在创建/编辑考试时配置抽题规则；及格分按抽题实际满分折算。
3. **答案详情可见性**：修复 `answerDetailMode=PUBLISHED`（前端「成绩发布后可见」）在后端无实现分支的问题。
4. **跨端考试类型文案**：`examType` 中文映射收敛到 `shared`，消除移动端渲染裸枚举码。

## 非目标

- 不实现线下考试的「考试过程」能力（无线上作答、无防作弊），仅覆盖成绩录入与查看。
- 不为独立 BANK_PRACTICE 新增「提交即生效」语义；其生效仍走既有发布流程。
- 不改动 SPECIAL_PRACTICE 现有行为（实测已闭环），仅补充定向测试。
- 不引入题库练习的错题/收藏增强（功能项 49 的其余部分另行确认）。

## 风险与缓解

- **数据兼容**：`sts_exam_exam` 新增抽题规则存储列，历史 BANK_PRACTICE 考试该列为空。空值时的行为需在
  design 中明确定义，避免历史数据在发布时报错。
- **ID 错位**：OFFLINE 的 `resource_id` 当前等于 `examId`，若库中存在同号 `paper_version` 会冻结无关题目。
  修复后该路径不再可达，需补测试锁定。
- **契约变更**：新增接口与字段属 L4，需同步 `docs/api/exam.openapi.json` 与调用方。
