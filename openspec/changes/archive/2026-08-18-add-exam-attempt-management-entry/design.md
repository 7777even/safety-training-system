# Design：考试情况阶段与既有作答流程整合

## 方案

考试工作台新增第四阶段“考试情况”。该阶段作为 `exam/workspace/components` 下的嵌入式 Panel，根工作台只传递当前考试 ID 和路由跳转能力。

Panel 调用既有 `getExamAttemptRecordPage`，固定传递 `query.examId`，并允许用户补充：考生关键字、作答状态、批阅状态、成绩发布状态和交卷时间范围。列表展示学员、作答次数、开始/交卷时间、用时、作答状态、批阅状态、成绩、是否通过和成绩发布状态。

## 操作边界

- “查看作答”：进入既有成绩处置页，以只读作答快照、反作弊事件和成绩发布流水查看为主。
- “批阅试卷”：仅有 `exam:review` 权限时显示，进入既有教师批阅页；该页继续由服务端校验该用户是否可批阅。
- “成绩处置”：仅有 `exam:score:publish` 权限时显示，进入既有成绩处置页；未完成主观题批阅时既有页面保持禁用发布。
- “考试批阅”和“成绩管理”继续保留为跨考试任务入口；新增 Panel 只是按考试聚合的入口。

## API 与数据

仅使用既有 Contract：

- `GET /api/exam/attempts`：支持 `query.examId`、学员、作答、批阅与发布状态筛选。
- `GET /api/exam/attempts/{examAttemptId}`：读取作答快照。
- 既有批阅、成绩发布、反作弊事件和成绩发布流水接口。

无 API、数据库或权限变更。

## 风险与取舍

`exam:attempt:list` 是查看作答快照的服务端权限；前端只依既有权限数据控制入口显示，不能替代服务端授权。单次成绩发布保持当前契约，不在本 Change 猜测批量发布规则。
