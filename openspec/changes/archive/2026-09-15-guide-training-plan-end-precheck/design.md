# Design：复用现有事实的结束前检查

## 数据来源

页面不创建聚合接口，按当前计划 ID 复用以下已存在的读取：

1. 执行链接与计划阶段内容，识别尚未安排的内容；
2. 线下场次分页，识别 `IN_PROGRESS` 场次；
3. 每名参训人的培训结果，识别必修内容是否进入 `COMPLETED`、`FAILED` 或 `EXPIRED` 终态；
4. 每名参训人结果中仍为 `IN_PROGRESS` 的内容，识别进行中的课程学习或考试作答；
5. 当前计划的 `COMPOSITE` 表单绑定记录与逐人 `officialCalculationRunId`，识别尚未确认的正式综合成绩。

这些检查仅代表页面已读取的事实。请求失败或前端无法识别的后端规则不伪造“可结束”，页面保留后端结束接口作为最终门禁。

## PC 交互

- 仅当计划为 `RUNNING` 时显示“结束前检查”和“刷新检查”。
- 检查中显示加载状态；存在阻塞项时逐项显示内容/参训人名称及处理说明，并禁用结束按钮。
- 无已知阻塞项时显示“当前已知条件满足，可结束培训”，但仍提示最终以后端门禁为准。
- 取消计划不受结束前检查约束；将其移至单独风险区并说明“取消后保留已有事实且不会产生通过结论”。

## 错误与兼容

- 逐人结果读取失败时显示“无法完整核对”，不把读取失败当作通过，也不在前端伪造后端错误码。
- 真实 0 分是有效成绩；本检查只判断状态和正式综合成绩批次标识，不以分数数值判定完成。
- 不新增 API/OpenAPI 契约、权限、迁移或移动端修改。
