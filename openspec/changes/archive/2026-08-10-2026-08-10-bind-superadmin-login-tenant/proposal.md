# Proposal：将 superAdmin 绑定到登录租户

## 背景

现有多租户实现把账号编码精确为 `superAdmin` 的会话直接设置为全局旁路。该会话进入任意业务接口时，
MyBatis 租户插件都会跳过 `organization_id` 条件与自动填充，产生两个问题：

- `superAdmin` 从某个企业入口登录后，仍可在普通素材、课程、人员等接口中读取全部租户数据，登录时提交的企业编码没有成为业务边界。
- 新增素材、完成分片上传等普通写操作无法稳定获得 `organization_id`，已出现非空约束失败；局部补丁只能修复单个接口，不能消除同类风险。

人工已确认新的规则：登录时携带的企业编码决定本次会话的租户；普通用户必须属于该企业，`superAdmin`
不校验账号归属企业，可以选择任一启用租户登录，但登录后所有普通业务接口都按所选租户隔离。

## 目标

1. 让 `superAdmin` 使用平台唯一凭证登录任一启用租户，不要求其账号归属与目标租户一致。
2. 将登录企业写入所有已认证会话，并作为后续普通业务接口唯一的租户上下文。
3. 取消 `superAdmin` 的请求级全局数据旁路，仅保留其全量功能权限。
4. 将企业开户范围收窄为创建企业主数据和一个可登录的企业管理员，不代建企业内部业务数据。
5. 保持普通用户的企业编码、账号归属和凭证一致性校验不变。

## 用户价值

- `superAdmin` 可以收藏并使用任意企业的路径式入口，进入后看到和操作的就是该企业数据。
- 素材、文件、课程等普通业务写入都能由服务端稳定填充所选企业的 `organization_id`。
- 超级权限与数据范围解耦：`superAdmin` 仍可管理平台，但不会因访问普通业务接口而无条件跨租户。
- 普通用户无法通过修改企业编码登录其它企业，原有租户隔离边界保持不变。

## 功能范围

- 本地登录认证：区分平台 `superAdmin` 与普通租户用户的凭证定位和租户归属校验。
- 登录结果与会话：保存登录时解析出的目标租户 ID、类型和超级管理员标识。
- 请求租户上下文：所有已认证会话默认绑定登录租户，移除 `superAdmin` 请求级旁路。
- 企业开户：创建企业主数据，并以新企业租户上下文创建一个可登录、可管理本企业的管理员账号。
- 审计：登录成功与普通业务操作记录本次登录租户；无法解析租户的失败登录仍记为平台未知租户。
- 同步 `docs/api/system-admin.openapi.json`、受影响自动化测试与工程记录。

## 非目标范围

- 不修改任何前端页面、路径路由、Mock、联调代码或 UI；前端以 OpenAPI 为准另开。
- 不要求客户端在登录成功后的每个 API 请求中重复提交企业编码；后端以 TokenSession 中的登录租户为准。
- 不允许 `superAdmin` 通过 `X-Target-Tenant-Id` 在单个普通业务请求中切换租户；切换企业须重新从目标企业入口登录。
- 不改变监管租户通过 `X-Target-Tenant-Id` 进行只读下钻的既有规则。
- 不新增权限码、角色类型、数据库表或字段；`us_sys_user.dept_id` 调整为可空，不改变 `superAdmin` 的 `*` 功能权限。
- 不实现账号同时归属多个租户；开户管理员仍是一人一租户账号。
- 不为新企业创建默认部门、岗位、标签、普通业务角色、素材、课程或其它企业内部数据；由企业管理员登录后自行创建。

## 影响范围

- `backend/sts-service-admin` 的本地登录策略、认证应用服务、租户过滤器、租户上下文说明与企业开户边界。
- `backend/sts-service-admin` 的认证、租户过滤、租户开户及真实持久化测试。
- `database/migration` 与开发期 schema 中用户部门归属的可空约束。
- `docs/api/system-admin.openapi.json` 登录契约说明与示例。
- 原多租户规格中“`superAdmin` 请求级全局旁路”的设计与需求语义。

## 破坏性变化

- `superAdmin` 登录后调用普通业务接口不再查看全平台数据，只能查看登录企业数据。
- `superAdmin` 不再通过请求级旁路完成普通业务操作；企业管理员账号创建仅在开户事务内使用新企业租户上下文。
- 改造前签发且没有 `organizationId` 的 `superAdmin` TokenSession 不再可用，部署后必须重新登录。
- `us_sys_user.dept_id` 由必填改为可空；仅开户管理员允许暂未分配部门，普通用户创建 Contract 仍要求部门。
