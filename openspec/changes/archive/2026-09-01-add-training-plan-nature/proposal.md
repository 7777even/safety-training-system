# Proposal：补齐培训计划初培 / 复审性质与学时判定

> 状态：已确认并实施完成（2026-09-01）。

## Why

功能项 5 要求培训类型保存“初培学时、复审学时”，功能项 2 要求将实际培训计划与培训类型学时标准比较并形成预警。现有培训计划只保存
`trainingTypeId`，该字段表达高压电工作业、焊接作业等培训类型，不能表达本次计划是初培还是复审。因此系统虽然保存并冻结了
`initialHours`、`reviewHours`，却无法确定应采用哪一个值，发布校验和监管预警也没有形成同一套可追溯判定。

## 本次覆盖的功能项

| 序号 | 原文语义                                  | 本次边界                         |
|----|---------------------------------------|------------------------------|
| 2  | 根据培训类型和实际培训计划形成对比；计划不满足培训类型所设置学时时产生预警 | 为计划冻结可适用最低学时，监管检测按同一冻结口径形成证据 |
| 5  | 培训类型包含初培学时、复审学时和线上培训学时最高占比            | 计划明确选择初培或复审，并使用对应学时完成发布校验与追溯 |

## What Changes

- 培训计划新增必填业务维度 `trainingNature=INITIAL|REVIEW`，并为历史计划保留只读兼容值 `UNSPECIFIED`。
- 发布预检按培训性质选取培训类型学时，叠加只能收紧的培训标准，发布时冻结最终适用最低学时。
- `PLAN_TOTAL_HOURS` 监管检测改读计划冻结口径，证据记录培训性质、实际学时、阈值及来源。
- **BREAKING（请求契约）**：计划创建 / 修改必须提交培训性质；培训类型创建 / 修改必须提交正数初培和复审学时。
- 新增计划关系型字段、Admin Versioned Migration，并同步 init SQL、schema-version 和 OpenAPI。

## Capabilities

### New Capabilities

- `training-plan-nature`：培训计划初培 / 复审选择、发布学时冻结、历史兼容及监管预警一致判定。

### Modified Capabilities

- （无独立 capability delta）既有 `training-execution-loop` 和 `training-api-contract` 的相关实现与契约在本能力实施时同步，完整增量规则集中在
  `training-plan-nature`，避免建立重复规格。

## 目标

1. 培训计划在草稿创建或修改时必须明确选择 `INITIAL`（初培）或 `REVIEW`（复审）。
2. 发布前根据培训性质选择培训类型的 `initialHours` 或 `reviewHours`，与适用培训标准共同计算最低要求学时。
3. 发布时冻结培训性质及最终适用最低学时；来源类型或标准后续修改不改变已发布计划。
4. 监管计划学时预警读取已发布计划的冻结口径，证据能够说明培训性质、实际学时、最低要求及来源。
5. 历史计划不通过名称、学时或状态猜测初培 / 复审，保持可读和可追溯。

## 范围

- 培训计划创建、修改、分页查询和详情返回中的培训性质。
- 培训类型初培 / 复审学时的必填、正值约束及统一“复审”术语。
- 培训计划发布预检、发布冻结和来源快照。
- `PLAN_TOTAL_HOURS` 监管检测对冻结最低学时的使用及证据记录。
- Admin init SQL、Admin Versioned Migration、Entity / DTO / VO、`training.openapi.json` 及必要的
  `regulation.openapi.json` 契约同步。
- 零 DB 测试、真实 MySQL 持久化 / migration 测试和培训计划到监管预警的目标验收。

## 非目标

- 不新增培训类型、培训标准或预警权限。
- 不改变培训计划的课程、考试、题库、线下执行和个人结论口径。
- 不把计划最低编排学时解释为每名学员的实际学习时长门槛。
- 不给培训模板增加初培 / 复审字段；模板继续按培训类型复用，计划实例自行选择培训性质并接受发布校验。
- 不自动修改历史计划的业务性质，不提供批量历史数据订正接口。
- 不新增“复训”或“初审”枚举；本 Change 以功能项原文“初培 / 复审”为准。
- 不实施前端页面、Mock、联调或 UI；前端以 OpenAPI 为准另开。

## 前后端影响

仅后端；前端以 OpenAPI 为准另开。

## Impact

- 后端：培训类型和计划 DTO / VO / Entity / Service、发布校验与快照、监管预警检测和目标测试。
- API：`docs/api/training.openapi.json`；必要时同步 `docs/api/regulation.openapi.json` 的证据语义说明，不新增路径或权限。
- 数据：培训计划新增两个字段；init SQL、新 migration 和 `sts.init.schema-version` 同步。
- 兼容：历史计划明确为 `UNSPECIFIED`，不猜测、不回写；新写请求存在契约不兼容，调用方须按 OpenAPI 另行适配。

## 人工确认关卡

本 Change 修改 API Contract 和数据库结构，属于 L4。确认 Proposal、Design、Tasks 和 Spec Delta 后才允许实施。确认同时表示接受以下
业务决策：

1. 对外业务值只有 `INITIAL`（初培）和 `REVIEW`（复审），“复训”统一改称“复审”。
2. 培训标准只能在培训类型对应学时之上追加更严格要求，不能降低培训类型基线。
3. 历史计划使用 `UNSPECIFIED` 只读兼容，不由系统猜测或自动回填为初培 / 复审。
