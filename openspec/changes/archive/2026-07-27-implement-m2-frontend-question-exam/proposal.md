# Proposal：M2 题库、试卷与考试前端 Mock 优先闭环

## 背景

`2026-07-24-implement-question-paper-exam` 已交付 M2 后端的迁移、权限、OpenAPI
与自动化测试。题库、试卷与考试的真实接口环境尚未可供前端联调；继续让页面直接依赖真实请求会阻塞完整交互和双端体验的开发。

经人工确认，M2 前端先以 `docs/api/question.openapi.json`、`paper.openapi.json`、`exam.openapi.json` 为唯一契约实现浏览器内存
Mock；默认启用 Mock，后端接口可用时统一设置 `VITE_USE_API_MOCK=false`，调用同一 API 模块中的真实请求分支。Mock
不是接口验收证据，真实联调仍保留在最终验收。

原有题库、试卷和考试列表页已形成最小请求边界，但其以弹窗为主，无法承载题目编辑、试卷组卷、考试编排和学员作答的完整工作流。本
Change 将这些复杂操作调整为独立页面，并以附件所示的答题卡、计时、结果和解析信息层级作为双端考试体验参考。

## 目标

1. 管理员维护知识点、题库、题目与不可变题目版本。
2. 管理员在独立组卷页建立、预览和发布固定、随机或自定义试卷版本。
3. 管理员在独立详情与人员配置页维护考试、考生和批阅人；编辑既有考试时不得更换 `paperVersionId`。
4. 学员在 PC 与移动端的独立考试页开始作答、暂存、交卷并查看已发布成绩与解析。
5. 教师批阅主观题；管理员发布成绩、安排补考或重置练习，并回接课程考试类内容项。
6. 所有上述 API 模块以契约一致的 Mock 支撑开发，并可通过单一环境变量切换为真实请求。

## 用户价值

管理员获得可连续完成的建题、组卷、编排流程；学员获得适配设备的答题、答题卡和结果体验；后端接口就绪后可切换真实请求，无须替换页面业务逻辑。

## 功能范围

- PC 管理端：题库、题目编辑/版本、试卷创建/组卷/版本、考试创建/详情/考生与批阅人配置。
- 学员 PC：考试任务、专注作答、答题卡、交卷结果与解析页。
- 移动端：考试任务、作答与结果页，使用 uni-app 路由和触控布局。
- 题库、试卷、考试及学员端 API 的 Contract Mock、开关测试与真实请求分支保留。
- 为每个 Task 添加先失败的前端自动化测试；真实环境可用后执行真实请求验收。

## 非目标范围

- 后端、数据库、权限模型或既有 OpenAPI Contract 变更。
- M1 Task 4 的真实接口联调、Mock 清理或验收记录。
- 真实媒体转码、媒体播放、仿真、人脸识别和强制客户端防作弊。
- 培训计划、问卷、档案、证书、统计或监管预警功能。
- 在后端真实联调通过前删除 M2 Mock；Mock 仅限开发期浏览器/移动端会话内数据。

## 人工确认关卡

- 已确认（2026-07-27）：M2 按现有 OpenAPI 开始 TDD；编辑既有考试时不允许更换试卷版本。
- 已确认（2026-07-28）：Mock 优先策略、独立详情页路由清单与重开的 M2 Task 1～3；后续已按 Task 顺序实施。
