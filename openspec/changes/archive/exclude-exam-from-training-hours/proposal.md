# Proposal：考试与题库退出培训学时

## Why

当前考试/题库在阶段内容上仍填 `requiredHours`，发布时计入总学时和线上占比，学员获得学时却固定为 0。课表和档案对不上，功能项
2、5、33、34 也没有要求考试占学时。需要让考试/题库退出学时体系，阶段不再填写。

## What Changes

- 模板和计划阶段内容中，`EXAM` / `QUESTION_BANK` **不得填写正数学时**；省略、`null` 或 `0` 均可，落库为 `0`。
- **BREAKING（请求语义）**：这两类内容提交 `requiredHours > 0` 时拒绝保存，业务码 `8165`。
- **BREAKING（发布/预警合计）**：总学时只加课程 + 线下；线上学时只加课程。考试/题库不进总学时、不进线上占比。
- 学员获得学时口径不变：考试/题库仍为 0；课程仍按正式学习秒；线下合格仍按该项安排学时。
- 监管 `PLAN_TOTAL_HOURS` / `PLAN_ONLINE_RATIO` 与发布使用同一套合计，避免预警再把考试学时灌进计划学时。
- 契约与架构说明同步；无 DDL。已发布计划结构不改写，预警按新公式重算。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `training-execution-loop`：安排学时只来自课程和线下；考试/题库不填、不计、不发给学员。

## Impact

- 后端：模板/计划阶段保存、apply-template、发布预检、监管学时预警合计。
- API：`docs/api/training.openapi.json`；必要时同步 `docs/api/regulation.openapi.json` 合计说明。新错误码 `8165`。
- 数据：无表结构变更；考试/题库学时列保留，新写为 0。
- 兼容：靠考试学时才凑满类型尺子的草稿将无法发布，须把学时加回课程或线下。已发布计划若曾用考试灌总学时，预警可能变为不足。
- 仅后端；前端以 OpenAPI 为准另开。

## 本次覆盖的功能项

| 序号 | 原文语义             | 本次边界                       |
|----|------------------|----------------------------|
| 2  | 计划与类型学时对比，不够则预警  | 计划学时 = 课程 + 线下安排学时，不含考试/题库 |
| 5  | 类型初培/复审学时、线上最高占比 | 线上占比 = 课程 / (课程 + 线下)      |
| 33 | 阶段可加理论考试/题库作培训考核 | 考试/题库仍可编排，但不占学时            |
| 34 | 计划设置线上/线下内容      | 学时只填在课程和线下内容上              |

## 目标

1. 考试/题库阶段内容不用填学时，正数被拒绝，读写统一为 0。
2. 发布总学时和线上占比与学员学时账使用同一批计入学时的内容（课程 + 线下）。
3. 考试仍是必修关卡，完成规则不改为发学时。

## 非目标

- 不把考试合格改为发放安排学时。
- 不改课程获得学时（仍用正式学习秒）和线下合格发放安排学时。
- 不删除 `requiredHours` 列，不迁移改写已发布内容行。
- 不改个人结业门禁（仍看必修正式完成，不用个人获得学时套 TOTAL_HOURS）。
- 不实施前端页面、Mock、联调或 UI。

## 前后端影响

仅后端；前端以 OpenAPI 为准另开。

## 人工确认关卡

本 Change 修改 API 学时语义和发布/预警公式，属于 L4。确认 Proposal、Design、Tasks 和 Spec 后才允许实施。确认即接受：考试/题库不再用于凑总学时或线上占比。
