# 设计：隔离浏览器标签页登录会话

## 设计结论

将 PC Web 当前登录令牌的持久化介质由 `localStorage` 改为 `sessionStorage`。`sessionStorage` 按同源下的顶层浏览器浏览上下文隔离：同一标签页刷新仍可读取令牌，不同标签页/窗口不会共享令牌。

Pinia 的用户状态继续在每个页面上下文中独立创建，并继续从该上下文的 `sessionStorage` 初始化。请求拦截器不改动，仍从当前 `useUserStore` 读取令牌并添加 `Authorization: Bearer {token}`。

## 会话行为

| 场景 | 期望行为 |
| --- | --- |
| 标签页 A 登录账户 A | A 只保存于标签页 A |
| 标签页 B 登录账户 B | B 只保存于标签页 B，不覆盖 A |
| 刷新标签页 A | 恢复账户 A |
| 标签页 A 退出登录 | A 失效，标签页 B 仍保持账户 B |
| 标签页 A 登录新账户 C | 仅替换 A 的会话，B 不变 |
| 新标签页打开同一地址 | 不继承其他标签页的会话，需独立登录 |

## API、权限与数据影响

- API：无变化，继续调用 `/api/auth/login`、`/api/auth/logout` 和当前用户资料接口。
- 权限：无变化；每个标签页仅使用自己保存的 Token 获取服务端权限结果。
- 数据库：无变化。
- 后端：无变化。

## 风险与取舍

- `sessionStorage` 通常不会在新标签页之间共享，满足并行账户场景；代价是关闭标签页后会话不再保留，这是本需求下的安全取舍。
- 浏览器“复制标签页”可能复制初始 `sessionStorage` 状态；若复制时已有登录状态，复制出来的标签页可能先继承该状态。验收重点是独立打开的标签页/窗口及登录后互不覆盖；如需禁止复制标签继承，需要另行设计一次性会话迁移机制。
- 不使用 `localStorage` 的跨标签同步事件，因为该需求要求会话互不影响。

## 测试设计

- 单元/行为测试验证令牌读写使用当前标签页存储，不访问共享 `localStorage`。
- 行为测试验证两个独立存储上下文可分别保存账户 A/B，互不覆盖。
- 行为测试验证刷新恢复和单上下文登出隔离。
- 运行 PC Web 定向测试、typecheck、lint 和 build。
