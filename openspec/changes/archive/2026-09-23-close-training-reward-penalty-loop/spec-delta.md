# 培训奖惩闭环增量规格

## 计划执行中的奖惩记录

- 系统 MUST 允许有权限的管理员仅在 `RUNNING` 培训计划内为该计划参训人创建、修改和删除奖励/处罚记录，并可关联当前机构可访问的佐证文件。
- 系统 MUST 拒绝不存在、跨计划、跨机构的计划、参训人、记录或佐证文件；`DRAFT`、`PUBLISHED`、`ENDED`、`CANCELLED` 计划的奖惩写入 MUST 被服务端拒绝。
- 更新 MUST 使用记录当前 `version`；版本冲突不得覆盖既有记录。

### Scenario：记录奖惩并刷新综合分

- **GIVEN** 一个执行中计划、一名本计划参训人和已绑定的综合评价版本
- **WHEN** 管理员创建一条启用的奖励或处罚记录
- **THEN** 计划奖惩列表能回读该记录，参训人的当前综合分按既有规则自动刷新
- **AND** 培训结束后的成果页、三级档案可追溯同一记录，页面不自行计算分数

### Scenario：冻结后或归属错误的写入

- **GIVEN** 计划已结束，或请求的参训人、奖惩记录、文件不属于本计划/机构
- **WHEN** 调用奖惩创建、修改或删除接口
- **THEN** 服务端拒绝且不改写奖惩、综合分或最终结果

## 最小操作界面

- 培训计划工作台 MUST 在「过程与结果」展示奖惩记录，并在状态及权限允许时提供新增、编辑、删除操作。
- 表单 MUST 从本计划参训人选择，不得手输全局主键；可选佐证 MUST 经统一上传组件获得文件 ID。
- 已结束计划 MUST 只读展示；成果页和档案 MUST 使用服务端返回的正式事实。
- 奖惩说明和发生日期 MUST 保持可选；创建时可省略，编辑时可清空，数据库不得以非空约束拒绝这两种合法输入。
- 奖惩列表和新增、编辑弹窗 MUST 能预览已有或本次上传的佐证；已保存佐证 MUST 经奖惩记录受控读取，记录、文件不存在或不可见时不得返回文件内容。
