# Proposal：修整开课配置与课程测验阅卷流程

## 背景

草稿开课包含带主观题的课程测验时，管理员在发布前必须配置阅卷人。但当前考核管理面板会在草稿阶段读取尚未生成的批阅任务和结果，分别触发
`7062` 与 `PageRequest<Void>` 的反射异常；新增开课也未提示或承接这一前置步骤。

## 目标

1. 草稿开课的考核管理只提供可执行的阅卷人配置，不调用依赖执行对象的批阅任务和结果接口。
2. 修复课程考核结果接口的 `PageRequest<Void>` 参数解析异常。
3. 将“课程测验需要阅卷人”的检查和配置纳入新增/编辑开课流程，并在发布前给出明确指引。
4. 重做考核管理抽屉与开课编辑弹窗，使信息层级、操作顺序和两栏表单布局清晰一致。

## 范围

- PC 管理端开课配置、考核管理与相关课程测验接口调用。
- 后端课程考核结果分页接口的参数类型修复及回归测试。

## 非目标

- 不改变课程测验“有主观题必须配置阅卷人”的后端规则。
- 不新增权限、数据库结构或 OpenAPI 路径/字段。
- 不修改学员端课程学习、独立考试或成绩生效规则。
