# Design：开课配置与课程测验阅卷流程

## 流程设计

```text
新增开课（草稿）
  → 识别课程中的课程测验
  → 有主观题：在弹窗内配置阅卷人并保存
  → 发布开课
  → 已发布后展示批阅任务与自动生效结果
```

- 草稿阶段只请求阅卷人接口；批阅任务和结果只在已发布开课读取，避免调用前置条件不成立的接口。
- 对每一项含主观题的测验，发布操作均独立校验是否至少配置一名阅卷人；任一项缺失均不得发布，并显示后端业务消息。纯客观题保持无需阅卷人的既有规则。
- 新增开课先保存草稿，再在同一弹窗内完成课程测验阅卷人配置；用户确认发布时统一执行发布。编辑草稿使用相同流程。
- 结果分页接口使用显式空查询 DTO，避免 `PageRequest<Void>` 被参数解析器实例化。
- 课程题库练习和课程测验必须在课程报名、内容项和作答三元路径内暂存、提交和读取；不得跳转到独立考试的 `/portal/exams`
  作答页。课程专用答题页仅支持学员手动交卷，避免独立考试倒计时错误提交课程作答。
- 课程任务接口对学员仅暴露 `NOT_STARTED`、`IN_PROGRESS`、`WAITING_RESULT`、`RESULT_EFFECTIVE`；待批阅的底层状态统一收敛为 `WAITING_RESULT` 并保留已提交作答 ID。课程测验存在终态作答时必须复用，不得创建第二份答卷。
- 课程结果自动生效后，答案、标准答案和解析直接可见，不适用独立考试的人工发布与答案详情策略；作答页在提交或返回前先暂存本次未保存修改。

## UI 设计

- 新增/编辑开课使用居中 `ElDialog`，表单常规字段按左右两栏 `ElRow/ElCol` 排列。
- 弹窗内设置“基本信息”“课程测验”两个区块；课程测验区仅显示 QUIZ 内容项，并标记是否需要阅卷人。
- 考核管理按章节平铺全部课程测验卡片：每张卡片显示章节、测验名称、已配置阅卷人姓名与配置操作；草稿显示配置提示，已发布再在对应卡片下显示待批阅与自动生效结果。

## 权限与契约

- 沿用 `course:offering:list` 查看、`course:offering:edit` 配置阅卷人、`course:offering:publish` 发布、`exam:review` 批阅和
  `course:learning:view` 查看结果。
- 沿用现有课程 OpenAPI 接口；仅修复实现和页面调用时机。
