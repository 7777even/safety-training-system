# Design：课程管理端工作流优化

## 页面结构

课程中心路由同时承载列表和详情状态。列表无查询参数；新增使用 `mode=create&stage=basic`；编辑使用 `courseId` 和 `stage`。详情工作台包含 `basic`、`content`、`publish`、`offering` 四个阶段，首次保存基础信息取得 `courseId` 后才允许进入后三个阶段。

课程业务页面统一位于 `frontend/pc-web/src/views/admin/business-center/class/`。课程详情、阶段面板和素材选择器为内部组件，不要求菜单配置。素材库继续位于 `business-center/resource-library`；统一上传组件位于 PC Web 全局 `components/file-upload`。

## 交互设计

- 基础信息采用分阶段显式保存，支持“保存”和“保存并下一步”。
- 内容编排采用章节导航、内容列表、当前项编辑面板三栏布局；章节和内容配置不再打开业务弹窗。
- 素材选择器是课程工作台唯一业务选择弹窗，支持单选和多选，并在弹窗内展示预览。
- 发布版本在页面内展示状态、说明、历史和只读快照；发布、下线等危险操作继续二次确认。
- 开课配置在当前课程阶段内按 `query.courseId` 查询，并在页面内编辑；独立开课管理页继续提供跨课程管理。
- 素材库使用右侧抽屉编辑。上传时抽屉内容切换为上传面板，完成后返回素材表单，不叠加弹窗。

## 组件接口

`AssetPickerDialog` 接收显示状态、选择模式、已选 ID 和允许类型；确认时返回完整素材对象。`UnifiedFileUpload` 支持 `dialog` 和 `panel` 两种模式，由调用方注入上传函数并返回文件信息，不硬编码素材 API。

文件预览只使用本地 Object URL、本次上传响应中的 `fileUrl`、外部链接或富文本内容。刷新后无法通过现有 Contract 恢复 URL 时显示能力降级提示，不扩展 `AssetDetail` 字段。

## API、权限与状态

- 继续使用 `asset.openapi.json`、`course.openapi.json` 和系统文件上传 Contract。
- 所有带 `version` 的更新保持乐观锁语义，2040 冲突不覆盖用户数据。
- 页面和按钮只按现有权限点控制展示；真实鉴权仍由后端负责。
- 素材选择查询固定使用启用、`SUCCEEDED` 素材，不创造素材分类接口。
- Mock 与真实请求保持相同的页面调用接口。

## 风险和取舍

- 当前动态路由不会注册不可见菜单，因此课程详情使用课程中心同一路由的查询参数，而不是新增隐藏路由。
- 浏览器不能预览 Office、压缩包等格式时只展示文件信息。
- 发布前检查是基于已加载数据的提示，最终发布合法性以后端响应为准。
- 当前工作区已有系统菜单相关未提交改动，实施仅修改课程、素材、通用上传、测试和本 Change 文档。
