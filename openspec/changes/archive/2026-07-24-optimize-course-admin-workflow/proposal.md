# Proposal：优化课程管理端工作流

## 背景

当前课程中心通过多层弹窗承载课程基础信息、内容编排、版本发布和开课配置；内容编排内部又继续打开章节、内容、材料规则、直播和下载资料弹窗。连续操作时上下文容易丢失，也不利于刷新、返回和恢复当前工作阶段。

## 目标

- 将课程新增、编辑、内容编排、版本发布和开课配置收敛为四阶段全页工作台。
- 将章节、内容项、材料规则、直播和开课表单改为页面内编辑。
- 提供独立素材选择器和统一文件上传组件，并避免抽屉与上传弹窗叠加。
- 保持现有课程、素材 API Contract、权限语义、状态机和 Mock 切换方式不变。

## 用户价值

课程管理员可以沿着“基础信息 → 内容编排 → 发布版本 → 创建开课”的连续路径完成课程制作，减少重复关闭弹窗、重新定位课程和丢失编辑上下文的成本。

## 功能范围

- PC 管理端课程中心和课程详情工作台。
- 课程章节、内容项、材料规则、直播、下载资料、版本和开课配置。
- 素材选择器、素材预览和统一文件上传组件。
- 素材库新增/编辑抽屉及抽屉内上传面板。
- 菜单组件迁移至 `business-center/class`。

## 非目标范围

- 不新增或修改后端 API、权限点、数据库结构和业务状态机。
- 不实现根据 `fileInfoId` 重新读取历史文件 URL 的非契约接口。
- 不实现学员端课程发现、学习或评价页面。
- 不回接考试、练习、题库和仿真内容项。
