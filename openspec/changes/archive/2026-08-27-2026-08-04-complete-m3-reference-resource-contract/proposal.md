# Proposal：补齐 M3 当前机构可引用资源 Contract

## 背景

M3 培训模板和培训计划已经能够保存课程、考试和题库资源
ID，并在发布后生成执行关联，但管理端缺少一个统一的服务端候选资源查询。前端若分别调用课程、考试和题库列表再本地筛选，无法稳定保证分页、发布状态和机构隔离，培训内容编排因此不能形成真实接口闭环。

本系统的资源边界收敛为严格机构隔离：课程、考试和题库归属于各自的 `organization_id`，只能由同一机构使用和引用。本 Change
不引入资源共享、跨机构授权或父子机构资源继承。

## 目标

1. 提供当前登录机构可引用的课程、考试和题库统一分页查询。
2. 培训模板、培训计划在保存和发布时校验资源与业务聚合属于同一机构。
3. 复用各资源既有稳定事实：课程使用发布版本，考试使用已绑定试卷版本，题库练习在开考时由既有考试链冻结题目快照。
4. 以完整 OpenAPI、零 DB 测试和 MySQL IT 形成 M3 后端真实闭环证据。

## 用户价值

- 培训管理员可以在模板和计划编排中准确选择本机构可用资源。
- 机构之间的课程、考试和题库数据保持严格隔离，不会因前端传参或本地筛选泄露。
- 培训计划发布时能够识别资源停用、未发布、不可执行或机构不一致等问题。
- 已发布计划保留稳定资源版本，后续审计和执行结果可追溯。

## 功能范围

1. 新增当前登录机构可引用 `COURSE`、`EXAM`、`QUESTION_BANK` 的统一分页查询。
2. 明确三类资源的已发布、启用、可执行条件及既有引用标识。
3. 培训模板和计划写入时校验资源与模板/计划属于同一机构。
4. 培训计划发布时重新校验资源状态和机构归属，并冻结稳定版本信息。
5. 同步 `docs/api/training.openapi.json`、后端实现及分层自动化测试。

## 非目标范围

- 不修改任何前端页面、Mock、联调代码或 UI；前端以 OpenAPI 为准另开。
- 不实施 M2.1 的题目版本历史、批阅历史、学员考试记录或考生 Excel 导入。
- 不实施开课多 purpose 参与范围、LINK 准入或外部人员身份策略。
- 不重复实现机构主数据更新、启停和引用保护；继续由 `2026-07-27-implement-organization-master-data` 负责。
- 不提供机构删除接口。
- 不设计资源共享、跨机构授权、授权等级或父子/监管机构资源继承。
- 不读取或扩展 `sts_common_resource_org_grant`；既有授权能力的清理如有需要另开 Change。
- 不在本 Change 修复 `asset.openapi.json`、`course.openapi.json` 的既有悬空 `$ref`；按独立小修处理。
- 不提供联调环境、账号和种子数据；该项属于后续端到端验收准备。

## 已确认决策

1. 资源按照机构严格隔离，资源所属机构与培训模板/计划所属机构必须一致。
2. 当前机构由服务端根据登录身份派生，不接受可改变资源边界的客户端机构参数。
3. 本 Change 不引入共享和授权语义。
4. 取消共享或授权、机构层级和监管关系均不参与可引用资源计算。
5. QUESTION_BANK 不新增不可变版本表；培训内容保存 `questionBankId`，具体作答沿用考试链的开考快照。
