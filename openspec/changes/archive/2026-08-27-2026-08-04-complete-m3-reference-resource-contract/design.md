# Design：M3 当前机构可引用资源 Contract

## 1. 总体约束

- API Contract 唯一机器可读来源为 `docs/api/training.openapi.json`；新增或变更 operation 必须提供 Controller
  tag、中文字段说明、参数与成功响应 example、错误响应和 `x-permission`。
- 当前用户和当前机构由服务端可信登录上下文派生；接口不得接受能够切换资源归属边界的 `organizationId`。
- 课程、考试、题库和培训模板/计划均以各自 `organization_id` 表示所属机构。
- 资源只允许同机构引用；父子机构、监管关系以及 `sts_common_resource_org_grant` 均不扩大可引用范围。
- 前端 Mock、本地分页筛选和逐条资源校验不得作为验收证据。

## 2. 当前机构解析

沿用现有登录身份和有效机构成员关系解析当前用户的主机构。无有效主机构时拒绝查询和培训内容写入，不允许调用方通过请求参数补充或覆盖机构。

如实现阶段发现登录上下文无法唯一确定主机构，必须暂停并由人工确认身份模型，不得自行增加机构切换语义。

## 3. 可引用资源查询

新增 `GET /api/training/reference-resources` 分页查询，供培训模板和培训计划内容编排使用。

### 3.1 查询条件

- `resourceType`：必填，仅允许 `COURSE`、`EXAM`、`QUESTION_BANK`。
- `keyword`：可选，按资源编码或名称模糊查询。
- 分页参数沿用项目统一 `PageRequest` 约定。
- 固定使用服务端派生的当前机构，不提供 `organizationId` 查询参数。
- 使用稳定排序：按资源更新时间倒序、资源 ID 倒序；OpenAPI 必须明确该规则。

### 3.2 机构隔离

三类资源均必须满足：

```text
resource.organization_id = currentOrganizationId
```

即使其他机构存在父子关系、监管关系或历史资源授权记录，也不得出现在结果、分页总数或任何候选字段中。

### 3.3 资源状态与引用标识

| 资源类型            | 可引用条件              | 引用与冻结方式                             |
|-----------------|--------------------|-------------------------------------|
| `COURSE`        | 课程启用且存在已发布课程版本     | `courseVersionId`                   |
| `EXAM`          | 考试启用、已发布且满足既有可执行条件 | `examId` 与既有 `paperVersionId`       |
| `QUESTION_BANK` | 题库启用且处于 ACTIVE 状态  | 保存 `questionBankId`；开考时由既有考试链冻结题目快照 |

本 Change 不为 QUESTION_BANK 新增版本表，也不在培训域创建第二套考试或题库版本模型。题库内容后续变化不得改写已经由考试作答链冻结的尝试快照。

### 3.4 响应字段

响应至少包含：

- 资源类型、资源 ID；
- 资源编码、名称；
- 所属机构 ID、名称；
- 发布和启用状态；
- 可执行状态；
- 既有引用标识；COURSE/EXAM 同时返回对应版本标识，QUESTION_BANK 的版本标识为空。

不返回授权来源、授权等级、授权期限或共享状态。

## 4. 写入与发布校验

### 4.1 模板和计划写入

培训模板内容和培训计划内容保存时，服务端必须：

1. 根据内容类型读取真实资源；
2. 校验资源存在且未删除；
3. 校验资源 `organization_id` 与模板或计划 `organization_id` 相同；
4. 校验资源处于允许保存到草稿的状态；
5. 拒绝跨机构资源 ID，不能依赖前端候选列表保证安全。

### 4.2 计划发布

发布事务内必须重新读取并校验：

- 资源仍属于计划机构；
- 资源仍启用、已发布且可执行；
- 冻结的资源版本仍存在且符合既有领域规则。

校验通过后，把稳定资源版本信息写入既有计划快照或执行关联事实。查询接口不是发布校验的替代。

## 5. 权限与错误边界

- 查询权限复用或新增明确的培训模板/计划资源选择权限，最终权限码必须在 OpenAPI 与 Controller 中一致。
- 跨机构资源统一按不可引用处理；响应不得泄露目标资源名称、所属机构或存在性。
- 未发布、停用、不可执行和版本失效应使用明确、稳定的业务错误码。
- 并发发布继续沿用培训计划现有 `version` 乐观锁，冲突返回 HTTP 409。

## 6. OpenAPI 交付

仅修改 `docs/api/training.openapi.json`：

- 新增当前机构可引用资源分页 operation；
- 补充查询参数、分页响应、资源联合字段、权限和错误响应；
- 如模板/计划现有写入 Contract 未明确同机构规则，同步补充说明和错误码；
- 保证 Controller、DTO/VO 与 OpenAPI 对齐。

## 7. 验证

每个新增或修改行为按 TDD 先观察失败：

- 零 DB：当前机构派生、参数校验、三类资源状态判断、同机构写入护栏、发布时复核、跨机构不泄露。
- MySQL IT：三类资源真实分页、稳定排序、机构隔离、发布状态过滤、资源版本读取、跨机构资源不计入总数、发布快照可追溯。
- 契约：OpenAPI JSON、`$ref`、Controller-operation、Schema-DTO/VO 对齐。
- 最终执行 `openspec validate --strict` 与双轴 Review。
