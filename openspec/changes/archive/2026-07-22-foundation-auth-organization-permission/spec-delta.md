# Spec Delta：认证、组织与权限前端基础能力

## ADDED

### 本地登录与会话

PC Web 和移动 H5 必须支持 `identityType=local` 的账号密码登录。前端必须按 `/api/auth/login` Contract 将密码作为 SHA-256
64 位摘要提交；成功后必须使用返回 token 调用当前用户资料接口，并在受保护请求中传递 `Authorization: Bearer {token}`。

退出登录必须调用 `/api/auth/logout` 并清除本地会话。前端路由守卫和入口隐藏只改善体验，真实认证与授权必须始终由后端负责。

### PC 门户与后台访问

PC 门户必须使用顶部导航和居中内容布局，显示与当前用户相关的静态学习概览和可见快捷入口。拥有后端返回管理权限的用户可以看到管理后台入口；未获授权的用户不得看到该入口，且访问后台路由时必须回到门户或登录页。

管理后台必须使用 240px 左侧导航、顶部工具栏和自适应工作区。后台一级菜单必须包括：

- 首页概览；
- 课程分类；
- 资源管理；
- 课程学习；
- 考试中心；
- 系统设置。

课程分类、资源管理、课程学习和考试中心在本 Change 中仅建立导航和占位页，不得实现或模拟其业务功能。

### 系统设置管理

系统设置必须包含用户管理、角色管理、菜单管理、组织管理和字典管理五个子页面，并且只调用 `docs/api/system-admin.openapi.json`
已定义的系统管理接口。

- 用户管理必须支持分页筛选、新增、编辑、删除和重置密码，并从部门树和角色列表选择关联信息。
- 角色管理必须支持分页筛选、新增、详情、编辑、删除和菜单树授权；角色菜单授权只能使用 Contract 定义的 `menuIds`。
- 菜单管理必须支持菜单树查询、新增、编辑、删除以及单项或批量可见性调整。
- 组织管理必须支持部门树查询、新增、编辑和删除。
- 字典管理必须支持字典类型和字典数据的分页筛选、新增、编辑、删除、目录读取和按类型读取。

所有列表分页、筛选、写入字段、版本号和错误处理必须遵守 OpenAPI Contract；前端不得自行增加字段、错误码或权限语义。

### 数据范围边界

本 Change 建立数据范围的前端消费边界：前端只根据后端返回的菜单和权限数据控制入口显示，后端负责真实数据范围与资源访问校验。当前
API Contract 未定义角色数据范围的读取或保存字段，因此不得提供数据范围配置表单、伪造请求字段或以路由守卫代替后端校验。

### PC 菜单动态路由与按钮权限

PC Web 必须以 `/api/system/users/profile` 的 `menus` 作为门户、后台和系统设置的唯一路由与权限来源。除 `/login`
外，前端不得维护静态业务路由、路径常量或菜单路径映射；登录成功、会话恢复和用户切换后，必须按可见 `menus` 注册路由，并打开第一个可解析菜单页面。

非按钮菜单的 `path` 必须直接作为路由路径，`menuName` 作为路由标题，`sortOrder` 作为导航顺序。顶层无子菜单页面按
`src/views/<component>.vue` 解析，组件不存在或为空时回退至 `src/views/<path>/index.vue`。每个顶层 `/admin` 菜单均使用统一
`AdminLayout`，并作为后台左侧一级菜单展示；后代页面支持 `admin/system/...` 完整组件路径或 `system/...` 相对组件路径，二者均按
`src/views/admin/system/...` 目录约定解析，空组件目录节点用 `RouterView` 承载子路由。无法解析的叶子菜单与 `F`
功能按钮节点不得注册页面路由。门户导航仅显示 profile 中已授权的非 `/admin` 顶层菜单。当前接口错误返回 `/dashboard`
时，前端必须临时注册实际门户路径 `/portal`；后端菜单修正为 `/portal` 后不得保留额外分支。路由 `meta` 必须由前端从既有菜单字段生成，当前
Contract 不要求后端新增 `meta`。用户、角色、菜单、组织和字典管理页必须仅根据可见 `F` 节点的 `perms`
显示操作按钮。用户切换或退出后再次登录时，前端必须移除上一用户的动态路由，避免遗留入口；前端控制只改善体验，后端继续承担真实鉴权。

后台顶栏必须只展示路径属于 `/admin` 的顶层 `D` 模块；当前模块的 `M` 目录和 `C` 页面才显示在左侧导航。没有可解析 `M` 或 `C`
后代的模块必须作为独立页面展示，且不显示左侧导航；有可解析后代的模块点击或直接访问模块根 URL 时必须打开其按 `sortOrder`
排列的首个页面叶子节点。所有模块及其叶子页面直接访问时都必须保留 `AdminLayout`
；当前模块识别必须使用最长的菜单路径边界匹配，避免祖先路径覆盖子模块。前端不得依赖模块名称判断布局，也不得为业务中心等模块硬编码菜单路径或组件映射。

### 视觉与移动端边界

PC 登录、门户和后台页面必须遵守 `docs/design/` 的深海蓝设计系统。附件可用于参考布局和信息层级，但不得继承其红色品牌视觉。移动端必须使用独立的触控登录布局，不得复制
PC 后台结构；原生 App、企业微信与微信登录具体实现均为暂定，不能提前实现。
