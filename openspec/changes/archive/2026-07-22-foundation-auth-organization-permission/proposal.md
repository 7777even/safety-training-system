# Proposal：认证、组织与权限前端基础能力

## 背景

PC Web 与移动端目前仅具备前端工程壳层，尚不能通过既有系统管理 API 完成登录、会话初始化、后台访问控制和系统设置维护。系统管理
API 已提供用户、角色、菜单、部门和字典的管理能力，需要以该契约为唯一依据建设前端基础能力。

## 目标

- 建立 PC Web 与移动 H5 的本地账号登录和基础会话能力。
- 建立 PC 门户静态首页、管理后台框架及后台访问控制体验。
- 在“系统设置”下完成用户、角色、菜单、组织和字典管理页面。
- 配置后台一级菜单“首页概览、课程分类、资源管理、课程学习、考试中心”，并让系统设置承载本 Change 的五项管理页面。

## 用户价值

用户能够登录并进入与自身权限匹配的门户或管理后台；管理员能够通过已确认的 API 维护账号、角色、菜单、组织和字典，从而为后续业务模块提供稳定的身份与权限基础。

## 范围

- 调用 `/api/auth/login`、`/api/system/users/profile`、`/api/auth/logout` 完成登录、会话初始化和退出登录。
- PC 登录页、门户首页静态排版和管理后台框架遵循 `docs/design/` 的深海蓝设计系统，并参考附件的信息结构，不复用其红色品牌视觉。
- PC 后台的“系统设置”包含用户管理、角色管理、菜单管理、组织管理、字典管理；每个页面只使用
  `docs/api/system-admin.openapi.json` 已定义接口。
- 角色管理使用已定义的 `menuIds` 维护角色菜单授权；前端根据用户资料的 `perms`、`menus` 控制入口显示，后端仍负责真实授权。
- 移动端仅实现适配触控的登录与会话初始化基础；原生 App、企业微信登录细节保留为暂定。

## 非目标

- 不实现课程、考试、培训、证书、统计、仿真或人脸识别业务功能、数据接口或页面内容。
- 不实现微信登录。
- 不修改后端代码、数据库结构、迁移或 API Contract。
- 不自行定义角色数据范围的配置字段、接口或权限语义；当前契约未提供该能力，数据范围由后端授权规则承载。
- 不为尚未实现的一级菜单接入课程或考试业务页面；只配置可见的导航入口与占位提示。
