# Proposal：统一考核执行快照与完整性校验

> 状态：已确认并完成实施（2026-09-15）。

## 背景

课程题库练习和课程测验生成 `AssessmentExecution` 时，当前实现把规则序列化到 MySQL `JSON`
列，却按写入前的 JSON 原始文本计算 SHA-256。MySQL 写入后会规范化对象键顺序、空白和数字表达，课程分支读取后仍按原始文本重算，导致未被篡改的执行对象也可能返回
`7063「考核执行快照已损坏」`。

培训分支已经引入部分规范化逻辑，但课程、独立考试和培训仍存在不同 hash 路径；执行快照事实同时散落在多个普通列和
`policy_snapshot_json` 中，缺少一个版本化、唯一权威的快照边界。

## 功能项依据

| 功能项   | 原文核心语义                    | 本 Change 的对齐方式          |
|-------|---------------------------|-------------------------|
| 14    | 管理员通过题库创建专项训练和题库练习，学员完成练习 | 确保题库练习从完整且可校验的冻结执行启动    |
| 15    | 试卷按规则组卷并发布不可变版本           | 执行快照稳定引用不可变试卷版本及其冻结规则   |
| 16    | 独立考试设置人员、阅卷人、时间、时长和次数     | 独立考试执行使用同一版本化快照边界冻结执行规则 |
| 22    | 课程章节可直接添加理论题库和理论试卷测验      | 课程题库和课程测验均可从有效冻结快照正常开考  |
| 48～49 | 课程学习与独立练习、在线考试入口分离        | 保持入口和来源隔离，仅统一底层快照机制     |

## 目标

1. 使用单一、完整、版本化的 `snapshot_json` 作为所有 `AssessmentExecution` 冻结事实的唯一权威来源。
2. 使用同一套与 MySQL JSON 物理文本无关的规范化算法计算和校验 SHA-256。
3. 让来源、资源和规则查询列仅承担路由、关联和索引职责，并在读取时与快照核对一致性。
4. 课程题库练习、课程测验、独立考试/练习和培训考核均通过同一 Codec 创建、读取和校验快照。
5. 修复正常课程考核因 JSON 落库规范化而误报 `7063` 的问题，并以真实 MySQL 往返测试防止回归。

## 范围

- 重构 `sts_assessment_execution` 的快照字段及完整性校验。
- 新增强类型 `AssessmentExecutionSnapshot`、统一 Codec 和规范化 SHA-256 组件。
- 调整课程、独立考试和培训执行的生成、读取、开考及相关查询逻辑。
- 同步 Admin migration、Admin-init 最终完整 SQL、`sts.init.schema-version`、Entity 和必要 Mapper。
- 保持现有 HTTP 请求和成功响应结构不变；补全 `docs/api/course.openapi.json`、`exam.openapi.json`、
  `training.openapi.json` 的 `7063` 语义。
- 仅后端；`git config user.name=lims`，前端以 OpenAPI 为准另开。

## 非目标范围

- 兼容、转换、回填或继续读取旧 `AssessmentExecution` 数据。
- 双写、双读、旧 hash 算法回退或按来源保留不同算法。
- 改变课程完成、练习计分、考试发布、培训结果或阅卷业务规则。
- 修改题库、试卷、课程版本或培训资源的发布模型。
- 新增权限、接口路径或客户端请求字段。

## 数据前提

本项目当前处于开发阶段，本 Change 明确不保留旧考核执行及其作答数据。最终 migration
只支持执行事实为空的数据库；已有执行数据的开发环境必须在部署前整体重建测试数据库，不在 migration
中静默删除或猜测转换业务事实。生产或需要保留数据的环境禁止应用本 Change，必须另行设计迁移方案并确认。

## 风险等级与确认点

本 Change 修改数据库结构、执行快照权威来源和跨课程/考试/培训的内部协议，属于 L4。实施前必须人工确认：

1. 接受不兼容旧执行数据，已有开发数据库整体重建。
2. 接受 `snapshot_json` 成为冻结事实唯一权威来源，普通列只作查询投影。
3. 接受所有来源统一使用同一规范化 hash 算法，不提供旧算法回退。
