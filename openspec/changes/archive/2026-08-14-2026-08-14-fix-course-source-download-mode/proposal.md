# Proposal：统一课程源文件下载模式

## Why

课程创建、更新、数据库字段和既有课程版本快照使用统一枚举：`NONE`、`ALL`、`PARTIAL`。后续新增学员课程附件下载能力时，
详情状态组装与实际文件下载服务错误地引入了不存在的 `ALLOW` 值，并把它作为唯一允许下载的条件。

因此，真实课程快照中的 `ALL` 和 `PARTIAL` 都会被判定为禁止下载，详情统一返回
`SOURCE_DOWNLOAD_DISABLED`，实际下载接口也返回课程不允许下载。该问题属于课程定义与学员下载链路之间的枚举契约漂移。

## What Changes

1. 课程详情与实际下载接口统一识别既有 `NONE`、`ALL`、`PARTIAL` 枚举。
2. `NONE` 禁止下载；`ALL`、`PARTIAL` 进入冻结附件归属与附件有效性校验。
3. 删除学员下载契约、测试夹具中的虚构 `ALLOW` 值，保持 OpenAPI 与课程创建/更新契约一致。
4. 对未知或空下载模式保持失败关闭，不放行附件下载。

## 用户价值

- 管理员配置“全部允许”或“部分允许”并发布后，学员能够按冻结课程附件清单正常下载有效源文件。
- 管理端配置值、课程版本快照、学员详情和实际下载接口使用同一套稳定枚举。
- 未知历史值不会意外扩大下载权限。

## 功能范围

- 修复学员课程详情中 `downloadable`、`downloadUrl`、`unavailableReason` 的课程级下载模式判断。
- 修复学员课程附件文件接口的课程级下载授权判断。
- 更新相关零 DB 测试，覆盖 `NONE`、`ALL`、`PARTIAL` 和未知值。
- 修正 `docs/api/course.openapi.json` 中学员课程响应的下载模式枚举、说明和示例。

## 非目标范围

- 仅后端；前端以 `docs/api/course.openapi.json` 为准另开，不包含页面、Mock、联调或 UI 验收。
- 不修改课程创建/更新接口已有的 `NONE`、`ALL`、`PARTIAL` 枚举。
- 不改变课程附件清单的维护方式，不在本 Change 中实现 `ALL` 自动收集课程内容项、辅助材料或其他素材。
- 不修改数据库结构、存量课程数据或课程版本快照 schema，不创建 migration。
- 不改变报名本人、报名/开课状态、冻结附件归属、素材状态、源文件和存储可用性校验。
