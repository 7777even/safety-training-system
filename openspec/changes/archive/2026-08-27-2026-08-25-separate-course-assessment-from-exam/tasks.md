# Tasks：分离课程考核与独立考试

> 状态：业务规则、设计和实施已于 2026-08-25 获得人工确认，按 Task 顺序实施。
>
> Owner / 执行身份：`lims`。仅后端；前端以 OpenAPI 为准另开。
>
> 执行顺序：Task 1 → Task 2 → Task 3；每个 Task 按 TDD、目标验证、双轴 Review 和状态更新独立闭环。

## Task 1：完成课程理论题库与测验的资源直连能力

- 状态：已完成（2026-08-25；规格符合性 Review：通过；代码质量 Review：通过）
- Owner：`lims`
- 输入：功能项 15、22；已发布题库/试卷版本；现有课程内容项及题库关联；不保留原有数据但复用职责正确资产的决策。
- 输出：课程 `QUESTION_BANK -> questionBankId`、`QUIZ -> paperVersionId` 互斥引用及版本快照；课程模型不包含
  `EXAM / PRACTICE + examId`。
- 前后端影响：仅后端；前端以 OpenAPI 为准另开。
- API 依赖：修改 `docs/api/course.openapi.json` 的内容项创建、更新、查询和发布校验契约；不修改前端调用代码。
- 数据影响：复用 `sts_course_item` 并增加课程测验试卷版本引用及索引；同步更新 init 的 `schema-course.sql` 最终完整结构并新增同版本
  Admin `V`；直接复用题库关联表；课程结构不建立考试任务引用。
- 验收标准：
  1. 管理员可在课程章节直接引用本机构可用题库或已发布试卷版本，无需先创建独立考试。
  2. 题库、试卷和其他类型引用互斥，跨机构、未发布、停用或类型错误必须被服务端拒绝。
  3. 课程版本快照可独立重放当时的资源引用和已确认规则，后续编辑不改写已开课内容。
  4. init 完整 SQL 可在空库建立最终 schema，同版本 Admin `V` 可从上一版本升级到相同结构；课程结构中不存在 `examId`
     或替代引用路径。
- 测试方式：零 DB Service/Controller TDD；课程 Item/Version/Mapper MySQL IT；最终 schema 空库建库验证；OpenAPI JSON 与
  `openspec validate --strict`。

## Task 2：完成按来源执行的课程测验、课程题库练习与独立考试

- 状态：已完成（2026-08-25；规格符合性 Review：通过；代码质量 Review：通过）
- Owner：`lims`
- 输入：Task 1 的冻结课程引用；功能项 14、16、22；现有
  Exam/Policy、Candidate/Attempt、题目快照与判分链；已确认的“冻结全部可用题目、全部至少作答一次完成一轮、无正确率门槛”规则。
- 输出：`AssessmentExecution` 执行边界；独立考试、课程测验和课程题库练习的来源隔离；试卷与题库两条作答快照链；题库练习无试卷版本可启动。
- 前后端影响：仅后端；前端以 OpenAPI 为准另开。
- API 依赖：修改 `docs/api/course.openapi.json` 的课程考核启动/详情契约；修改 `docs/api/exam.openapi.json` 的通用 Attempt
  来源摘要；独立考试入口不接受课程来源参数。
- 数据影响：复用独立考试及作答事实表；同步更新 init 的课程/考试最终完整 SQL并新增同版本 Admin `V`
  ，建立缺失的执行对象；Candidate/Attempt
  调整为以执行对象作为唯一归属并使用明确来源；按最终模型建立唯一键；题库练习的 `paper_version_id` 可空。
- 验收标准：
  1. 课程入口只从当前登录学员的有效报名、开课和版本快照派生执行，不接受客户端伪造的人员、资源或来源。
  2. 题库练习未绑定试卷版本时仍可开始、保存、交卷、判分和重放，且不再返回“考试未绑定试卷版本”。
  3. 同一试卷或题库被两个课程内容项和一个独立考试复用时，Candidate、Attempt、答案和成绩互不串联。
  4. 开考时冻结题目版本、选项、正确答案、分值和执行规则，后续资源变更不影响既有作答。
  5. 幂等令牌和并发请求不产生重复候选人或作答。
  6. 题库冻结题目全部至少作答一次并提交后完成一轮；正确率和错题可追溯，重复练习不撤销完成状态。
- 测试方式：两条执行分支先写失败测试；纯 Mockito/Controller 零 DB；执行对象、Candidate、Attempt、题目快照和唯一约束 MySQL
  IT；受影响模块编译和 OpenAPI 校验。

## Task 3：完成按来源的批阅、成绩归属与完整执行归属

- 状态：已完成（2026-08-26；规格符合性 Review：通过；代码质量 Review：通过）
- Owner：`lims`
- 输入：Task 2 的执行来源；功能项 17、22、48～49；既有批阅、成绩发布、课程进度回写和教师任务；已确认的课程阅卷人显式配置、课程成绩自动生效及完成规则。
- 输出：独立考试与课程测验的分域查询；带来源的批阅/成绩事实；课程结果幂等回写；唯一执行归属；QA / Retro 和进度证据。
- 前后端影响：仅后端；前端以 OpenAPI 为准另开。
- API 依赖：修改 `docs/api/exam.openapi.json` 的独立考试批阅/成绩来源契约；在 `docs/api/course.openapi.json`
  增加课程测验结果/批阅后端契约；所有字段、参数、example、错误码和 `x-permission` 同步。
- 数据影响：阅卷人以执行对象为唯一归属；独立考试保留发布流水，课程测验记录自动生效事实；同步更新 init 最终完整 SQL与同版本
  Admin `V`。
- 验收标准：
  1. 独立考试批阅只返回独立来源；课程测验批阅只返回指定开课和内容项来源。
  2. 聚合教师任务中每条作答明确标明来源类型、来源名称和稳定业务 ID，不能通过空字段或名称猜测。
  3. 课程成绩自动生效时只回写同一 `assessmentExecutionId + courseEnrollmentId + courseItemId`；重复事件不重复更新，不覆盖其他课程结果。
  4. 独立考试成绩仅进入该考试任务的人员、成绩与考情统计，不因共用试卷/题库而改变课程进度。
  5. 查询、批阅、发布和统计只使用 `assessmentExecutionId` 执行归属，不存在第二套归属路径。
  6. 纯客观题交卷判分后自动生效；含主观题时必须配置阅卷人并在全部批阅后自动生效，课程端不提供人工发布成绩接口。
  7. `ALL_REQUIRED_ITEMS / ALL_ITEMS` 继续决定参与课程完成计算的内容项；测验成绩生效即完成，记录合格结果但不以合格阻断课程完成。
- 测试方式：按来源权限、查询、批阅、发布和回写零 DB TDD；批阅关联、发布流水、课程进度幂等与最终 schema MySQL
  IT；三条典型后端纵向闭环验收；OpenAPI JSON、`openspec validate --strict`、QA / Retro 及双轴 Review。

## 实施暂停条件

以下任一情况发生时必须暂停：

1. 已确认的题库完成、阅卷人、成绩自动生效或课程完成规则需要变化。
2. 需要新建或改变权限模型。
3. init 最终完整 SQL 与 Admin 同版本 `V` 无法得到一致 schema。
