# Design：题目编辑与发布工作流（前端）

## Contract 边界

本 Change 只消费现有接口：

- `GET /api/question/questions`：列表仅使用 `questionCode`、`currentVersionNo`、`archiveStatus`、`status` 等主记录字段。
- `GET /api/question/questions/{questionId}`：选择题目或进入详情时读取 `currentVersion`，用于展示题干、题型、难度、规则和 `publishedStatus`。
- `POST /api/question/questions`、`PUT /api/question/questions/{questionId}`、`POST /api/question/questions/{questionId}/publish`、`PUT /api/question/questions/{questionId}/assets`：保持请求体和调用时机不变。

分页接口不保证返回 `currentVersion`，因此列表不得猜测题型或发布状态，也不得为了补齐每行内容并发加载详情。完整预览仅在用户选中具体题目时加载。

## 列表与预览

列表保留序号，显示题目编码、当前版本、归档状态和启用状态，移除题目 ID。用户点击“查看题目”或选中一行后，前端调用详情接口，在右侧预览区显示：

- 题干、题型、难度、判分方式；
- 当前版本号和发布状态；
- 草稿时的“继续编辑”入口，已发布时的“查看详情”入口；
- 详情加载失败或 `currentVersion` 为空时，显示真实错误或“当前版本数据不可用”，不伪造状态。

## 题型驱动表单

所有题型均显示：所属题库、题目编码、题型、题干、难度。解析、版本说明和题干素材为可选补充信息，采用折叠区避免干扰首次录题。

| 题型 | 显示且校验 | 不显示 |
| --- | --- | --- |
| 单选题 | 选项、至少一个正确选项；自动判分 | 标准答案文本、填空答案、关键词、答案匹配规则 |
| 多选题 | 选项、至少一个正确选项；自动判分 | 标准答案文本、填空答案、关键词、答案匹配规则 |
| 判断题 | 判断选项、一个正确选项；自动判分 | 标准答案文本、填空答案、关键词、答案匹配规则 |
| 填空题 | 填空答案；无序、大小写、全半角匹配规则 | 选项、标准答案文本、关键词、人工判分 |
| 简答题 | 判分方式；自动判分时关键词，人工判分时评分参考 | 选项、填空答案、答案匹配规则 |

切换题型时清空不适用的前端状态；提交时不发送不适用的 `options`、`blankAnswers`、`keywords` 或答案匹配开关。

## 详情与发布

详情顶部使用 `currentVersion.publishedStatus` 显示状态卡：版本号、草稿/已发布、发布时间、可编辑性和下一步操作。

- 草稿：显示“保存草稿”和“发布题目”。前端根据已加载内容提示客观题是否设置正确选项、填空题是否填写答案；最终发布结果以服务端响应为准。
- 已发布：完整信息只读，显示现有服务端语义——提交修改会创建新的草稿版本；不在前端伪造版本或发布动作。
- 详情根据题型完整展示已有字段；例如填空题展示每个填空答案及全部匹配规则，简答题展示关键词或评分参考。

## 验证

- 新增/修改前端定向测试，覆盖选中列表项的详情加载、题型字段显隐、提交净化、草稿/已发布状态和详情规则回显。
- 运行受影响 PC Web 定向测试、lint/typecheck/build。
- 使用 `VITE_USE_API_MOCK=false` 进行真实接口人工联调；服务端未返回的字段不得由前端补造。
