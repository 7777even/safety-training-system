# Proposal：优化题目新增、详情与发布工作流（前端既有 Contract 内）

## 背景

题库中心进入真实接口联调后，题目列表、录题表单和详情页的业务信息层级不清晰：列表显示低价值题目 ID；不同题型同时出现不适用字段；草稿、发布、只读和再次编辑的边界不易理解。

本次按前端协作范围执行，不改变后端接口、数据库、权限或 `docs/api/question.openapi.json`。前端仅消费现有题目分页、详情、创建、更新、发布和素材关联接口。

## 目标

1. 题目列表展示分页接口现有的关键主数据，并在选中某题时按既有详情接口展示完整题目信息。
2. 新建与编辑草稿时按题型显示适用字段，隐藏不适用字段并给出中文校验。
3. 详情页完整回显现有 Contract 已定义的版本内容和规则。
4. 用现有 `currentVersion.publishedStatus` 明确草稿、已发布、只读和再次编辑的操作边界。

## 功能范围

- PC 题库列表移除题目 ID；保留题目编码、当前版本、归档/启用状态和操作入口。
- 选择题目后调用既有 `GET /api/question/questions/{questionId}`，在右侧或详情页展示题干、题型、难度、发布状态和完整规则。
- PC 新建题目与草稿编辑页按题型展示字段、清理不适用提交数据、提供发布前提示。
- PC 详情页使用现有 `QuestionVO.currentVersion` 完整展示选项、填空答案、关键词、答案匹配规则、解析、素材、版本说明和发布信息。
- 在 `VITE_USE_API_MOCK=false` 下按既有 Contract 完成前端真实接口联调。

## 非目标范围

- 不新增、调整或删除后端 API、OpenAPI 字段、错误码、权限或数据库结构。
- 不在分页列表中逐条预加载详情接口；完整信息仅在用户选择题目时加载。
- 不新增审核、撤销发布、批量发布、版本回滚或移动端能力。
- 不把前端提示变为新的服务端发布规则；服务端响应仍是发布结果的唯一事实来源。

## 人工确认关卡

已明确为仅前端、仅使用现有 API Contract。确认后按 Task 顺序实施。
