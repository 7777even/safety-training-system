## ADDED Requirements

### Requirement: 系统用户文本输入必须可辨认

系统 MUST 在创建和更新用户时拒绝不可见 Unicode 控制、格式及异常分隔字符，MUST NOT 自动删除或替换后继续保存。

#### Scenario: 拒绝用户编码中的零宽字符

- **WHEN** 创建请求的 `userCode` 包含 `U+200B` 或其他已禁止的不可见字符
- **THEN** 系统返回 HTTP 400、业务码 1001
- **AND** 不执行用户查重、用户写入或凭证写入

#### Scenario: 拒绝用户姓名和可选资料中的不可见字符

- **WHEN** 创建或更新请求的可写字符串字段包含已禁止的不可见字符
- **THEN** 系统返回 HTTP 400、业务码 1001
- **AND** 不调用用户 Service

#### Scenario: 允许正常可见文本

- **WHEN** 用户资料包含正常中文、拉丁字母、数字、标点、Emoji、组合字符或普通半角空格
- **THEN** 不可见字符规则不拒绝请求
- **AND** 字段原有非空、邮箱、枚举及其他业务校验继续执行

### Requirement: 用户密码摘要必须符合既有契约

系统 MUST 在创建用户和重置密码时只接受 64 位小写十六进制 SHA-256 摘要，并 MUST 拒绝任何不可见字符。

#### Scenario: 拒绝混入不可见字符的密码摘要

- **WHEN** 管理员提交肉眼呈现为摘要但混入零宽或控制字符的密码字符串
- **THEN** 系统返回 HTTP 400、业务码 1001
- **AND** 不执行 BCrypt 编码或凭证写入

#### Scenario: 接受合法密码摘要

- **WHEN** 管理员提交 64 位小写十六进制密码摘要
- **THEN** 参数校验通过
- **AND** Service 继续按既有 BCrypt(SHA-256(原始密码)) 语义处理
