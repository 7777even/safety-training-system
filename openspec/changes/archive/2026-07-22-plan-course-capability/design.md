# Design：课程能力业务设计

## 设计边界

课程域按“可复用资源 → 课程内容 → 开课授权 → 学员学习 →
学习结果”组织。资源和课程是内容资产；开课是面向组织和学员的业务发布；学习记录是过程结果。课程不得直接实现考试、培训、证书或仿真业务，只通过明确的关联契约与后续领域协作。

## 领域对象

| 对象   | 职责                           | 关键关系             |
|------|------------------------------|------------------|
| 课程资源 | 文件、图文或链接等可复用内容资产，具有处理状态和归属范围 | 可被章节材料引用         |
| 课程   | 维护概况、目标、大纲与考核方式的教学单元         | 包含章节；可被授权和开课     |
| 课程章节 | 有序的目录节点和内容编排单元               | 归属课程，引用资源或后续内容类型 |
| 课程授权 | 向组织授予课程查看或编辑删除能力             | 决定组织是否可使用课程开课    |
| 开课记录 | 定义可见范围、有效时间、类型与合格方式          | 向学员产生课程任务或开放选课   |
| 学习记录 | 记录学员在章节中的有效学习、答题或成绩结果        | 汇总为管理端学习详情       |
| 直播课程 | 课程中的直播内容配置                   | 受课程可见范围控制        |

## 分阶段交付设计

1. 先确认资源存储与转码的外部边界，再实现课程资源和素材管理。
2. 在资源可用后实现课程与章节编排；课程内容类型采用可扩展的引用边界，但只启用资源和知识点，考试与仿真关联等其领域完成后再启用。
3. 以现有组织、用户、角色、菜单与数据范围基础能力为唯一身份和权限来源，实现课程授权和开课。
4. PC 与移动端通过同一 API Contract 读取课程任务、课程目录与学习状态；后端负责真实的数据范围和学习规则校验。
5. 直播仅管理课程侧配置与访问入口；直播提供方、回放、互动和可靠时长回传在确认后另立 Change 或明确纳入 Task。

## API 与数据设计原则

- 在编码前于 `docs/api/` 增加课程 OpenAPI Contract，包含资源、课程、章节、授权、开课、学习记录和直播所需接口。
- 课程域新增实体必须通过 `database/migration/` 演进；不得复用或改变系统管理表语义。
- 所有查询和写操作均以既有权限、组织数据范围和课程授权为后端校验输入。
- 转码、通知和直播等异步或外部能力的失败状态、重试策略、幂等键和观测指标须在实现前确认。

## 暂定且必须确认的决策

1. 文件格式、大小、存储、预览、转码服务、失败重试及完成通知。
2. 课程分类治理、章节无限级目录的实际限制、排序并发策略。
3. 学习时长、切屏、完成、合格、重学与知识点掌握度的判定规则。
4. 公共课程、内部课程、跨机构授权、外部链接学习和选课退选的权限边界。
5. 直播供应商、认证、回放、互动及学习时长的可信采集方式。

上述事项未确认前不得由代码自行选择默认规则。
