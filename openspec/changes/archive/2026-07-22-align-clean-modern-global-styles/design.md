# Design：统一清爽现代风全局样式

## 系统设计

以 `docs/design/clean-modern-style-baseline.md` 为唯一视觉来源，采用“Token 优先、壳层先行、页面收敛”的分层方式。

1. PC Web 在 `src/styles/variables.less` 定义语义 Token，并在全局入口覆盖 Element Plus CSS 变量。
2. 移动端在 `src/styles/variables.less` 定义等价语义 Token；仅复用颜色、字体、圆角、阴影和间距，不复用 PC 的侧栏、表格和
   Element Plus 规则。
3. 布局壳层与现有页面只消费语义 Token，逐步移除与基准冲突的局部颜色、阴影和圆角硬编码。

## Token 设计

| 类别    | 关键值                               | 使用场景            |
|-------|-----------------------------------|-----------------|
| 页面与容器 | `#F8FAFC`、`#FFFFFF`、`#F9FAFB`     | 页面背景、内容容器、弱强调区块 |
| 文字    | `#0F172A`、`#374151`、`#64748B`     | 标题、正文、辅助信息      |
| 品牌与状态 | `#2563EB`、`#1D4ED8`、`#EFF6FF`、危险红 | 主操作、悬停、选中态、错误   |
| 边框与形态 | `#E5E7EB`、6/8/12px、轻阴影            | 控件、卡片、导航与详情容器   |

Token 必须使用语义名称，不以页面、业务模块或具体组件名称命名。课程封面允许独立的内容渐变 Token，但不得被导航、表单和系统级容器引用。

## PC Web 设计

- `main.ts` 已加载全局 Less；保持该入口，不新增样式依赖。
- Element Plus 覆盖限于主题色、边框色、填充色、圆角、禁用态和常用按钮/输入框/表格/菜单状态；不改变组件 API。
- `AdminLayout`、门户与登录页使用白色容器、浅灰蓝背景、轻边框、轻阴影和统一选中导航。
- 页面标题、筛选区、数据卡片、详情编辑容器按清爽现代基准收敛；一个操作区只保留一个主操作。

## Mobile 设计

- 保持 uni-app 页面机制与现有入口；不引入 Element Plus 或 PC 侧栏布局。
- 移动端全局 Token 等价于 PC Token；页面水平留白 16px、卡片圆角 12px、主要触控控件最小高度 44px。
- 当前首页和登录页只调整视觉基底与控件状态，不改变页面信息架构或交互。

## API、权限与数据设计

本变更不新增或修改 API、权限、数据模型、Mock、数据库结构或 migration。

## 测试设计

- 运行根目录 PC Web 与移动端的 lint、typecheck、build 脚本。
- 在 PC Web 检查后台壳层、门户、至少一个列表页和一个详情编辑页；在移动端检查登录页与首页。
- 验证正文、辅助文字、卡片、阴影、按钮、表单焦点、选中导航与空状态符合 Token；同时检查窄屏下布局不溢出。

## 风险和取舍

- 全局 Element Plus 变量会影响所有已实现页面。采用语义 Token 和有限组件覆盖，避免一次性重写页面结构。
- 现有工作区包含其他未提交页面与路由改动。本变更仅修改全局样式入口、样式相关布局和当前页面的视觉属性，不覆盖无关改动。
- 暂定：首轮不新增暗色模式；设计基准仅定义浅色主题。
