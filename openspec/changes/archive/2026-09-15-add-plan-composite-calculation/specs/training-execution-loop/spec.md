## ADDED Requirements

### Requirement: PC 管理端可在计划上下文确认综合成绩

系统 MUST 允许 PC 管理端在培训计划的参训人结果视图中，使用该计划已绑定且启用的 `COMPOSITE` 表单版本创建、确认和查询该参训人的综合成绩计算批次。前端 MUST 从当前计划和当前参训人上下文派生请求参数，MUST NOT 提供计划 ID、参训人 ID 或表单版本 ID 的手工输入。前端 MUST 仅在计划为 `RUNNING` 时开放创建和确认；计划结束后仍可按权限查看历史，但 MUST NOT 创建或确认批次。

#### Scenario: 管理员确认执行中计划的综合成绩

- **GIVEN** 当前计划为 `RUNNING`，已绑定启用的 `COMPOSITE` 表单版本，当前用户拥有计算、确认和批次查看权限
- **WHEN** 管理员在某参训人的培训结果抽屉中先计算并确认最新批次
- **THEN** 前端使用当前计划 ID、该参训人 ID 和绑定表单版本调用既有评价结果接口
- **AND** 计算后刷新批次历史，确认后刷新批次历史和参训人培训结果
- **AND** 正式综合成绩展示为后端确认后的结果

#### Scenario: 无法操作时仅展示原因

- **GIVEN** 计划未绑定启用综合表单、计划不是 `RUNNING`，或者当前用户缺少对应按钮权限
- **WHEN** 管理员查看参训人培训结果
- **THEN** 前端展示中文原因
- **AND** 不展示不可执行的计算或确认按钮
