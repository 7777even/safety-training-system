# Proposal：优化教师任务详情的名单与录分提示

## 背景

教师任务详情已支持教师按场次名单录入线下培训成绩，但名单只显示用户 ID，教师无法直接识别参训人。场次尚未开始时，成绩操作栏为空，页面没有清楚说明原因；无查看或处理权限时也缺少面向教师的说明。现有“无需登记签到”提示带有系统实现语气，不利于业务人员理解。

## 目标

1. 教师任务详情的应到名单展示学员姓名，而非仅展示用户 ID。
2. 未开始场次明确告知教师：开始场次后即可录入参训人员成绩。
3. 无查看或处理权限时，明确告知教师权限限制；其他不可录分状态说明实际业务原因。
4. 将线下培训说明改为面向教师的业务文案，清晰说明教师评分是本期培训完成依据。

## 覆盖功能项

- 功能项 33「培训管理」：线下培训公示地点、培训考核成绩导入系统。此次只优化教师对既有线下场次名单和成绩录入能力的识别与提示，不恢复签到流程。

## 范围

- `GET /api/training/teacher-tasks/{offlineSessionId}` 的名单项补充学员姓名，并同步 OpenAPI、后端 VO/查询及测试。
- PC Web 教师任务详情展示姓名，保留用户 ID 仅作辅助信息。
- PC Web 在场次未开始、已结束、已取消、无查看权限或无录分权限时给出中文说明；录分入口仍仅由后端 `availableActions` 授权。
- 更新教师任务详情的定向前后端回归测试。

## 非目标

- 不恢复签到、签退、扫码或考勤登记。
- 不改变线下场次状态机、评分规则、权限模型、数据库结构或成绩保存接口。
- 不修改移动端和其他教师任务页面。
