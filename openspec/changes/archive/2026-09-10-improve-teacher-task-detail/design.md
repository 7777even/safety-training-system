# Design：优化教师任务详情的名单与录分提示

## 契约设计

- `TrainingTeacherRosterItemVO` 新增可空 `userName`，语义为该参训人在当前系统中的展示姓名。后端从现有用户资料读取；用户资料不存在或无可展示姓名时返回 `null`，不伪造姓名。
- 教师任务详情仍以 `availableActions` 作为唯一可执行动作来源。前端不得根据 `sessionStatus` 自行开放录分、开始、结束或取消操作。
- `GET /api/training/teacher-tasks/{offlineSessionId}` 访问被拒绝时，后端维持既有 HTTP 403 / 业务码语义；PC Web 需将其展示为“您没有查看或处理该场次的权限，请联系管理员”，不得误报为场次未开始。

## 展示与交互

- 名单“学员”列优先显示 `userName`；当其为空时显示“未获取姓名”，并以 `用户 ID：{userId}` 作为辅助信息，确保教师仍能辨识并反馈数据问题。
- 场次为 `SCHEDULED` 且 `RECORD_SCORE` 不可用时，在名单卡片内显示“请先开始本场线下培训，开始后可录入参训人员成绩。”
- 场次为 `COMPLETED` 或 `CANCELLED` 且不可录分时，分别说明“场次已结束，不能再录入成绩。”或“场次已取消，不能录入成绩。”
- 场次为 `IN_PROGRESS` 但 `RECORD_SCORE` 不可用时，说明“当前没有录入成绩的权限，请联系管理员。”该文案只解释已由后端拒绝授权的事实，不改变后端权限判断。
- 顶部说明调整为“本期线下培训由教师录入参训人员成绩，成绩将作为培训完成依据。”不出现签到、接口或开发实现说明。

## 数据与兼容性

- 不新增表、字段或迁移；`userName` 是详情查询时拼装的返回字段。
- `userId` 保持返回，既有调用方兼容；PC Web 不再将其作为唯一可见学员标识。
- 无姓名的历史或异常用户不阻断名单加载和成绩录入。

## 风险与取舍

- 用户名称属于可变基础资料，而参训资格和成绩归属仍以 `trainingParticipantId`、`userId` 为准。本次展示当前姓名，不将姓名复制为参训快照，避免无授权的数据模型变更。
- 不新增“不可录分原因”枚举，以免为已可由场次状态和后端动作表达的页面提示扩大 API；真正的访问拒绝继续使用既有 403 语义。
