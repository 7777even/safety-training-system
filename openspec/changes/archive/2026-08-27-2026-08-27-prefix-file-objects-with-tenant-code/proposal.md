# Proposal：文件对象统一增加租户编码根目录

## 背景

当前不同机构的新上传文件共同使用 `source/`、`derivative/`、`course-cover/` 或通用业务目录作为对象键起点。数据库访问已有
`organization_id` 隔离，但对象存储控制台和运维工具无法从对象键根目录直接识别租户，容易增加排查、备份和按租户治理成本。

用户已明确要求：所有以后新产生的文件对象统一以机构编码作为最外层租户目录；历史文件引用和对象键保持原样，不迁移、不改写。

## 目标

- 所有新上传或新生成的对象键统一以当前机构不可变的 `orgCode` 为根目录。
- 在租户目录下保留现有业务目录、年月层级和文件命名规则。
- 历史无租户前缀的对象继续按数据库已保存的完整对象键读取、下载、播放和删除。
- 集中生成并校验租户前缀，禁止客户端自行提交机构编码或跨机构对象键。

## 用户价值

- 对象存储可按机构根目录直观分区，便于运维定位、租户级备份和容量治理。
- 数据库租户隔离与对象存储命名形成一致的双重边界。
- 无需搬迁历史对象，避免已有课程、素材和派生文件引用失效。

## 功能范围

1. 新通用单文件上传和分片上传对象增加机构编码根目录。
2. 新素材源文件、课程封面和转码派生对象增加机构编码根目录。
3. 新课程封面路径变为 `{ORG_CODE}/course-cover/{yyyy}/{MM}/{uuid}.{ext}`。
4. 新素材源文件路径变为 `{ORG_CODE}/source/{yyyy}/{MM}/{uuid}.{ext}`；其他通用业务目录仅在原对象键前增加
   `{ORG_CODE}/`。
5. 新派生文件路径变为 `{ORG_CODE}/derivative/{assetId}/{jobId}/...`。
6. 历史对象键保持兼容；读取和清理不得为已保存对象键自动补前缀。
7. 同步受影响的系统文件 OpenAPI 字段说明与示例。

## 功能项追溯

- 功能项 20：课程资源管理中的文档、音频、视频和图片文件上传、下载、删除及后续转码文件管理。本 Change 仅补充其对象存储租户目录规则。
- 功能项 22：课程章节可添加 Word、Excel、PDF、PPT、图片、音频或视频材料。本 Change 仅保证这些文件及课程封面的新对象按机构目录隔离。

## 非目标范围

- 不迁移、复制、重命名或删除任何历史对象。
- 不批量改写 `us_sys_file_info.object_name`、`file_url` 或其他历史引用。
- 不新增 bucket，不改变年月层级，不增加日目录。
- 不修改机构编码，不允许上传请求自行指定租户目录。
- 不新增数据库字段、索引、Migration、权限码或生产依赖。
- 不实施前端页面、Mock 或联调；前端以 OpenAPI 为准另开。
