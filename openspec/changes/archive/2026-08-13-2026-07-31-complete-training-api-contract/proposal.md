# Proposal：补齐培训域 API 契约与纵向执行入口

> 状态：待人工确认。确认前只允许评审本 Change，不得修改业务代码或 `docs/api/*.openapi.json`。
>
> Owner：lims

## 背景

培训域后端已经完成类型、标准、模板、评价表单、计划、参训人和线下执行的基础实现，但机器可读契约与真实实现、既有数据模型和前端纵向流程之间仍存在缺口：

1. `training.openapi.json` 只登记 35 个 operation，而 5 个培训 Controller 已有 57 个，遗漏 22 个。
2. `evaluation-result.openapi.json` 遗漏已有的评价记录详情接口。
3. 培训与评价表单契约大量使用无明确字段的通用 `object`，缺少 DTO、VO、分页、枚举、错误响应和完整 example。
4. 模板分类分页无法可靠生成完整树；评价表单没有从表单 ID 枚举版本 ID 的读取入口。
5. 标准规则、模板阶段和发布操作缺少聚合根版本校验；发布人、教师任务查询等身份字段未全部从登录态派生。
6. 后续计划执行、教师处理、学员任务和培训结果读取尚缺少稳定 API 入口。

原 Change `2026-07-24-implement-training-execution` 的 Task 7 已标记“完整 OpenAPI”，但当前契约不满足其验收描述。本 Change
不重写原业务规格，只负责修复契约闭环，并为确有数据模型支撑的缺失读取与执行入口形成增量规格。

## 目标

1. 使培训、评价表单和评价结果 OpenAPI 与已有 Controller、DTO、VO、数据库枚举和真实错误码一致。
2. 为模板分类树和评价表单版本历史提供稳定读取接口，解除培训管理输入侧阻塞。
3. 修正整体替换、发布和教师任务中的并发、审计与登录身份语义。
4. 按既有计划、执行关联、参训人、考试上下文和综合结果模型补齐后续纵向入口。
5. 所有新增或修改的 API 均先更新 OpenSpec 与 OpenAPI，再按 TDD 实施后端；前端以 OpenAPI 为准另开。

## 用户价值

- 前端可以依据唯一机器可读契约生成正确请求、枚举、错误处理和类型定义，不再猜测后端字段。
- 培训管理员可以获得完整模板分类树和评价表单版本 ID，完成计划输入配置。
- 并发编辑不会静默覆盖他人修改，发布人和教师身份具备可信审计来源。
- 教师和学员后续可以沿培训计划进入真实执行对象并读取可追溯结果。

## 功能范围

### 第一阶段：现有接口契约补齐

1. 在 `training.openapi.json` 登记培训 Controller 已有但遗漏的 22 个 operation。
2. 在 `evaluation-result.openapi.json` 登记已有的评价记录详情 operation。
3. 补齐 `training.openapi.json` 和 `evaluation-form.openapi.json` 中已有接口使用的请求、响应、分页、枚举、错误响应和
   example。
4. 修正评价表单 `formType` 为数据库规定的 `COMPOSITE/EXPERT_INSPECTION`，登记真实错误码，包括模板内容类型错误 `8038`。

### 第二阶段：管理输入与安全语义

1. 新增模板分类树读取接口。
2. 新增评价表单版本历史摘要接口。
3. 为标准规则整体替换、模板阶段整体替换及相应发布操作增加聚合根 `version` 并发校验。
4. 评价表单发布规则通过同批次 `evaluationItemCode` 关联新建项目。
5. 发布人、教师任务身份及其他执行人审计字段从当前登录态派生。
6. 明确发布后不可变、版本冲突、删除保护和资源状态冲突的 HTTP 409 契约。

### 第三阶段：培训执行与结果纵向入口

1. 草稿计划移除参训人。
2. 当前教师线下任务详情与可处理动作。
3. 计划执行关联读取、单内容幂等补建及培训上下文考试启动。
4. 学员本人培训任务、参训详情、计划结果同步和参训人分项结果读取。

第三阶段涉及课程、考试、综合结果的跨域协议。实施前必须再次人工确认接口边界、幂等键、权限和正式结果口径；未确认时不得执行第三阶段
Task。

## 非目标范围

- 不修改数据库结构，不新增 migration；若实施中发现现有表无法表达已确认语义，立即暂停并另行决策。
- 不新增权限模型，不根据角色名称、机构类型或客户端传入用户 ID 推导权限。
- 不改变课程、考试、评价计算和正式成绩的既有业务规则。
- 不在本 Change 中实现批量导入、导出、统计、档案、证书、预警或素材转码。
- 不实施前端页面、Mock、联调或 UI 验收；前端以 OpenAPI 为准另开。
- 不把 Markdown 计划作为平行业务规格；本目录的 `tasks.md` 是本 Change 唯一实施任务来源。
