# Design：M5 中山 50 最小监管闭环与超范围能力收口

## 1. 文档地位

本文件是 M5 重整的主设计文档。经人工确认后，M5 页面、API、权限、代码、测试和验收均以本文件及同目录 `spec-delta.md` 为准。旧 M5
Change 只用于历史追溯，不再提供新增范围或完成依据。

本 Change 获得人工确认前，不得删除代码、修改 API、调整权限、修改数据库 COMMENT 或更新 M5 状态。

## 2. 设计原则

### 2.1 范围判定

每项对外能力必须同时满足：

1. 可追溯到 `docs/product/功能项中山50.csv` 的明确语义；
2. 是形成对应功能最小用户闭环所必需；
3. 具有真实页面、真实 API、真实数据、权限和可执行验收；
4. 不依赖 Mock、固定返回、占位文件或仅后端接口。

### 2.2 三类处置

| 分类     | 判定                           | 处置                                              |
|--------|------------------------------|-------------------------------------------------|
| 最小产品能力 | 功能项明确要求且闭环必需                 | 保留或补齐页面、API、Service、查询和测试                       |
| 必要内部机制 | 用户不直接配置，但为跨租户安全、幂等、证据或历史兼容所需 | 保留内部代码与 SQL；不提供独立页面、菜单或公开操作                     |
| 超范围能力  | 功能项未要求且不是必要内部机制              | 删除业务代码、公开 API、前端、权限、OpenAPI 和专属测试；SQL 保留并标注暂时隐藏 |

## 3. M5 最小业务闭环

```text
园区监管人员登录
→ 查看园区总体培训和学习数据
→ 查看培训类型、特种作业、机构与人员统计
→ 下钻到某企业、培训计划和参训人事实

企业保存培训计划
→ 系统按初培/复审读取培训类型要求学时
→ 计划学时不足时自动生成或刷新预警
→ 园区监管人员看到待查看预警
→ 查看培训类型与计划学时对比及来源计划
→ 导出真实预警/统计数据

企业管理员登录
→ 查看本企业功能入口和最小数据概览
→ 跳转到对应业务列表继续处理
```

## 4. 能力一：园区监管工作台（功能项 1、3）

### 4.1 首页布局

监管工作台只展示功能项要求的概览和入口：

- 受监管企业数量；
- 受监管培训机构数量；
- 培训计划总数及进行中、已结束数量；
- 参训人数及完成人数；
- 待查看学时预警数量；
- 培训类型分布；
- 特种作业培训计划数、参训人数和完成人数；
- 企业/培训机构列表摘要；
- 证书管理、课程制作和数据中心快捷入口。

快捷入口只负责路由导航，不授予额外权限。当前用户没有目标模块权限时不得因快捷入口绕过鉴权。

### 4.2 数据来源

- 企业、培训机构：机构主数据；
- 培训计划：`sts_training_plan`；
- 培训类型：计划关联的 `sts_training_type`；
- 特种作业：培训类型 `tag='特种作业'`；不得通过名称模糊匹配猜测；
- 参训人数与完成情况：`sts_training_participant`；
- 预警：当前有效且状态为待查看的培训计划学时预警。

统计直接聚合现有事实，不新增统计事实表，不定时复制一套可能失真的汇总数据。

### 4.3 跨租户安全

监管汇总是显式跨租户只读查询，必须统一经过：

1. `REGULATOR` 身份校验；
2. 专用只读聚合 Mapper，显式列出机构隔离条件；
3. 禁止在聚合 Mapper 中出现写语句；
4. 下钻明细使用受控的目标租户只读视角；
5. 所有越权目标租户请求返回明确的 403 错误。

现有 `/regulator/aggregates/tenants` 与 `/regulation/overview` 必须合并为一套监管工作台契约，不能保留两套不同统计口径。

### 4.4 企业/培训机构分类

当前机构类型只有 `ENTERPRISE` 和 `REGULATOR`，不能独立统计培训机构。为了覆盖功能项 1、4，机构主数据需要能够区分：

- `ENTERPRISE`：企业；
- `TRAINING_INSTITUTION`：培训机构；
- `REGULATOR`：园区监管平台。

不得根据机构名称或描述猜测培训机构。既有企业数据保持 `ENTERPRISE`，需要转为培训机构的历史数据由管理员明确修改，不自动迁移。

该枚举调整会影响登录、租户目录、监管目标选择、组织查询和 OpenAPI，属于 L4；实施前必须单独核对全部 `orgType` 分支。

### 4.5 最小验收

监管用户登录后能看到企业和培训机构分类、园区培训概览、类型分布、特种作业统计、人员完成情况和待查看预警；点击机构后进入该机构只读视角；快捷入口不绕过权限。

## 5. 能力二：学习情况统计与数据中心（功能项 3、7）

### 5.1 二级页面

数据中心提供园区汇总和单机构两个层级，不建设可拖拽大屏编辑器。页面至少展示：

- 员工账号数；
- 上课次数；
- 上课人数；
- 参与课程数；
- 人均上课次数；
- 参与率。

### 5.2 最小统计口径

以下口径作为本 Change 的确认项，确认后全园区、单机构、页面、导出和测试统一使用：

| 指标     | 最小口径                                   |
|--------|----------------------------------------|
| 员工账号数  | 当前启用企业/培训机构内启用的非监管用户数                  |
| 上课次数   | 有效课程报名产生的学习次数；同一学员参加一个开课计一次，不按学习会话重复累计 |
| 上课人数   | 至少参加一个开课的去重学员数                         |
| 参与课程数  | 至少有一名学员参加的去重课程开课数                      |
| 人均上课次数 | 上课次数 ÷ 上课人数；无人参与时为 0                   |
| 参与率    | 上课人数 ÷ 员工账号数；无员工账号时为 0                 |

统计使用现有课程开课和报名事实，不把考试、题库练习或线下场次计入“上课次数”。若产品希望使用学习会话或培训场次口径，必须在确认本
Change 前修改本节，实施时不得自行改变。

### 5.3 展示与下钻

- 园区层可查看全部机构汇总和按机构列表；
- 单机构层展示同口径指标；
- 点击上课人数、参与课程数可进入对应人员或开课明细；
- 不提供任意字段组合、任意维度、图表设计器或指标公式编辑。

### 5.4 最小验收

准备两个机构，其中一个存在课程报名、另一个无报名；园区汇总等于两机构合计；单机构指标、明细和导出使用同一口径；零分母返回
0，不返回异常或虚假比例。

## 6. 能力三：培训计划学时预警（功能项 2）

### 6.1 唯一预警规则

当前版本只支持：

```text
计划安排总学时 < 培训类型按培训性质要求的学时
```

- 初培计划读取培训类型 `initialHours`；
- 复审计划读取培训类型 `reviewHours`；
- 计划安排总学时沿用培训域已经确认的统计口径；
- 不加入用户自定义阈值；
- 不加入线上占比、人员完成率、证书到期或其他预警。

### 6.2 自动刷新时机

预警不是监管人员手工执行的检测任务。系统在以下时机内部刷新：

- 培训计划创建或修改成功后；
- 培训性质、培训类型、阶段或内容学时变化后；
- 发布预检前；
- 培训计划删除、取消或修正为满足学时后。

已有存量计划在部署 migration 后通过一次受控修复任务扫描，不提供公开“执行检测”按钮或 API。

### 6.3 状态

对用户只提供：

- `UNREAD`：待查看；
- `READ`：已查看。

当计划修正为满足学时、删除或取消时，系统内部将当前预警结束，默认列表不再显示；历史数据继续保留。内部结束状态不提供人工关闭按钮。

### 6.4 幂等与证据

同一监管租户、目标机构和培训计划只有一条当前学时预警。系统内部保留确定性去重键和证据：

- 培训计划 ID、名称和编号；
- 目标机构；
- 培训类型 ID、名称；
- 培训性质；
- 计划安排学时；
- 类型要求学时；
- 学时差额；
- 检测时间。

证据必须能跳转到对应计划，不建立通用指标字典或规则表达式。

### 6.5 页面

监管端提供：

- 工作台待查看预警数量；
- 预警分页列表；
- 按机构、培训类型、待查看/已查看筛选；
- 预警详情与学时对比；
- 查看详情时标记已查看；
- 跳转对应企业培训计划；
- 按当前筛选条件导出。

### 6.6 删除或隐藏

删除以下公开产品能力：

- 预警规则和条件 CRUD；
- 自定义 `metric_code`、运算符和阈值；
- `PLAN_ONLINE_RATIO`；
- 手工 detect API；
- 预警分派、评论、人工关闭、忽略和重开；
- 预警负责人和处置流水页面。

预警规则表可保留一个内部固定规则记录，用于兼容既有非空 `warning_rule_id`；不提供管理接口。预警条件表和操作流水表保留但当前不读写。

### 6.7 跨租户执行

自动刷新计划预警时，读取计划事实必须显式绑定目标企业租户；写入预警必须显式绑定监管租户。禁止在同一个隐式租户上下文中同时查询监管规则和企业计划。

实现前必须补真实 MySQL 登录态测试，覆盖监管租户、目标企业租户和非监管用户；Mock Service 测试不能作为跨租户闭环证据。

### 6.8 最小验收

企业保存一个初培学时不足的草稿计划后，监管端自动出现一条待查看预警；详情显示计划学时、培训类型要求学时和差额；重复保存不新增重复预警；监管人员查看后变为已查看；企业补足学时后预警退出默认列表；导出得到真实
CSV。

## 7. 能力四：监管机构管理（功能项 4）

### 7.1 复用现有机构主数据

不新增监管机构表。复用现有机构管理完成：

- 按企业/培训机构分类创建；
- 列表和详情查看；
- 编辑基本信息；
- 启用和停用；
- 进入机构只读管理中心。

监管人员进入企业管理中心时继续使用目标租户只读视角；本 Change 不因“管理”二字默认允许跨租户修改业务数据。

### 7.2 “授权”待人工决策

功能项未说明授权对象。实施前必须从以下语义中由人工选择并写入 OpenSpec：

- 机构账号启用/停用；
- 系统模块或菜单授权；
- 监管关系授权；
- 课程、证书或其他资源授权。

选择前不得新增授权表、权限码、跨租户写接口或资源授权模型。该事项未确认时，Task 可完成机构分类、查看、编辑和只读管理入口，但 M5
不得声称完整覆盖功能项 4。

## 8. 能力五：企业管理员工作台（功能项 8）

### 8.1 功能模块

企业管理员工作台提供已授权模块的快捷入口，最小包括：

- 课程管理；
- 理论考试；
- 培训管理；
- 证书管理；
- 组织与用户管理。

入口是否显示完全服从当前角色菜单权限，不新增工作台专属授权模型。

### 8.2 数据分析

只展示能从现有事实直接解释的本企业概览：

- 已发布课程数；
- 进行中考试数；
- 进行中培训计划数；
- 当前参训人数；
- 已结束培训通过/未通过人数；
- 本人权限范围内的明确待办数量及分类。

待办必须返回分类明细，不能把不同业务对象简单相加为一个不可解释数字。

课程、考试和培训专项统计继续由功能项 25、18、41 的独立页面承担；工作台不重复完整分析。

### 8.3 删除或迁出

- 删除 M5 教师工作台 Controller、Service、VO、权限和 OpenAPI；教师任务继续由各业务域入口承担。
- 删除 M5 学员工作台摘要；学员首页按功能项 47 独立实现。
- 删除通用课程/考试/培训/结果状态统计和仅返回 ID 的通用 drilldown。
- 删除对 M4 已隐藏综合计算批次表的统计依赖。

### 8.4 最小验收

企业管理员登录后看到权限允许的快捷入口及真实概览；点击卡片进入对应业务列表；无权限模块不展示；待办总数与分类明细之和一致。

## 9. 真实导出

### 9.1 范围

当前 M5 只导出：

- 监管机构统计列表；
- 学习情况统计列表；
- 当前筛选条件下的培训计划学时预警列表。

### 9.2 最小格式

采用 UTF-8 BOM CSV，通过受权限保护的下载响应同步生成。文件列与当前页面列表一致，包含导出时间和筛选摘要。数据量超出安全上限时拒绝并提示缩小筛选范围；不在本
Change 建设异步导出中心。

不得将固定 `fileId`、只创建任务记录或空文件作为导出完成。

## 10. SQL 保留与 COMMENT 标准

### 10.1 禁止事项

- 不删除既有表、列、索引和历史数据；
- 不修改已经执行的 migration；
- 不因功能隐藏而破坏历史数据读取和租户隔离。

### 10.2 注释格式

完全不再使用的表：

```sql
COMMENT='【暂时隐藏】原用于：<原用途>；当前中山50最小闭环不启用，不得作为当前页面、API或业务规则依据；后续启用须新建并确认 OpenSpec Change'
```

隐藏列：

```sql
COMMENT '【暂时隐藏】原用于：<原用途>；当前中山50最小闭环不读取、不写入、不展示；后续启用须新建并确认 OpenSpec Change'
```

必要内部字段：

```sql
COMMENT '【内部保留】用于：<当前必要用途>；不提供独立页面或对外操作'
```

### 10.3 首批处置对象

| SQL 对象                             | 处置                         |
|------------------------------------|----------------------------|
| `sts_regulation_warning`           | 保留；当前预警、去重和已读状态继续使用        |
| `sts_regulation_warning_evidence`  | 内部保留；保存学时对比证据              |
| `sts_regulation_warning_rule`      | 内部保留一个固定系统规则；规则管理字段按实际使用标注 |
| `sts_regulation_warning_condition` | 暂时隐藏，不再由当前业务读写             |
| `sts_regulation_warning_action`    | 暂时隐藏，不再写处分派/评论等流水          |
| `sts_ops_export_job`               | 暂时隐藏；同步 CSV 不使用任务中心        |
| `current_assignee_id`              | 暂时隐藏                       |
| `warning_level`                    | 固定内部值，不提供配置                |
| `closed_time`                      | 内部用于计划修正后结束当前预警，不提供人工关闭    |

COMMENT 变更必须同步最新 init SQL、新 Admin Flyway migration、Entity 说明和 `sts.init.schema-version`。

## 11. 代码删除规则

确认实施后，每项超范围能力同时删除：

- Controller 路径及权限注解；
- 专属 Service、DTO、VO、Mapper 查询和枚举；
- 前端 API、类型、Mock、菜单、路由、按钮和页面；
- 菜单种子和角色权限；
- OpenAPI path、schema、错误码与示例；
- 仅验证已删除行为的测试。

首批删除目标包括：

- `OpsTeacherWorkbench*`；
- M5 中的 `OpsLearnerWorkbench*`；
- 通用 `OpsStats*` 和 `OpsDrilldown*`；
- `OpsExport*` 任务中心代码；
- 公开 `WarningRule*`、`WarningCondition*` 管理代码；
- 公开手工检测入口；
- `WarningActionService` 中除查看标记外的人工处置代码；查看标记可直接收敛到预警服务，不保留通用 action 流水。

删除前必须静态检索所有真实调用方；存在调用方时在同一 Task 同步，不长期保留双轨接口。

## 12. API 与权限原则

- 监管 API 必须同时校验权限和监管租户身份；普通企业即使获得错误菜单权限也不得访问。
- 监管汇总与下钻共享同一指标定义。
- 企业工作台严格使用当前租户和角色数据范围。
- 学时预警不接受客户端传入任意机构执行跨租户检测。
- OpenAPI 与 Controller 一一对应，不保留无调用方的历史路径。

建议收敛后的业务资源如下，准确 URL 在实施 Task 的 OpenAPI 评审中确认：

| 资源    | 最小操作                         |
|-------|------------------------------|
| 监管工作台 | 园区概览、机构列表、类型/特种作业统计          |
| 学习统计  | 园区汇总、机构明细、人员/课程下钻、CSV 导出     |
| 学时预警  | 待查看数量、列表、详情、标记查看、计划跳转、CSV 导出 |
| 机构管理  | 分类创建、查看、编辑、启停、只读进入；授权待确认     |
| 企业工作台 | 权限化快捷入口、概览和分类待办              |

## 13. 历史数据与状态

- 实施开始时将 M5 从“已完成”改为“实施中”。
- 历史规则、条件、处置动作和导出任务不删除、不改写，默认不在新页面展示。
- 既有 `PLAN_ONLINE_RATIO` 预警不再参与当前检测；历史记录保留。
