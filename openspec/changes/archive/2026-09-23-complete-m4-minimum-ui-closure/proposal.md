# Proposal：补齐 M4 最小界面业务闭环

## 状态

- 已获人工确认实施；二维码渲染依赖、个人档案沿用 JSON 文件格式均获确认。确认不表示下列 Task 已完成。
- 基于已确认的 `m4-minimum-closure` 主规格和现有 M4 OpenAPI，接续 `2026-09-21-implement-m4-pc-outcome-closure` 的未验收部分；不改写该 Change 的既有范围声明。
- 覆盖中山功能项 19、35、39、40、42、43、44、50。原文语义分别为证书设计/配置/签发及本人查看，扫码问卷及结果可见性，综合分自动计算，已结束培训成果，问卷设计管理及双端预览，专家查课，个人/企业/一期档案，个人中心证书。

## 现状与问题

- 问卷、成果、档案、证书已有页面或接口，但扫码二维码、问卷删除与可见性、成果明细、档案生成与三级查询、证书预览等操作尚不能从界面走完整条链。
- `GET /api/archive/persons/{userId}/file` 已公开，但个人档案查询不设置 `fileInfoId`，当前下载必然返回未生成；一期档案实际是 JSON，PC 却命名为 ZIP。
- 附件中的证书三级组件路径已存在；本地初始化菜单与增量迁移尚未同步 M4 菜单。成果详情依赖计划 ID，应保持培训计划上下文入口，不新建无参数成果菜单。
- 现有类型检查和定向测试通过，仅证明静态接线，不证明三角色真实业务验收。

## 目标与范围

1. 只复用当前 OpenAPI 和既有业务规则完成问卷、成果、档案、证书最短操作路径；发现真正的契约缺口才另行修订并确认。
2. 修复已公开个人档案下载端点；仅为必需导航同步初始化菜单和幂等 Flyway 菜单数据，不改变权限模型或业务表结构。
3. 每个 Task 先写可失败的定向测试，再作最小实现；验证通过后记录 QA、双轴 Review 与真实角色证据，最后才勾选 Task。

## 非目标

- 不恢复签到/出勤前置、人工成绩计算批次、档案版本中心、异步导出中心、证书撤销/重发、复杂问卷规则、图表大屏或监管跨租户汇总。
- 不把 Mock、页面存在、类型检查或接口返回非空当作真实闭环验收。
- 不操作生产数据库或直接修改线上菜单；菜单变化只通过受控初始化种子与增量迁移交付。

## 实施前需确认的选择

- 二维码：现有前端没有二维码渲染依赖。建议批准一个仅用于把现有 `qrContent` 渲染成可扫描二维码的轻量依赖；不用外部二维码服务传出填写链接。
- 个人档案导出：建议沿用现有 JSON 档案格式，按本人已结束培训的现有档案事实生成受控文件，不新增 ZIP/PDF 能力或数据库字段。
- 菜单：以附件为目标信息架构，但先核对 ID、`moduleId`、类型和权限冲突；只迁移已实现的菜单/按钮，不照搬错误字段或制造无参数成果页。
