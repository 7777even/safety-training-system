# Proposal：拒绝素材转码空产物成功

## 背景

线上视频转码任务出现 `SUCCEEDED`、执行耗时不足一秒且没有任何有效派生文件的状态组合，导致管理端显示转码成功，但素材没有可播放的
HLS
与封面。当前 `TranscodeResultService` 会无条件接受 `TranscodeOutput.empty()`，既有测试也把空结果提交成功作为正常行为，因而没有守住转码成功事实。

## 目标

1. 视频转码只有同时产生 HLS 与封面派生结果时才能提交 `SUCCEEDED`。
2. 空产物或不完整视频产物必须进入既有失败链路，记录稳定失败码并保持素材不可用。
3. 使用专用失败码区分“环境未启用真实转码”和“真实转码执行异常”。
4. 通过 Red → Green 自动化测试覆盖空结果、不完整结果和完整结果，防止再次出现伪成功。

## 用户价值

- 管理员看到的转码状态与真实可播放产物一致。
- 失败任务能够通过既有任务失败信息和人工重试入口暴露、定位和恢复。
- 课程与学习模块不会消费没有实际播放载体的“成功”素材。

## 覆盖功能项

- 功能项 20：课程资源管理支持文档、音频、视频及图片资源的上传、下载、删除和在线预览；“上传资源后平台会对资源进行转码服务，转码中的资源不可下载、编辑及课程制作，转码成功后的资源方可进行下载编辑及课程制作”。本
  Change 修复其中“转码成功”状态必须对应真实可用派生结果的语义。

## 功能范围

1. 在转码结果提交边界校验视频派生结果完整性。
2. 将空产物或缺少 HLS/封面的视频任务转入既有 `FAILED/TRANSCODE_ERROR` 流程。
3. Stub Provider 使用 `PROVIDER_DISABLED` 明确报告环境未启用真实转码服务，不再返回空结果。
4. 修正把 `TranscodeOutput.empty()` 视为视频成功的既有测试，并补充结果提交护栏测试。

## 非目标范围

- 不修改任何前端页面、Mock、联调或 UI；前端以 OpenAPI 为准另开。
- 除在既有开放字符串 `failureCode` 文档中增加 `PROVIDER_DISABLED` 语义外，不修改 API 路径、字段结构、权限模型、数据库结构、任务表字段或
  migration。
- 不改变 FFmpeg 编码参数、视频大小限制、并发数、超时策略或人工重试规则。
- 不处理线上既有伪成功数据，也不操作生产数据库；历史任务的数据修复另行人工决定。
- 不在本 Change 中解释特定大文件为何返回空结果；本次先确保异常结果不能再伪装为成功，并通过失败状态暴露真实故障。

## 人工确认点

空产物或缺少 `HLS`、`THUMBNAIL` 任一必需派生类型的真实视频转码任务记录为 `FAILED/TRANSCODE_ERROR`；Stub Provider
记录为 `FAILED/PROVIDER_DISABLED`，原因固定为“当前环境未启用真实转码服务，任务未执行”。不增加自动重试。
