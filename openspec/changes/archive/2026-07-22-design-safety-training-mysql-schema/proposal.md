# Proposal：安全教育培训系统模块化 MySQL 数据模型

## 背景

`docs/product/安全教育培训74条FR新需求描述对照表.md` 给出了覆盖园区监管端、企业/培训机构端和学员端的 74 条功能需求追踪记录，
`docs/product/魔学院功能调研文档_排版优化终稿.md` 进一步细化了课程、题库、试卷、考试、证书、问卷和人脸核验能力。
当前仓库只有系统管理模块的 `us_sys_*` 表，尚无培训业务的可实施物理数据模型，后续 API、前后端和 migration 缺少共同的数据边界。

2026-07-21，经需求方确认，仿真和人脸识别能力延期，本期不设计、不实施、不验收。74 条 FR 中 FR-ENT-EXM-009～016、FR-ENT-SYS-006 共
9 条延期，
其余 65 条为本期有效 FR；FR-ENT-CRS-005、FR-ENT-CRS-006、FR-ENT-TRN-002 本期只覆盖非仿真部分。

## 目标

- 按业务领域而非页面或技术层拆分 MySQL 表，覆盖本期 65 条有效 FR 涉及的长期业务数据；其中 3 条混合 FR 只覆盖非仿真部分。
- 详细设计课程、题库、试卷、考试/练习的内容模型、执行模型和历史快照模型。
- 为培训计划、证书、问卷、分析归档和园区监管建立可演进的数据骨架。
- 统一复用现有 `us_sys_dept`、`us_sys_role`、`us_sys_user_role`、`us_sys_menu` 和 `us_sys_role_menu`
  承载培训组织、角色和功能权限，并补充系统级角色数据范围。
- 明确主键、审计、逻辑删除、租户隔离、唯一约束、索引和历史数据不可变规则。

## 用户价值

- 产品和架构负责人可以按模块审查系统边界、业务规则和未决项。
- 后端可据此先定义 API Contract，再分能力实施 Entity、Mapper 和 migration。
- 前端可围绕稳定的课程、考试、培训等业务聚合设计页面和共享类型。
- 学习、考试、证书、档案和监管数据具备可追溯的历史依据，避免资源编辑后污染既有结果。

## 功能范围

- 机构、系统部门树、机构成员、系统角色与功能/数据权限、标签/岗位、监管关系。
- 通用参与范围、资源授权、管理权限、提醒消息、分享、积分流水和通用导入批次。
- 素材与转码、课程与开课、学习过程与评价。
- 题库、题目版本、试卷版本、固定/随机/自定义组卷。
- 正式考试、专项练习、题库练习、补考、批阅、防作弊和成绩发布。
- 培训类型/标准/模板/计划、线上与线下执行。
- 证书、问卷、综合评价、专家查课、培训档案和监管预警。
- 物理表命名、字段类型、审计类别、索引、唯一约束和跨模块关系。

## 非目标范围

- 本 Change 只提供用于评审和本地建表验证的 DDL 设计草案，不创建正式 migration、Entity、Mapper、API、页面或 Mock
  数据；本地验证通过不代表可直接用于生产部署，正式数据库变更仍必须生成 `database/migration`。
- 不直接修改 `backend/sql/schema-system.sql`、后端 Entity 或生产数据库；本 Change 只描述 `us_sys_dept`、`us_sys_role`
  的目标扩展和新增 `us_sys_role_dept`，正式修改仍须由确认后的 migration Task 完成。
- 本期不实施人脸供应商能力，不创建人脸配置、档案、策略、核验和修订表。
- 本期不实施仿真能力，不创建仿真资源、安装包、试卷、分配、参与和结果表。
- 不自行确认角色权限矩阵、跨机构数据授权、统计口径或证书编号规则。
- 不实现综合成绩的缺勤否决、封顶保底、条件组合或自定义公式引擎。
- 不把列表展示字段、统计卡片或临时报表各自固化为重复业务表。

## 决策状态

- 暂定：所有业务资源归属于一个机构，平台公共资源由一条 `PLATFORM` 类型机构记录持有；跨机构使用通过资源授权表表达。
- 已确认（2026-07-21，需求方）：培训业务组织树、角色、用户角色和功能权限统一使用系统表，不再创建 `sts_org_unit`、`sts_org_role`、
  `sts_org_member_role`、`sts_org_role_permission`。
- 已确认（2026-07-21，需求方）：本期补充角色数据权限，至少支持全部、全机构、本部门、本部门及下级、自定义部门和本人六类范围；不支持字段条件、SQL
  或任意表达式。
- 已确认（2026-07-21，需求方）：同一用户多个角色的数据范围取并集；仅账号编码严格等于 `superAdmin` 的用户硬编码绕过功能权限和数据权限。
- 已确认（2026-07-21，需求方）：除 `superAdmin` 外不按角色编码、名称或级别设置隐含特权，其他角色严格按自身功能权限和
  `data_scope` 配置执行。
- 已确认（2026-07-21，需求方）：一个普通账号只属于一个主要机构和一个主部门，不支持在多个机构分别任职或切换机构角色；
  `superAdmin`、监管关系和跨机构资源授权不视为跨机构任职。
- 已确认（2026-07-21，需求方）：课程内考试、专项练习和题库练习采用简单直接关联；`EXAM`、`PRACTICE`、`QUESTION_BANK` 内容项均关联
  `exam_id`，每个题库项只关联一个题库并与 `BANK_PRACTICE` 考试来源一致；课程来源考试人员保存开课、内容项和报名
  ID，作答与成绩继续复用统一考试执行表。
- 已确认（2026-07-21，需求方）：课程和问卷采用不可变发布版本；问卷另设独立投放实例，同一版本允许重复投放，参与范围与结果可见范围以
  `business_type=SURVEY_INSTANCE` 解析为实例专用冻结范围，参与人和答卷同时固定投放实例与版本。
- 已确认（2026-07-21，需求方）：考试人员按 `exam_id + user_id + context_type + context_id` 标识一次业务上下文，课程上下文使用内容项进度
  ID，培训上下文使用计划内容 ID 并另存参训人员 ID；分配来源只用于追溯，人员记录冻结姓名、机构、部门等档案快照。
- 已确认（2026-07-21，需求方）：题库练习和线下考试允许不绑定固定试卷版本，但每次尝试必须保存试卷来源并冻结总分、及格线、时长、题序和多选计分等执行参数；练习重置必须限定考试人员和上下文。
- 已确认（2026-07-21，需求方）：考试结果通知不推导学员直属负责人；考试配置时直接选择一个或多个接收人，成绩发布后仅向已选接收人推送，不建设部门负责人或成员直属上级关系。
- 已确认（2026-07-21，需求方）：修复会因 `NULL` 失效的业务唯一键；按机构后台、统计、权限过滤和清理入口补充租户组合索引；统一
  `design.md`、DDL 与表目录描述。
- 已确认（2026-07-21，需求方）：跨模块引用统一使用逻辑外键，不创建 MySQL 物理外键；由领域服务写入校验、发布检查、删除保护、幂等事件和孤儿巡检保证一致性。
- 已确认（2026-07-21，需求方）：园区作为培训类型、培训标准和培训模板的资源所有方，企业或培训机构在有效监管关系和显式资源授权下使用；创建或发布计划时校验授权并冻结来源园区和资源快照，授权到期不影响已发布计划的历史执行和归档。
- 已确认（2026-07-21，需求方）：`sts_training_type` 已满足不少于 25 种培训类型的数据承载要求；具体类型清单和字段值由需求方在实施阶段自行提供并内置，当前设计不新增表、不编造正式
  seed。
- 已确认（2026-07-21，需求方）：培训计划每种评价用途只绑定一个固定表单版本；每个计分课程/考试内容单独配置权重，同类型结果按
  `AVERAGE` 或 `WEIGHTED_AVERAGE` 聚合；每次综合成绩计算保存不可变批次和逐来源贡献明细，一个参训人跨表单版本最多只有一个正式批次。
- 已确认：综合成绩继续使用版本化的来源类型权重和基础加减分配置；具体权重值由机构配置，高级计算规则后续通过独立 OpenSpec
  Change 升级。
- 已确认（2026-07-21，需求方）：监管预警主单按规则、被监管机构、可选培训计划和检测周期生成确定性去重键，证据按指标、来源记录和来源事实版本生成证据键；同一周期重复扫描不得重复建单或追加相同证据。
- 暂定：课程目录按 FR 支持无限级；调研文档中的“多章节”是该模型的两级使用方式。
- 暂定：统计页面优先从学习、答卷和培训事实表计算，只有正式归档时生成不可变快照。
- 已确认（2026-07-21，需求方）：培训计划和培训模板内容本期不提供直播（LIVE）类型，培训直投直播不实施；直播仅通过课程内容项执行，后续启用需独立
  OpenSpec Change 补执行通道。
- 已确认（2026-07-21，需求方）：题库题目、用户账号、参训人员和线下成绩四类批量导入统一使用公共导入批次表和公共导入错误表（
  `business_type` 区分），删除题库和线下成绩专用导入批次表；各类导入模板列定义和校验规则仍待产品确认。
- 已确认（2026-07-21，需求方）：开课类型（必修/选修）作为独立字段 `course_type` 保存于课程开课，与报名类型 `enrollment_type`
  正交；UI 按报名类型给默认值但存储显式；退选规则仍待产品确认。
-

已确认（2026-07-21，需求方）：证书采用简单规则——签发规则挂业务定义（课程/考试/培训计划），证书实例挂执行实例（开课/考试/培训计划），复训经新开课或新计划自然签发新证书；同一持有人、来源、模板最多一张未删除证书，撤销后重发须由管理员先逻辑删除旧证再人工签发，不建签发序号和自动重发机制。

- 已确认（2026-07-21，需求方）：人脸与仿真延期，本期不设计、不实施、不验收；后续启用时必须分别创建独立 OpenSpec
  Change，不能直接恢复旧草案或补 migration。
- 已确认（2026-07-21，需求方）：两轮数据库设计评审（问题一～七、R2-01～R2-12）全部关闭，本 Change 设计评审通过；DDL 已通过本地
  MySQL 8.0.45 建表、唯一性和索引验证。实施仍按 `tasks.md` 逐 Task 确认执行。
