## 2. 关系设计说明

- 当前设计暂不创建 MySQL 物理外键，所有 `*_id` 均为逻辑外键，由应用服务、唯一索引和发布前完整性检查保证一致性。
- `user_id`、`*_user_id`、`create_by`、`update_by` 等用户字段逻辑关联 `us_sys_user.user_id`；用户主部门由
  `us_sys_user.dept_id` 确定。
- `dept_id` 逻辑关联 `us_sys_dept.dept_id`；`file_info_id`、`*_file_id` 逻辑关联 `us_sys_file_info.file_info_id`。
- `business_type + business_id`、`resource_type + resource_id`、`source_type + source_id`、`target_type + target_id`
  是多态逻辑关联，实际目标表由类型字段确定。
- 下文只列每张表的主要业务关系，省略公共审计字段形成的用户关联。

核心数据链路如下：

```text
系统技术账号 ──→ 系统部门 / 系统角色 ──→ 功能权限 + 部门数据范围
       └──────→ 机构成员档案 ─────────→ 参与范围、授权、提醒、积分
    ├── 素材 ──→ 课程 ──→ 开课 ──→ 报名 ──→ 学习事实
    ├── 题库 ──→ 题目版本 ──→ 试卷版本 ──→ 考试 ──→ 作答与成绩
    └── 培训标准 / 模板 ──→ 培训计划 ──→ 计划内容
                                        ├── 课程开课 ──→ 课程报名 ──→ 参训人员
                                        ├── 考试 ──→ 考试人员 ──→ 参训人员
                                        └── 线下场次 ──→ 签到 / 成绩 ──→ 参训人员

课程 / 考试 / 培训结果 ──→ 证书、问卷投放实例、综合评价计算批次
培训及其学习事实 ──→ 培训档案版本 ──→ 监管预警
```

| `us_sys_role_dept`     | **新增** | `CUSTOM` 角色的部门数据范围及是否包含下级。                    |
| `us_sys_file_info`     | 复用     | 上传文件、证书文件、导出文件和业务附件的统一文件元数据。                  |
| `us_sys_dict_type`     | 复用     | 可配置字典类型。                                      |
| `us_sys_dict_data`     | 复用     | 可配置字典数据。                                      |
| `us_sys_oper_log`      | 复用     | 系统操作审计日志。                                     |
| `us_sys_login_log`     | 复用     | 登录审计日志。                                       |
| `us_sys_config`        | 复用     | 系统级通用参数配置。                                    |

功能权限由 `us_sys_role_menu` 和 `us_sys_menu.perms` 判断，数据权限由 `us_sys_role.data_scope` 和可选的
`us_sys_role_dept` 判断；两者必须同时满足。

## 18. 主要基数约束汇总

| 主表         | 从表或关联表                     | 基数  | 约束说明                                             |
|------------|----------------------------|-----|--------------------------------------------------|
| 机构         | 系统部门、成员、角色、岗位、标签、课程、考试、培训等 | 1:N | 业务聚合根、部门和角色必须归属机构。                               |
| 系统部门       | 子部门                        | 1:N | `us_sys_dept.parent_id` 形成机构内无限级树，禁止跨机构挂接。       |
| 用户         | 系统角色                       | M:N | 由 `us_sys_user_role` 表达，用户部门和角色必须属于同一机构。         |
| 系统角色       | 功能权限                       | M:N | 由 `us_sys_role_menu` 关联 `us_sys_menu.perms`。     |
| 系统角色       | 自定义部门范围                    | M:N | 仅 `data_scope=CUSTOM` 时由 `us_sys_role_dept` 表达。  |
| 成员         | 标签、岗位                      | M:N | 分别由成员标签、成员岗位关联表表达。                               |
| 课程         | 分类                         | M:N | 一门课程可属于多个分类。                                     |
| 课程         | 发布版本、章节、内容项、开课             | 1:N | 每次发布生成不可变版本；课程定义可被多次开课。                          |
| 课程开课       | 课程发布版本                     | N:1 | 开课发布时固定版本，后续课程发布新版本不自动升级。                        |
| 开课         | 报名                         | 1:N | 同一开课与用户最多一条有效报名。                                 |
| 报名         | 内容项进度、学习会话                 | 1:N | 汇总进度与明细会话分离。                                     |
| 题库         | 知识点                        | M:N | 一个题库可覆盖多个知识点。                                    |
| 题库         | 题目                         | 1:N | 题目主标识归属一个题库。                                     |
| 题目         | 题目版本                       | 1:N | 历史版本不可覆盖。                                        |
| 试卷         | 试卷版本                       | 1:N | 考试绑定具体版本。                                        |
| 试卷版本       | 题目版本                       | M:N | 由版本题目表表达；随机卷另保存抽题规则。                             |
| 考试         | 考试人员                       | 1:N | 同一考试、用户和业务上下文最多一条有效人员记录；分配来源只作追溯。                |
| 考试人员       | 考试尝试                       | 1:N | 首考、补考、练习重做均独立保存。                                 |
| 考试尝试       | 尝试题目、答案、防作弊事件              | 1:N | 交卷后保留完整快照和事实。                                    |
| 培训类型/标准/模板 | 培训计划                       | 1:N | 同机构直接引用，跨机构须有效授权；计划冻结来源快照，之后不回写来源资源。             |
| 培训计划       | 计划阶段、参训人员、附件               | 1:N | 培训计划是培训执行聚合根。                                    |
| 培训计划       | 课程、考试、线下场次                 | 1:N | 由计划内容和来源字段串联各执行模块；培训直投直播本期不实施。                   |
| 培训计划内容     | 课程开课、考试、线下场次               | 1:N | 各执行实例通过 `plan_content_id` 直接关联。                  |
| 参训人员       | 课程报名、考试人员                  | 1:N | 各执行人员通过 `training_participant_id` 直接关联，支撑培训结果归集。 |
| 课程/考试/培训   | 证书                         | 1:N | 达标后按签发规则幂等生成。                                    |
| 问卷         | 发布版本、题目、投放实例               | 1:N | 每次内容发布生成不可变版本；同一版本可按不同业务来源、受众和时间窗口多次投放。          |
| 问卷投放实例     | 参与人、答卷                     | 1:N | 同一实例下每位用户最多一条有效参与记录和一份有效答卷，不同实例互不限制。             |
| 评价表单       | 表单版本                       | 1:N | 评价记录绑定固定版本。                                      |
| 参训人员       | 综合成绩计算批次                   | 1:N | 重算追加不可变批次；跨表单版本最多一个正式批次，每批次保留逐来源贡献。              |
| 证书模板       | 模板版本                       | 1:N | 元素和已签发证书均绑定固定模板版本。                               |
| 培训计划       | 培训档案                       | 1:1 | 一个计划一个档案主记录，可有多个档案版本。                            |
| 培训档案       | 档案版本                       | 1:N | 更新档案新增版本，不覆盖已封存版本。                               |
| 预警规则       | 预警                         | 1:N | 同一被监管机构、可选计划和检测周期按确定性去重键最多形成一条有效预警。              |
| 预警         | 证据、处置流水                    | 1:N | 证据和操作历史只追加。                                      |
