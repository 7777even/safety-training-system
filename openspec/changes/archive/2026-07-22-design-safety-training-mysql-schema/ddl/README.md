# MySQL DDL 设计草案

本目录把 `../design.md` 的字段级模型展开为按模块拆分的 MySQL 8.0 DDL 草案，便于数据库设计审查。
当前 DDL 共创建 130 张表，其中 129 张培训业务表、1 张系统数据权限关联表；另包含对 `us_sys_dept`、`us_sys_role` 的目标结构扩展。
新建表均包含中文表注释，全部业务字段和公共审计字段均包含中文字段注释；类型/状态字段在设计已明确时同步列出允许值，尚未确认的业务枚举明确保留为暂定项。

本期明确不实施人脸供应商和仿真协议能力，因此不包含任何 `sts_common_face_*`、`sts_sim_*` 表，也不保留课程、考试、培训对这些表的逻辑引用。
培训组织、角色、用户角色和功能权限统一复用系统部门与系统 RBAC；`00_system_permission_extension.sql` 增加机构/角色范围字段和
`us_sys_role_dept`，不再创建重复的 `sts_org_unit` 或培训角色权限表。

完整的表数量、逐表职责、上下游关系和主要基数约束见 [`table-catalog.md`](./table-catalog.md)。

## 审计类别

- A：可修改业务实体，带完整创建/更新审计、`deleted` 和 `version`。
- B：关联关系，带创建审计和业务唯一键，解绑时物理删除。
- C：不可变日志、流水或版本快照，只带创建审计。

## 审查重点

- `organization_id` 隔离与跨机构授权是否符合最终权限架构。
- 课程发布后的目录变更、学习完成和学时计算规则。
- 试卷与考试的时长、及格线、多选评分优先级。
- 答卷快照、补考成绩、人工改分及成绩发布状态机。
- 培训签到、计划课程/考试内容权重、同类型平均或加权平均、综合成绩来源权重与加减分、证书编号、归档和预警口径；缺勤否决和复杂公式留待后续升级。
- 人脸和仿真已从本期表设计移除；后续启用时必须创建独立 OpenSpec Change，不得直接补 migration。
