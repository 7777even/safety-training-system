## Task 1：完成机构、成员与公共业务支撑能力

- **Owner**: AI（实施）；产品、架构与权限负责人（确认）
- **输入**: 已确认的系统组织/RBAC 复用决策、机构边界、成员归属、角色数据范围与资源授权规则，design 中系统扩展及组织/通用支撑表
- **输出**: 系统部门树、机构成员、系统角色功能权限与数据权限、标签岗位、参与范围、资源授权、提醒消息、分享与积分能力
- **前后端影响**: 前端扩展现有部门和角色管理的数据范围配置，增加统一人员选择与资源授权模型；后端扩展系统组织/RBAC
  并建立统一数据权限执行组件，所有后续模块复用
- **API 依赖**: 先在 `docs/api/` 扩展系统部门、角色、角色数据范围 Contract，并定义机构成员、参与范围和公共资源 API Contract
- **数据影响**: 通过正式 migration 扩展 `us_sys_dept`、`us_sys_role`，新增 `us_sys_role_dept` 及保留的 `sts_org_*`、
  `sts_common_*` 表；必须先制定现有部门/角色数据回填方案，不直接修改生产数据
- **验收标准**:
  - 系统部门、标签、岗位和人员可组成包含/排除范围并生成冻结名单
  - 培训组织、角色、用户角色和功能权限分别复用 `us_sys_dept`、`us_sys_role`、`us_sys_user_role`、`us_sys_role_menu` 和
    `us_sys_menu.perms`
  - 角色可配置全部、全机构、本部门、本部门及下级、自定义部门或本人数据范围，自定义范围保存于 `us_sys_role_dept`
  - 多角色数据范围只合并授予当前功能权限的角色并取并集，不能通过无当前功能权限的宽范围角色扩大访问
  - 仅账号编码严格等于 `superAdmin` 的有效用户绕过功能和数据权限，其他用户严格按角色自身配置执行
  - 普通账号只能绑定其主部门所属机构的角色，不能跨机构分配角色或切换任职机构
  - 列表、详情、统计、导出和异步任务使用同一服务端数据权限规则，越权 ID 查询返回无权限或不存在
  - 机构归属和跨机构资源授权可审计且不能越权访问
  - 业务实体、关联和流水表符合审计、逻辑删除和唯一索引规范；“不限/非适用”字段使用已定义的非空哨兵值
  - 机构维度列表、统计、权限过滤和清理查询具有 `organization_id` 最左前缀的目标组合索引
  - 逻辑外键写入校验、发布检查、删除保护、跨模块幂等事件和孤儿巡检职责明确
- **测试方式**: Service 单元测试、权限与数据隔离测试、Testcontainers MySQL migration/唯一约束/索引集成测试
- **状态**: 待确认

## Task 2：完成素材、课程开课与学习追踪能力

- **Owner**: AI（实施）；产品与课程业务负责人（确认）
- **输入**: Task 1、课程目录/完成规则/素材处理确认项、design 中素材和课程表
- **输出**: 素材转码、课程分类与目录、素材/知识点/题库/考试/练习/直播编排、开课、选课、学习进度和学习明细能力
- **前后端影响**: PC 端管理课程，学员端查看并学习课程；后端新增课程与学习领域服务
- **API 依赖**: 先定义素材、课程、开课、报名和学习记录 API Contract；考试项仅依赖 Task 4 已声明的契约
- **数据影响**: 新增 `sts_asset_*`、`sts_course_*` 表及 migration；学习会话结束后冻结，课程实体逻辑删除
- **验收标准**:
  - 课程定义和开课实例分离，目录支持层级、稳定排序、知识点/题库关系和直播场次
  - 课程考试、专项练习和题库练习内容项直接关联对应考试配置；每个题库项只关联一个题库，并使用来源题库一致的 `BANK_PRACTICE`
    执行链；课程来源考试人员可追溯到开课、内容项和报名，不创建课程专用答卷
  - 每次课程发布生成不可变版本快照，开课发布后固定 `course_version_id`，后续课程修改不影响既有开课和学习记录
  - 学时、断点、素材规则、必修考试/练习和完成结果可追溯
  - 转码中素材不能被课程有效发布，历史学习记录不受素材编辑影响
- **测试方式**: 课程状态机与完成规则单测、素材转码契约测试、真实 MySQL 目录/进度/并发更新集成测试
- **状态**: 待确认

## Task 3：完成题库与试卷组卷能力

- **Owner**: AI（实施）；产品与考试业务负责人（确认）
- **输入**: Task 1、题型判分和导入规则确认项、design 中题库与试卷表
- **输出**: 题库分类、知识点、题目版本、批量导入、题目资源、试卷版本及固定/随机/自定义组卷能力
- **前后端影响**: PC 端新增题库和试卷维护；后端提供版本化内容与组卷服务
- **API 依赖**: 先定义题库、题目、导入校验、试卷与预览 API Contract
- **数据影响**: 新增 `sts_question_*`、`sts_paper_*` 表及 migration；已被使用的版本只读
- **验收标准**:
  - 五类理论题及其选项、填空答案、关键词和附件能够无损表达
  - 三类试卷的题库范围、题型数量、单题分值和题目顺序可重现
  - 不限难度和不限知识点的抽题规则不能利用 `NULL` 重复写入，题目非选项素材也能稳定去重
  - 题目或试卷编辑创建新版本，不覆盖历史版本
- **测试方式**: 题型校验/自动判分/版本规则单测，导入契约测试，MySQL 唯一约束与随机组卷集成测试
- **状态**: 待确认

## Task 4：完成考试、练习、补考与批阅能力

- **Owner**: AI（实施）；产品、考试与权限负责人（确认）
- **输入**: Task 1、Task 3，考试类型/时长冲突/补考/成绩发布/防作弊确认项，design 中考试表
- **输出**: 考试发布、人员名单、答卷快照、作答、自动判分、人工批阅、补考、防作弊、成绩发布和练习重置能力
- **前后端影响**: 管理端配置考试并阅卷，学员端参加考试/练习；后端建立统一测评执行引擎
- **API 依赖**: 先定义考试配置、作答、交卷、批阅、成绩和分析 API Contract；同步 Mock 和多端共享类型
- **数据影响**: 新增 `sts_exam_*` 表及 migration；考试人员增加业务上下文和人员快照，尝试增加执行参数快照，练习重置关联考试人员；答卷、批阅和事件流水不可覆盖删除
- **验收标准**:
  - 每次作答有独立题目/选项快照，固定和随机试卷均可复盘
  - 题库练习和线下考试不绑定固定试卷版本时，尝试仍冻结试卷来源、总分、及格线、时长、题序和多选计分策略
  - 同一考试用于不同开课或内容项时，考试人员、尝试和成绩按课程报名上下文隔离，课程报告不混入独立考试或培训考试成绩
  - 同一考试用于同一参训人的不同培训计划内容项时，使用 `plan_content_id` 形成不同培训上下文，考试人员和成绩互不覆盖
  - 考试人员按考试、用户和业务上下文唯一，重复分配幂等；姓名、机构和部门等人员档案按创建时快照展示
  - 练习重置只能作用于明确考试人员的当前上下文，不影响同一用户的其他课程、培训或独立练习
  - 考试结果通知接收人由管理员直接选择并冻结，不查询或推导部门负责人、直属上级、角色或岗位
  - 客观题、主观题、待阅卷、待发布、已发布及补考状态转换可审计
  - 交卷原因、防作弊事件、证据文件和设备环境可关联到具体尝试
- **测试方式**: 状态机/判分/补考/防作弊单测，API 并发与幂等测试，Testcontainers MySQL 完整作答批阅集成测试
- **状态**: 待确认

## Task 5：完成培训计划与线下执行能力

- **Owner**: AI（实施）；产品与架构负责人（确认）
- **输入**: Task 1、Task 2、Task 4，培训标准/签到确认项，design 中培训表
- **输出**: 培训类型、标准、模板、计划阶段、参训人员、线下签到成绩、评价和奖惩能力
- **前后端影响**: 园区端维护标准，机构端办培训，学员端执行培训
- **API 依赖**: 先定义培训标准、模板、计划、参与、签到和结果契约
- **数据影响**: 新增 `sts_training_*`；培训计划保存跨机构资源来源机构、类型/标准/模板快照和正式综合成绩计算批次引用；本期不创建
  `sts_sim_*` 表或引用
- **验收标准**:
  - 模板到实际计划复制后互不回写，阶段内容按顺序执行
  - 园区作为培训类型、标准和模板所有方，企业或培训机构仅可在有效监管关系和资源授权下使用；创建或发布计划时冻结来源园区、资源快照与哈希，授权到期不改写已发布计划
  - `sts_training_type` 直接承载不少于 25 种内置培训类型；具体清单和字段值由需求方在实施阶段提供
  - 正式培训类型初始化使用稳定 `type_code` 并保证幂等，不硬编码未知的自增机构 ID
  - 计划内容能直接关联课程、考试和线下执行实例，各执行人员能直接关联参训人员
  - 计分课程/考试计划内容能够分别保存权重和同类型聚合方式，培训计划发布后锁定计分配置
  - 参训名单、线上结果、线下签到/成绩、附件、评价和奖惩能形成完整培训结果
- **测试方式**: 模板实例化/计划状态/签到规则单测，跨模块契约测试，MySQL 培训闭环集成测试
- **状态**: 待确认

## Task 6：完成证书、问卷、评价、档案与监管闭环能力

- **Owner**: AI（实施）；产品、监管与合规负责人（确认）
- **输入**: Task 2、Task 4、Task 5，证书/问卷/基础综合评分/评价/归档/预警规则确认项，design 中相应表
- **输出**: 证书模板与签发、问卷反馈、基础权重与加减分综合评价、专家查课、培训归档、监管预警及查询投影
- **前后端影响**: 三端均增加结果和监管能力；统计页面基于统一事实和归档查询
- **API 依赖**: 先定义证书、问卷、档案、分析与预警 API Contract，明确指标口径、权限和示例
- **数据影响**: 新增 `sts_certificate_*`、`sts_survey_*`、`sts_evaluation_*`、`sts_archive_*`、`sts_regulation_*` 表及
  migration
- **验收标准**:
  - 证书签发来源、模板版本和内容快照可追溯，问卷匿名展示不丢失内部防重复提交标识
  - 每次问卷发布生成不可变版本快照和独立投放实例；参与范围和结果可见范围以 `business_type=SURVEY_INSTANCE` 解析为实例专用
    `BOUND/FROZEN` 范围，同一版本可重复投放，参与人和答卷固定实例与版本
  - 每个计分课程/考试计划内容可独立配置权重，同类型采用平均或加权平均；补考读取考试执行已经确定的正式最终成绩
  - 培训计划每种评价用途只绑定一个固定表单版本；综合成绩每次计算追加不可变批次和逐来源贡献明细，重算保留历史且同一参训人跨表单版本最多一个正式批次，不包含缺勤否决或自定义公式引擎
  - 个人、机构和一期档案来自同一已确认归档事实
  - 监管预警能够定位规则、机构、培训计划、检测周期、证据和处置流水；并发或调度重试只产生一条有效预警，且不会重复追加相同来源事实的证据
- **测试方式**: 签发/问卷/归档/预警规则单测，权限脱敏测试，跨模块端到端与 Testcontainers MySQL 集成测试
- **状态**: 待确认
