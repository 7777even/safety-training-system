# 建立项目知识库基础资产任务

## Task 1：建立培训业务全景与角色协作基线

- **Owner：** AI（文档起草）；产品/架构负责人（确认）。
- **输入：** 安全教育培训系统泳道图、功能清单与现有项目规范。
- **输出：** 系统总览、系统背景、用户角色和业务流程文档。
- **前后端影响：** 无代码影响；为后续多端路由、鉴权和任务中心能力提供共同业务语境。
- **API 依赖：** 无；后续接口需以本任务沉淀的角色与流程为业务输入。
- **数据影响：** 无数据库变更；仅描述概念对象。
- **验收标准：** 明确三类系统角色；完整覆盖既定八步业务闭环；未确认规则标“暂定”。
- **测试方式：** 人工对照泳道图，核对每个泳道职责和跨端数据流均有对应描述。

## Task 2：建立按领域拆分的培训能力基线

- **Owner：** AI（文档起草）；产品/架构负责人（确认）。
- **输入：** 企业/培训机构端、学员端与园区监管端功能清单。
- **输出：** 业务架构和功能模块文档。
- **前后端影响：** 无代码影响；后续前端模块和后端服务必须按领域能力而非页面或单接口拆分。
- **API 依赖：** 无；后续每个领域能力须先在 `docs/api/` 定义 API Contract。
- **数据影响：** 无数据库变更；标识后续可能产生的数据领域。
- **验收标准：** 覆盖培训标准、资源、计划、学习、考试、分析、档案证书、监管与基础支撑；不以页面为模块边界。
- **测试方式：** 人工检查模块名称和描述是否均对应业务领域，且功能清单中的核心能力能归属到一个领域。

## Task 3：建立概念领域模型与统一术语基线

- **Owner：** AI（文档起草）；产品/架构负责人（确认）。
- **输入：** 已确认角色、业务闭环与领域模块。
- **输出：** 架构领域模型、数据库概念领域模型、业务术语表和技术架构文档。
- **前后端影响：** 无代码影响；后续 DTO、VO、Entity、前端共享类型和 API 命名须引用统一术语。
- **API 依赖：** 无；后续 API Contract 在定义资源时需引用概念模型并补充字段级约束。
- **数据影响：** 无 migration；禁止据此直接创建表或字段。
- **验收标准：** 领域模型只描述概念对象和关系；术语前后一致；技术架构与现有工程技术栈一致。
- **测试方式：** 人工交叉检查角色、模块、流程、模型和术语中的关键名词是否一致；检查未出现 DDL、表字段或接口定义。
