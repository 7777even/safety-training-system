# 项目知识库基础资产规格增量

## 新增规则

### 规则：长期业务知识文档的最低集合

项目长期知识库应维护系统总览、业务架构、概念领域模型、技术架构、业务背景、角色、业务模块、业务流程、数据库概念模型和业务术语。

### 规则：三类系统角色

系统业务知识必须区分园区监管端、企业/培训机构端和学员端。任何后续业务能力 OpenSpec 必须说明涉及的角色及其职责边界。

### 规则：培训业务闭环

后续培训业务能力应能够映射至以下闭环之一或多个环节：培训标准制定、培训计划、课程学习、考试、成绩分析、档案、证书、监管预警。

### 规则：按领域拆分能力

长期知识库与 OpenSpec 任务必须按业务领域或业务能力组织，不得仅按页面、接口、数据表或技术层拆分。

### 规则：概念模型不等于物理数据库设计

`docs/database/domain-model.md` 仅记录概念实体及关系。数据库表、字段、索引和迁移必须通过独立 OpenSpec design 确认，并通过
`database/migration/` 实施。
