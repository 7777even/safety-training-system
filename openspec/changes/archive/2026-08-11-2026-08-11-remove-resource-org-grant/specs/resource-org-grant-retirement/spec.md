# 资源授权退役规格

## ADDED Requirements

### Requirement: 资源机构授权

系统 MUST NOT 支持资源所属机构向其他机构授予 `VIEW`、`USE` 或 `MANAGE`，且 MUST NOT 维护授权等级、授权有效期或授权状态。

#### Scenario: 资源授权接口下线

- **WHEN** 调用方访问 `/api/common/resource-grants/**`
- **THEN** 系统不存在对应路由
- **AND** 不提供兼容接口或替代授权接口

#### Scenario: 删除历史授权数据

- **WHEN** 退役 migration 执行
- **THEN** 系统删除资源授权表及其中全部记录
- **AND** 不把历史授权转换为其他权限或资源副本

### Requirement: 课程跨机构访问

系统 MUST NOT 允许机构通过资源授权查看或使用其他机构课程。

#### Scenario: 访问其他机构课程

- **WHEN** 当前机构请求其他机构课程详情
- **THEN** 系统按资源不可见处理
- **AND** 响应不泄露课程名称、所属机构或状态

### Requirement: 业务资源严格按机构隔离

课程、考试、培训类型、培训标准和培训模板 MUST 只允许其所属机构查看、引用和管理。父子机构、监管身份、客户端参数或历史授权记录
MUST NOT 扩大资源边界。

#### Scenario: 引用当前机构资源

- **WHEN** 当前机构引用属于本机构且满足既有业务状态的资源
- **THEN** 系统按既有业务规则继续处理

#### Scenario: 引用其他机构资源

- **WHEN** 当前机构提交其他机构的课程、考试、培训类型、培训标准或培训模板 ID
- **THEN** 系统拒绝读取或引用
- **AND** 不通过跨租户旁路加载资源
- **AND** 不泄露目标资源信息

### Requirement: 系统菜单与权限必须对应真实后端能力

系统菜单和可分配权限 MUST 不再包含资源授权菜单及 `common:grant:*` 权限。

#### Scenario: 读取系统菜单

- **WHEN** 管理员或普通角色读取可用菜单与权限
- **THEN** 结果不包含资源授权节点或权限码
- **AND** 既有角色菜单关联中不存在指向已删除节点的记录
