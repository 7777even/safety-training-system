# Proposal：移除跨机构资源授权能力

## 背景

系统当前提供“系统管理 → 资源授权”，允许资源所属机构向其他机构授予 `VIEW`、`USE` 或 `MANAGE`，并通过
`sts_common_resource_org_grant` 支撑课程、考试和部分培训基础资源的跨机构读取或引用。

产品现已确认本期不需要该能力。继续保留授权
API、菜单、跨租户旁路读取和授权表，会扩大机构隔离边界并增加无业务价值的维护成本。因此需要完整退役后端资源授权能力，并把相关业务引用统一收敛为当前机构资源。

## 目标

1. 删除资源授权 CRUD、授权校验 API、权限码和后端领域实现。
2. 删除课程、考试及培训基础资源的跨机构授权读取路径，统一执行严格机构隔离。
3. 通过新增 migration 删除资源授权菜单、角色菜单关联、授权表及其中全部存量授权记录。
4. 从当前全量 schema、初始化菜单、OpenAPI 和长期文档中删除仍然宣称该能力可用的内容。
5. 以零 DB 测试、MySQL IT、契约检查和引用扫描证明退役完整且未留下跨租户旁路。

## 用户价值

- 机构只能读取和引用本机构资源，权限边界更明确。
- 系统管理不再展示无产品需求的资源授权入口。
- 删除不再使用的 API、数据表和跨租户读取机制，降低误配置与越权风险。

## 功能范围

1. 退役 `/api/common/resource-grants/**` 全部接口及 `common:grant:*` 权限。
2. 删除 `com.sts.grant` 实现、对应零 DB/IT，以及仅为跨机构授权服务的跨租户读取组件。
3. 课程详情、课程考试内容项、培训类型、培训标准和培训模板只允许当前机构资源。
4. 删除 `sts_common_resource_org_grant` 的租户豁免配置。
5. 新增版本化 migration，清理菜单和角色菜单关联后删除 `sts_common_resource_org_grant` 表。
6. 删除当前全量 schema 中的授权表定义、初始化菜单中的资源授权节点，以及 `docs/api/resource-grant.openapi.json`。
7. 更新路线图、进度表、角色流程、API 清单等当前真相源。

## 非目标范围

- 不修改任何前端页面、前端 API、Mock、路由或 UI；当前执行身份为 `lims`，前端以移除后的 OpenAPI 为准另开。
- 不删除或改写已执行的历史 migration；`V20260724150000__create_regulatory_relation_and_resource_grant.sql` 和
  `V20260801153000__align_menu_tree_with_current_frontend.sql` 保留为历史迁移，新 migration 负责退役。
- 不改写已完成 OpenSpec Change、历史 QA 或归档数据库设计；这些文件保留当时的实施事实。
- 不恢复监管关系能力，也不以父子机构、监管身份或其他共享机制替代资源授权。
- 不新增生产依赖，不修改生产数据库，不提供手工生产 DDL。

## 破坏性影响

1. migration 执行后，`sts_common_resource_org_grant` 及其中全部授权记录被永久删除；恢复必须依赖执行前数据库备份或回滚发布中的备份恢复步骤。
2. `/api/common/resource-grants/**` 不再存在，旧调用方将收到 404。
3. 之前依靠授权访问其他机构课程、考试、培训类型、培训标准或培训模板的调用将不再成功。
4. 系统不提供从旧授权记录自动转换为其他权限或复制资源的兼容方案。

## 待人工确认决策

1. 确认接受删除全部存量资源授权记录，且不做数据迁移或导出。
2. 确认接受资源统一收敛为“仅当前机构可查看、引用和管理”。
3. 确认接口直接下线，不设置废弃期或兼容响应。
4. 确认历史 migration 保留，通过新增 DROP migration 完成数据库退役。
