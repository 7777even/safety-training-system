# Design：专家查课只读回看与一期档案

1. 培训计划“下一步操作”在 `RUNNING` 与 `ENDED` 均提供已有专家查课弹窗；提交按钮仍仅在 `RUNNING` 且有新增、提交权限时出现。只读入口要求计划查看和评价记录查看权限。
2. 一期档案接口的 `expertInspections` 返回当前计划已绑定专家检查版本中已提交的课程记录及冻结项目答案：课程、版本、评价人、提交时间、总分、摘要、项目名称/类型及答案。无绑定或无提交时返回空数组。仅一期档案接口返回该字段，企业和个人档案不扩大可见范围。
3. 档案服务复用现有专家查课摘要、评价记录与表单版本查询，不改变表结构或提交规则。生成一期 PDF 时使用相同事实；已有 PDF 保持原文件，更新档案后生成包含专家查课的新版本。
4. 契约同步 `archive.openapi.json`、前端 `m4-outcome.ts`。页面在一期档案事实区独立显示专家查课，不能并入“综合评价”或影响综合分。

## 权限与数据影响

一期档案保持 `archive:training:list` 鉴权；服务端仅按已校验可见的计划 ID 读取该计划当前绑定版本的已提交记录，不开放任意评价记录 ID 查询。无数据库迁移。历史正式文件不改写。
