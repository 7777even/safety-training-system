# Proposal：优化 PC/H5 PDF 渐进预览

## 背景

后端已经为新 PDF 生成 qpdf 线性化 PREVIEW，并通过受控文件代理支持 HTTP Range。当前 PC 与移动 H5 将 PDF 交给
`@open-file-viewer/core@0.1.33`，该版本会在初始化时依次读取全部页面元信息，并为全部页面创建 DOM；PC
学习页还会在每次滚动时遍历全部页面计算当前页。大 PDF 因此产生过多 Range 请求、主线程布局计算和 DOM 占用，前端没有完整兑现后端线性化能力。

仓库曾尝试通过 pnpm patch 修改第三方产物，但补丁无法稳定安装，且依赖升级时需要持续维护第三方 `dist` 差异，不适合作为长期方案。

## 目标

1. PC Web 与移动 H5 的 PDF 使用项目自有、直接基于 `pdfjs-dist` 的专用预览组件。
2. 采用分页阅读和按页加载，同一时刻只渲染当前页，杜绝初始化阶段遍历全部页面。
3. 保留 Bearer 鉴权、受控 URL、HTTP Range、qpdf 线性化、页码恢复和学习进度上报链路。
4. 删除 `@open-file-viewer/core` PDF 优化 patch 及其 pnpm 注册，依赖可以稳定安装。
5. 用仓库现有 64.6 MB、648 页样本完成浏览器网络和渲染性能验收。
6. 对扁平 Page Tree 的 PREVIEW，在 qpdf 线性化前使用后端已有 PDFBox 重建有界层级，解决 PDF.js 初始化读取大量 xref 的问题。

## 用户价值

- 大 PDF 更快显示第一页，不必等待数百页元信息读取。
- 翻页、缩放和恢复上次阅读页时，页面数量不会线性增加 DOM 和滚动计算成本。
- PC 与 H5 行为一致，加载失败时仍可通过受控入口访问文件。
- 前端依赖安装不再被第三方补丁阻断。

## 功能范围

- PC 素材库、课程管理预览及学员课程学习中的 PDF 预览。
- 移动 H5 学员课程学习中的 PDF 预览。
- PDF 文档加载、当前页渲染、上一页/下一页、页码输入、缩放、旋转、加载/错误/密码状态、资源清理。
- PC 学员课程的 `initialPageNo`、`pagecount`、`pageupdate` 契约保持不变。
- `OpenFileViewer` 继续负责非 PDF 格式；PDF 不再进入其插件链。
- 移除无效 patch 并恢复可重复的 `pnpm install --frozen-lockfile`。
- 记录并后续实施 PREVIEW Page Tree 分层规范化；最终仍由 qpdf 生成并校验线性化文件。

## 非目标范围

- 不修改 qpdf 可执行程序、对象存储、受控 Range 协议或 SOURCE；仅计划调整派生 PREVIEW 的生成顺序。
- 不新增或修改 API URL、字段、错误码、权限或数据库结构。
- 不实现非线性化 PDF 或历史 PDF 的兼容路径；本 Change 以现有在线预览 PDF 已全部线性化为前提。
- 不在本 Change 实现 PDF 搜索、批注、签名、打印、缩略图列表或连续滚动模式。
- App/企业微信原生端继续使用受控打开/下载降级，不在本 Change 内引入原生 PDF SDK。
- 不顺带处理现有学员素材管理权限链问题；该问题涉及 API/权限语义，应另建 Change 决策。

## 依赖与风险

- 复用两端已存在的 `pdfjs-dist`，不引入新的预览技术依赖；移动 workspace 仅显式声明 Uni 构建链已经使用的同版本
  `@dcloudio/uni-components`。
- 分页阅读改变了现有连续滚动交互，但能够提供稳定的常量级 DOM 和明确页码，适合课程断点场景。
- 加密 PDF、损坏 PDF、Range 失败和页面渲染取消必须有明确错误状态，不能静默回退为全量下载或非线性化兼容路径。
- 浏览器性能数据受设备和网络影响，验收同时采用确定性行为断言和真实样本观察，不只使用绝对耗时。
- Page Tree 重建使用后端已有 PDFBox，不新增生产依赖；必须保留页序、页面资源、书签/注释引用并在 qpdf 前后验证页数和结构。
