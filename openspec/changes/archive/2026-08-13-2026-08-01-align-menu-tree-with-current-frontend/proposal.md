# Proposal：按当前前端菜单重排后端菜单树

## 背景

前端提供了当前线上使用的菜单树 `current-online-menu-tree.json`，其目录、页面、路径和组件层级与后端初始化文件
`menus.json` 不一致。后端菜单同时承担 RBAC 权限目录职责，现有 223 个 Controller 授权点不能因展示树调整而丢失。

## 目标

1. 以前端菜单文件为 D/M/C 展示树的真相输入，重排后端菜单目录、页面、路径、组件、图标和顺序。
2. 保留后端全部真实 `@SaCheckPermission` 权限点，并挂到最接近的业务页面或目录。
3. 尽量复用既有稳定菜单 ID，并通过正式 migration 同步已有数据库。
4. 保证新库初始化与存量数据库升级后的菜单树一致。

## 用户价值

管理员登录后看到的动态菜单与当前前端路由保持一致，同时普通角色仍可完整配置后端真实功能权限。

## 功能范围

- 将前端嵌套菜单转换为后端扁平 `id/pid/moduleId` 菜单结构。
- 对齐 D/M/C 节点的名称、路径、组件、图标和排序。
- 保留并重新归属全部后端 F 权限节点。
- 更新 `menus.json`、正式 migration、菜单一致性测试和工程记录。

## 非目标范围

- 不修改 `frontend/`、前端 Mock、页面或联调代码。
- 不新增、删除或修改 Controller API、OpenAPI Contract。
- 不改变权限字符串、角色模型、数据权限规则或数据库表结构。
- 不实现前端菜单中尚无真实后端能力的占位功能。

## 前后端影响

仅后端；前端以 OpenAPI 为准另开。
