# Proposal：补充考试批阅任务与作答成绩分页接口

## 背景

现有考试后端已支持考生作答、客观题自动判分、主观题单题批阅和单次成绩发布，但教师和考试管理人员缺少可发现业务对象的分页入口：

1. 被指定为考试批阅人的教师无法分页找到本人需要处理的主观题作答。
2. 考试管理人员无法分页查看考试下的考生作答、批阅进度和成绩发布状态。
3. 前端只能持有已知 `examAnswerId` 或 `examAttemptId` 后调用单题批阅、Attempt 详情和成绩发布接口，无法形成“查找任务 →
   批阅 → 发布成绩”的闭环。

## 目标

1. 提供当前登录教师的批阅任务分页接口。
2. 提供管理端考试成绩 / 作答记录分页接口。
3. 为两个列表提供稳定的考试、Candidate、Attempt、学员快照、提交、批阅和成绩发布字段。
4. 复用既有考试权限、机构数据范围和批阅人分配事实，不新增权限模型或数据库结构。
5. 在 `docs/api/exam.openapi.json` 形成前端可直接使用的机器可读契约。

## 用户价值

- 教师可以从本人待办进入具体主观题并完成批阅。
- 考试管理人员可以查看考试执行进度、批阅状态和成绩发布状态，并进入 Attempt 详情或发布成绩。
- 前端无需自行拼接 Candidate、Attempt 和人员信息，也无需猜测状态。

## 功能范围

1. `GET /api/exam/review-tasks`

- 仅查询当前登录用户作为考试批阅人的任务。
- 按主观题答案形成可操作的批阅任务。
- 支持考试、批阅状态、学员关键字和提交时间范围筛选。

2. `GET /api/exam/attempts`

- 查询当前权限与机构数据范围内的考试作答记录。
- 支持考试、Attempt 状态、批阅状态、成绩发布状态、学员关键字和提交时间范围筛选。

3. 两个接口均使用统一 `PageRequest` / `PageResult`。
4. 同步 Controller、DTO、VO、Service、Mapper 聚合查询、自动化测试和 OpenAPI。

## 非目标范围

- 不修改现有判分、批阅、成绩发布、补考或练习重置规则。
- 不新增批阅任务表，不改变批阅人分配模型。
- 不提供批量批阅、批量成绩发布、导出或统计接口。
- 不修改数据库结构、migration 或生产数据。
- 不新增权限码或改变既有权限语义。
- 不实施前端页面、Mock 或前后端联调；前端以 OpenAPI 为准另开。
- 不在本 Change 中补充学员正确答案、标准答案和解析字段；该缺陷另按已确认的学员读取规格处理。
