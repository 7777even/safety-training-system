# Design：培训计划准备完成门禁与学员可见性

## 1. 生命周期语义

| 状态 | 管理员含义 | 学员任务列表 | 学员可进入内容 |
| --- | --- | --- | --- |
| `DRAFT` | 编辑计划、内容、评价和参训人员 | 不可见 | 不可进入 |
| `PUBLISHED` | 计划已确认并冻结，等待全部内容安排完成 | 不可见 | 不可进入 |
| `RUNNING` | 培训正式进行 | 可见 | 可进入 |
| `ENDED` | 培训结束，结果已冻结 | 可见 | 不可进入，仅查看结果 |
| `CANCELLED` / `ARCHIVED` | 已取消或归档 | 不可见 | 不可进入 |

`PUBLISHED` 不再被解释为“已向学员开放”。它只保留给管理员继续安排或重试培训内容。

## 2. 管理端操作流

```text
配置人员、阶段内容、评价表单
  → 发布预检
  → 发布计划（PUBLISHED）
  → 安排培训内容
      ├─ 任一内容失败：显示失败项，继续安排；不可开始
      └─ 全部内容成功：显示准备完成；可开始
  → 开始计划（RUNNING）
  → 同步过程结果
  → 结束培训（ENDED）
```

执行面板以“内容总数 / 已安排内容数”作为单一事实来源：

- `0/N`：主操作为“安排培训内容”；
- `M/N` 且 `M < N`：主操作为“继续安排培训内容”，显示未完成数和失败处理入口；
- `N/N`：隐藏安排按钮，突出“开始计划”；
- 没有内容：提示回到“阶段与内容”补充，不能开始。

安排弹窗继续逐项展示成功、复用和失败结果。刷新页面后，摘要仍按真实执行关联和线下场次计算，不以本次接口响应是否还在内存中判断准备状态。

## 3. 服务端门禁

开始计划时遍历计划全部内容，而非仅 `isRequired=1` 的内容：

1. `COURSE` / `EXAM` / `QUESTION_BANK` 必须存在与内容类型匹配的 `TrainingExecutionLink`。
2. `OFFLINE` 必须存在对应 `TrainingOfflineSession`。
3. 任一内容缺失时返回 HTTP 409 / `8162`，消息指出尚未安排的内容，不把计划更新为 `RUNNING`。

安排接口仍保持逐项独立事务：某一项失败不撤销其他已成功安排；管理员修复资源或配置后可再次调用，已有安排不重复创建。

## 4. 学员可见与进入规则

- 学员任务列表及详情仅允许 `RUNNING`、`ENDED`。
- `RUNNING` 才允许进入课程、考试、题库练习或查看线下场次。
- `ENDED` 允许读取本人计划和最终结果，进入内容返回 409 / `8154`。
- `PUBLISHED`、`DRAFT`、`CANCELLED`、`ARCHIVED` 的详情返回 404 / `8155`，不返回计划编排。

PC 和移动端任务列表仅保留两个业务文案：`RUNNING` 为“进行中”及“查看并执行”，`ENDED` 为“已结束”及“查看结果”。

## 5. API Contract

保持路径和权限不变，更新 `docs/api/training.openapi.json`：

- `POST /api/training/plans/{trainingPlanId}/start`：说明更新为“全部培训内容均已生成真实执行安排”；补充 `8162` 示例。
- `GET /api/training/learner/tasks` 与参训详情：可见状态从 `PUBLISHED/RUNNING/ENDED` 收紧为 `RUNNING/ENDED`。
- 学员进入内容接口：仅 `RUNNING` 可进入。
- `TrainingLearnerTaskVO.publishStatus` 枚举收紧为 `RUNNING`、`ENDED`，说明字段用于控制执行或结果查看入口。

不新增字段、不改数据库、不新增权限。

## 6. 测试边界

已确认的测试边界：

1. 后端 `start` 公共服务接口：缺任意一个非必修或必修内容安排都返回 `8162`；全部内容已安排才进入 `RUNNING`。
2. 后端学员任务与详情公共服务接口：仅 `RUNNING/ENDED` 可见，`PUBLISHED` 不可见且详情返回 `8155`；仅 `RUNNING` 可进入内容。
3. 前端用户界面：部分安排显示继续安排且禁用开始；全部安排只展示开始；PC/移动学员端不把 `PUBLISHED` 作为可执行任务。

## 7. 风险与兼容

- 已发布但未开始的计划会从学员任务列表消失，这是已确认的业务修正。
- 管理员需要在 `PUBLISHED` 阶段完成全部安排后再开始；失败项保留，重试不会重复创建已有安排。
- 前端的禁用按钮仅改善体验，后端 `start` 的全量校验是最终约束。
