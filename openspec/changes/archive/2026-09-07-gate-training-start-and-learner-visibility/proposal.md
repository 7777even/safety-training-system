# Proposal：培训计划全部准备完成后才开放学员执行

## 背景

培训计划当前在通过发布预检后进入 `PUBLISHED`。培训内容安排在发布后逐项生成，允许部分成功并保留已成功的安排；但学员任务列表把 `PUBLISHED` 与 `RUNNING` 同时视为可见、可执行状态。于是管理员仍在处理安排失败项时，学员端已经出现“查看并执行”，进入未安排内容又会失败。

人工确认（2026-09-07）：**所有培训内容都必须安排成功后才能开始计划**。`PUBLISHED` 表示管理员已确认并冻结计划，正在准备培训内容；只有 `RUNNING` 才表示学员可开始培训。

## 目标

1. 管理员在已发布阶段可清楚处理未安排和失败内容，全部内容准备完成后才出现“开始计划”。
2. 后端开始计划接口强制校验全部内容都有实际执行安排，避免绕过前端直接开始。
3. 学员只在计划执行中看到可执行任务，计划结束后只查看结果。
4. 管理端、PC 学员端、移动学员端和 OpenAPI 使用同一生命周期语义。

## 范围

- 培训计划 `PUBLISHED` / `RUNNING` / `ENDED` / `CANCELLED` 的用户可见语义。
- 所有内容安排完成后的开始门禁、失败提示和重试入口。
- 学员任务列表、详情和进入内容的状态门禁。
- PC 管理端执行面板及 PC/移动学员端任务入口文案。
- `docs/api/training.openapi.json` 的状态、错误码、字段说明与示例同步。

## 非目标

- 不新增计划状态、不改数据库结构、不新增迁移。
- 不改变安排接口“逐项处理、已成功内容保留、失败内容可重试”的行为。
- 不改变草稿阶段人员配置、发布预检、评价计算、结果冻结和取消后事实保留的规则。
- 不实现通知、消息推送或自动重试。

## 功能项追溯

- 功能项 34：培训计划实施。
- 功能项 56：我的培训任务、课程和考试结果。
