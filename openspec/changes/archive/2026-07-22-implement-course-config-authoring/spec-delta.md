# Spec Delta：课程配置与课程编排（草稿态）

## 新增需求

### 课程配置

- 系统必须支持机构内课程分类树的维护，同层分类名称在机构内唯一，排序稳定可控。
- 系统必须支持机构统一课程设置（每机构一条），作为材料学习规则的默认值来源；未配置项按系统默认值生效。

### 课程定义与编排（草稿态）

- 系统必须支持 FR-ENT-CRS-003、FR-ENT-CRS-004 定义的课程创建、基本信息维护和无限级章节目录；本阶段课程始终处于草稿态，不提供发布。
- 系统必须支持 FR-ENT-CRS-005 非仿真、非考试部分的内容编排：本阶段仅开放素材（ASSET）和直播（LIVE）两类内容项；知识点、题库、测验、考试、练习内容项建表预留但禁止写入，放开时机为题库/考试模块交付后。
- 素材类内容项只能引用同机构、未删除且转码成功的素材；未建设能力不得以虚构数据或虚假入口交付。
- 直播内容项与直播场次一对一且同事务创建，覆盖 FR-ENT-CRS-010 的配置侧；学员入口属于开课学习阶段。
- 单/多章节模式切换只调整内容项归属与排序，不得复制或丢失内容项。

## 依赖与约束

- 表结构以 `2026-07-21-design-safety-training-mysql-schema` 已评审 DDL 为唯一依据；实施中需要改表时必须回数据模型 Change
  走变更。
- 机构支撑采用最小方案时，权限执行"功能权限 + 机构隔离 + 创建人"三层；完整数据范围能力由数据模型 Change Task 1 交付后接入，API
  必须预留过滤条件位。
- 全部接口以 `docs/api/` Contract 为唯一协作来源；数据变化必须通过 migration 并同步 Entity、Contract 与本 Change design。
- 课程发布版本、开课、学习事实属于后续步骤（`docs/requirement/course-module-task-plan.md` 步骤 4/5），本 Change 不得提前实现。
