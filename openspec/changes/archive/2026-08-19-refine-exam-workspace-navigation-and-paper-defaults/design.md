# 设计：考试工作台步骤控制与试卷默认配置

## 设计原则

保持既有考试创建和试卷版本选择契约不变，前端只在选择发生时读取已发布试卷版本的详情，并把其规则作为新建考试表单的初始值。

## 步骤导航

- 新建态只允许“设置考试信息”；“人员配置”“发布考试”按钮使用原生 `disabled`，与已有课程和试卷工作台一致。
- 已发布前不展示“考试情况”，维持现有规则。
- 新建态即使通过查询参数访问后续步骤，也统一回落至“设置考试信息”，避免空面板。
- 不新增权限判断或权限语义；现有后端接口继续承担真实校验。

## 试卷默认值

1. 用户在新建考试的基础信息中选择一个试卷版本。
2. 前端调用既有 `GET /api/paper/papers/versions/{paperVersionId}` 获取 `PaperVersionVO`。
3. 仅在成功读取后，将 `durationSeconds`、`passRatio`、`questionOrderMode`、`multiSelectScoring` 写入考试创建表单；既有分类和封面带入逻辑保留。
4. 读取失败时保留表单当前值并提示加载失败，不提交额外字段或自行猜测默认值。
5. 已创建考试的试卷版本控件仍不可编辑，因此不会覆盖既有考试规则。

## API 与数据边界

- API：只调用已有 `GET /api/paper/papers/versions/{paperVersionId}`；不新增或修改接口、字段、错误码、权限。
- 数据：最终仍随既有 `POST /api/exam/exams` 保存；不新增数据模型或迁移。
- 权限：沿用试卷详情接口既有 `paper:paper:list` 权限，不增加前端权限模型。

## 风险与取舍

- 每次主动更换试卷版本会重新带入四项默认规则，这是“默认选择所选试卷”的直接语义；用户仍可在随后编辑表单字段。
- 不在试卷版本候选加载时批量查询详情，避免候选较多时产生无效请求。
