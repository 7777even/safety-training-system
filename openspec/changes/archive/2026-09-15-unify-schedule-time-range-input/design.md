# Design：统一时间范围控件与计划冻结态

> 状态：已完成（2026-09-15）。

## 约束

既有请求模型均保存两个字符串字段，而 Element Plus `datetimerange` 绑定二元数组。因此页面内部以计算属性桥接 `[startTime, endTime]` 与既有表单对象，不新增请求字段，不改变 `value-format="YYYY-MM-DDTHH:mm:ss"`。

## 交互

1. 每个录入时间段只显示一个“时间范围”控件，开始、结束占位分别为“开始时间”“结束时间”，分隔符为“至”。
2. 选择范围后，计算属性将两个值写回原有开始、结束字段；清空范围时两个字段同步清空。
3. 原有必填规则仍校验两个标量字段，保存 payload、编辑回显和 API 字段名称保持不变。
4. 计划基础信息的培训性质禁用条件为 `readonly || historicalNature`：草稿新建和草稿编辑可选择初培/复审；历史未标明计划与非草稿计划不可编辑。

## 验证

- 定向静态回归测试覆盖四个页面的 `datetimerange`、ISO 格式、标量字段桥接和计划只读条件。
- 运行受影响的现有 PC Web 测试文件、typecheck、受影响源码 ESLint 与 `git diff --check`。
- 人工在非生产环境验证：草稿计划可改培训性质，执行中计划不可改；计划、开班、直播、考试开放和补考表单的选择、回显、清空和保存请求均保持开始/结束字段。
