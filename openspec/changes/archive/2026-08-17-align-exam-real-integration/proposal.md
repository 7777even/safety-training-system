# Proposal：考试管理真实联调与全流程契约对齐

## 背景

考试管理 PC Web 正式进入真实接口联调。现有页面仍保留 Mock 优先阶段的两项遗留：

- 新建考试虽已采用详情页卡片外壳，但共享 `ExamDefinitionForm` 仍以单列渲染，未遵循最新详情页的双列表单排版；
- 考试 API 层和人员配置页仍调用已废弃且已从接口文档移除的 `/api/common/audiences`，并向旧的 `bind-audience` 路径提交考生范围。

当前唯一有效接口契约为 `docs/api/exam.openapi.json` 与 `docs/api/person-selection.openapi.json`。其中考生绑定已明确为
`POST /api/exam/exams/{examId}/candidates/bind-selection`，请求体为 `BindSelectionRequest`；人员选择使用
`GET /api/common/person-picker`。本 Change 以这些当前契约为准，完成考试的真实联调整改和端到端验收。

## 目标

1. 新建考试与考试详情的可编辑表单复用当前 `admin-detail-form` 双列布局、整行字段和固定操作栏规则。
2. 考试模块彻底停止调用废弃的受众查询与 `bind-audience` 路径；考生改由当前人员选择器和 `bind-selection` 契约绑定。
3. 在关闭考试 Mock 的非生产环境中验收：创建考试、配置考生与批阅人、发布考试、学员作答、教师批阅、发布成绩、学员查看成绩。
4. 逐项核对当前 OpenAPI 的请求、响应、权限与错误反馈；发现契约缺口时停止实现并提交人工决策。
5. 新建考试时，每份试卷仅提供最新的已发布版本；历史版本只用于已关联考试和版本历史回读。
6. 审计整个考试模块的界面操作、请求字段与当前 OpenAPI 映射；补齐确有界面语义的遗漏字段，不将会话派生或客户端元数据误做成手工输入。
7. 将考试详情改造成与试卷管理详情、课程详情一致的三步工作台：设置考试信息、人员配置、发布考试。

## 用户价值

管理员能以统一布局创建和配置考试；考生选择不再依赖已下线接口；教师和学员可在真实环境完成可追溯的成绩闭环。

## 功能范围

- PC Web 考试创建、详情和人员配置页的布局与接口适配。
- PC Web 与移动端考试管理、教师批阅和学员作答/成绩页面的字段—操作审计与已确认整改。
- 考试模块 Mock 清理、真实请求分支和定向自动化测试。
- 基于当前 `exam.openapi.json`、`person-selection.openapi.json` 的端到端真实联调、QA、双轴 Review 和进度回填。
- 若真实响应与 OpenAPI 不一致，仅记录并提出契约整改，不自行改变后端业务规则、权限或数据库。

## 非目标范围

- 不清理考试模块之外仍可能存在的 `src/api/audience.ts`、课程或培训模块旧受众调用；它们需要各自独立 Change。
- 不新增通知、受众、权限、数据库或考试业务规则。
- 不将 Mock 成功作为真实联调验收证据。
- 不在生产环境创建、修改或删除数据。
- 不将 `userId`、`clientAttemptToken`、`platform`、`operatingSystem`、`browser`、`clientIp`、`publishedBy` 等由登录会话或客户端自动派生的字段暴露为人工选择或输入。
- 不新增考试发布前置校验、接口、权限或数据结构；步骤栏仅组织既有详情、人员配置和发布操作。

## 需人工确认的契约决策

`ExamPolicyRequest.resultNotifyAudienceId` 仍在当前 `exam.openapi.json` 中，但已不存在可供前端读取或选择“受众 ID”的 OpenAPI 操作。为避免重新调用废弃 `/api/common/audiences`，须在实现前确认下列一种处理：

1. 从考试策略的当前前端实现中移除“成绩通知范围”输入，保留该可选字段仅供后端既有数据兼容；或
2. 变更并确认 OpenAPI，定义它与当前 `PersonSelectionRequest` 或新的通知能力之间的正式契约。

本 Change 建议选项 1，因为它不扩展当前接口和权限边界。
