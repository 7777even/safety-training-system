## MODIFIED Requirements

### Requirement: 证书必须按来源合格结果自动生成真实文件

系统 MUST 支持图片底图、证书编号、学员姓名等元素的模板设计与预览，MUST
支持将模板配置到课程、理论考试和培训，并在学员达到既有合格标准时自动、幂等签发真实证书文件。管理员可查询、预览和下载证书；学员只能查看和下载本人证书。

证书的达标来源 MUST 是三类彼此独立的来源：**独立课程、独立理论考试、培训结果**。判据为该来源对象
MUST NOT 属于任何培训计划。每类来源 MUST 以自身主数据标识触发对应规则：课程 MUST 使用 `course_id`，
理论考试 MUST 使用 `exam_id`，培训 MUST 使用 `training_plan_id`。系统 MUST NOT 使用开课实例、考核执行
实例等运行期标识作为规则来源标识。

培训计划内引用的课程与考试 MUST 只参与该培训的结果判定，MUST NOT 因此单独触发课程或理论考试的证书；
课程内考核 MUST 归属课程，MUST NOT 触发理论考试证书。

#### Scenario: 学员首次达标

- **GIVEN** 课程、理论考试或培训已配置启用的证书模板
- **WHEN** 学员第一次达到来源对象的合格标准
- **THEN** 系统自动且幂等地签发证书
- **AND** 生成可预览、可下载的真实图片或 PDF 文件

#### Scenario: 独立课程完成发证

- **GIVEN** 一门不属于任何培训计划的课程已配置启用的 `COURSE` 规则
- **WHEN** 学员的该课程学习状态首次达到 `COMPLETED`
- **THEN** 系统以该课程 `course_id` 为来源签发证书
- **AND** 同一学员、同一课程、同一模板重复判定时 MUST NOT 产生第二张证书

#### Scenario: 独立理论考试通过发证

- **GIVEN** 一次不属于任何培训计划的线上理论考试已配置启用的 `EXAM` 规则
- **WHEN** 该独立指派考生的正式结论达到 `PASSED`
- **THEN** 系统以该考试 `exam_id` 为来源签发证书
- **AND** 无论成绩经人工发布还是自动生效，MUST 都能触发且只签发一次

#### Scenario: 培训内引用内容不单独发证

- **GIVEN** 培训计划引用了课程和理论考试内容，并为该计划配置了启用的 `TRAINING` 规则
- **WHEN** 计划内课程完成或计划内考试通过，而培训整体结果尚未合格
- **THEN** 系统 MUST NOT 为学员签发课程或理论考试证书
- **AND** 仅当该培训整体结果达到合格标准时，系统 MUST 以 `training_plan_id` 为来源签发证书

#### Scenario: 学员查看证书

- **GIVEN** 学员已获得证书
- **WHEN** 学员进入个人中心“我的证书”
- **THEN** 系统只返回该登录学员本人的证书
- **AND** 支持在线查看和下载

## ADDED Requirements

### Requirement: 签发来源候选必须与培训派生对象隔离

证书规则的可绑定来源候选 MUST 只包含可供跨计划复用的稳定来源对象，MUST NOT 把培训运行期自动派生的
对象作为新规则的可选项。

- `COURSE` 候选 MUST 只包含已发布的独立课程主数据。
- `EXAM` 候选 MUST 只包含已发布的线上理论考试主数据，且 MUST 排除由培训计划派生的考试
  （`plan_content_id` 非空者）。
- `TRAINING` 候选 MUST 只包含已发布或进行中的培训计划。

#### Scenario: 培训派生考试不出现在候选中

- **GIVEN** 某培训计划已生成运行期派生考试
- **WHEN** 管理员在签发规则页选择 `EXAM` 来源类型并查询候选
- **THEN** 候选列表 MUST NOT 出现该派生考试
- **AND** 既有已绑定此类来源的历史规则详情 MUST 仍按原 ID 返回并尽力解析名称，不因候选收窄而报错

### Requirement: 同一来源对象只能绑定一条启用规则

签发规则 MUST 保证同一来源对象在启用状态下唯一，避免同一课程、理论考试或培训被配置为向学员签发
多张语义重复的证书。

- 同一 `source_type` 与 `source_id` 组合 MUST 至多存在一条 `status=1` 且未删除的规则。
- 新建规则或更新规则为启用状态时，若该来源已存在其他启用规则，系统 MUST 拒绝该操作并返回明确错误。
- 禁用状态的规则 MUST NOT 参与唯一性约束；管理员 MUST 能通过先禁用旧规则、再启用新规则的方式替换
  来源所绑定的模板。

#### Scenario: 重复配置同一来源的启用规则被拒绝

- **GIVEN** 某独立课程已存在一条启用中的签发规则
- **WHEN** 管理员再为同一课程新建一条启用规则，或把另一条已禁用规则改为启用
- **THEN** 系统 MUST 拒绝该操作并返回「该来源已存在启用规则」类错误
- **AND** MUST NOT 产生第二条启用规则

#### Scenario: 禁用后换绑模板

- **GIVEN** 某来源已有一条启用规则
- **WHEN** 管理员先将其禁用，再为同一来源新建一条启用规则
- **THEN** 系统 MUST 允许新建
- **AND** 同一来源在启用态下仍然只有一条规则
