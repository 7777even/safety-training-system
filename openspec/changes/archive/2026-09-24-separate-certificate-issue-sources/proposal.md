# Proposal：隔离证书签发来源，建立三类独立达标触发

## 1. 背景

功能项 19 原文：

> 证书可配置于**理论考试、课程和培训**，达到合格标准后，系统根据配置进行下发相应的证书。

即证书达标来源为**独立课程、独立理论考试、培训结果**三类。当前 M4 实现存在两处缺陷，导致该语义未真正落地。

### 1.1 签发来源 ID 两侧不一致

规则配置侧（`CertificateIssueRuleServiceImpl`）用**主数据 ID** 作为 `sourceId`，自动签发触发侧
（`CertificateAutoIssueServiceImpl.issueForCompletedContents`）却用**执行实例 ID**：

| 来源类型 | 规则候选 / 校验用 | 触发实际传 |
|---|---|---|
| `COURSE` | `sts_course_course.course_id` | `sts_course_offering.course_offering_id` |
| `EXAM` | `sts_exam_exam.exam_id` | `sts_assessment_execution.assessment_execution_id` |
| `TRAINING` | `sts_training_plan.training_plan_id` | `sts_training_plan.training_plan_id`（一致） |

2026-09-23 最小闭环验收记录中的「`COURSE/2`、`EXAM/38` 自动签发成功」经只读核对确认是**数值撞车**，
不是真实命中：`course_offering_id=2` 恰好等于独立课程 `course_id=2`；`assessment_execution_id=38`
恰好等于独立考试 `exam_id=38`。替换为不撞车的数据后，`COURSE`/`EXAM` 规则一条都不会命中。

### 1.2 培训内引用的课程 / 考试被错误当作独立来源

`issueForCompletedContents` 会遍历培训计划内所有 `COURSE`/`EXAM` 内容项并在其完成时触发对应规则。
按功能项 19 语义，培训内的课程与考试只是培训的组成部分，其达标只应参与「培训结果合格」判定，
不应额外触发一次独立的课程 / 考试证书。

### 1.3 独立学习链路零触发

全仓检索确认：证书自动签发仅有培训域三处调用（`TrainingResultSyncServiceImpl` 第 138、152、203 行）。
课程域、考试域源码**没有任何**证书引用，也没有手工签发端点。因此 `COURSE`/`EXAM` 规则在真实业务中
是永不生效的死规则，独立课程完成、独立考试通过的学员拿不到证书。

## 2. 目标（In scope）

1. 证书自动签发服务归位到证书域，提供与业务域无关的通用入口。
2. 删除培训内 `COURSE`/`EXAM` 内容项的独立触发，培训证书只由「培训结果合格」触发。
3. 新增独立课程完成触发点，以 `course_id` 触发 `COURSE` 规则；达标口径为 `COMPLETED`。
4. 新增独立考试通过触发点，以 `exam_id` 触发 `EXAM` 规则；只对独立指派考生生效。
5. 统一来源候选与触发口径：`EXAM` 候选排除培训派生考试（`plan_content_id IS NOT NULL`）。
6. 前端签发规则页把三类来源彻底隔离，标签与候选不再混淆培训对象与独立对象。
7. 清理已由撞车产生的历史证书脏数据。
8. 收口「同一来源对象只能绑定一条启用规则」，与归档证书设计 8.2 对齐（应用层校验，不改 DDL）。

## 3. 非目标（Out of scope）

- 不修改证书模板设计与发布逻辑，不修改证书查询、预览、下载能力。
- 不新增权限模型、不新增表、不改 DDL、不改 `sts.init.schema-version`。
- 不恢复证书撤销、人工重发、到期管理与客户端任意手工签发（仍按 M4 收口保持移除）。
- 不改变课程、考试、培训各自的既有成绩与合格判定口径，只复用既有结论。
- 不引入签到、档案、学时的联动改动。

## 4. 覆盖功能项

| 功能项 | 原文语义要点 | 本 Change 覆盖方式 |
|---|---|---|
| 19 | 证书可配置于理论考试、课程和培训，达到合格标准后按配置下发 | 三类来源各自建立真实触发点；候选与触发同口径 |
| 50 | 个人中心支持查看证书 | 不改变学员查看路径，仅保证证书能按语义真实产出 |

## 5. 影响面

- **后端**：证书域新增通用自动签发服务；课程域、考试域各新增一处收口调用；培训域移除内容级触发；
  证书规则候选查询增加派生过滤；证书规则新建/更新增加「同来源启用唯一」校验（新错误码 9418）。
- **前端**：`admin/result/certificate/rules` 来源类型与候选选择交互、标签口径；启用规则冲突的提示文案。
- **文档**：`docs/api/certificate.openapi.json` 的来源候选说明、示例与新增错误码。
- **数据**：定向清理撞车产生的事实数据，不改结构；规则存量无需清理（实测无启用重复组合）。
- **风险**：删除内容级触发后，原先依赖撞车拿到证书的历史配置将不再出证；需在验收中明确记录受影响范围。
  新增启用唯一校验后，既有「同来源多模板」配置需先禁用多余规则才能保存新配置。

## 6. 人工确认结论（2026-09-24）

- 方案 A（触发侧对齐主数据 ID + 补独立链路触发点）已确认。
- 独立课程达标口径确认为 `COMPLETED` 即达标，不设及格线。
- 历史撞车脏数据确认一并清理。
- 追加确认（2026-09-24）：同一来源对象**限定只能绑定一条启用规则**，与归档证书设计 8.2 对齐；
  采用应用层校验、保留既有唯一键、不改 DDL。
- 追加确认（2026-09-24）：三类来源必须跑**真实端到端签发验收**，不以单元测试或 Mock 代替。
