# Design：机构层级与机构树数据权限

## 1. 统一机构模型

`sts_org_organization` 是所有机构主体的统一主数据表，`org_type` 只区分职责类型，不创建平行的园区表、企业表或培训机构表。

固定层级如下：

```text
PLATFORM
└── PARK
    ├── ENTERPRISE
    │   └── TRAINING_INSTITUTION
    └── TRAINING_INSTITUTION
```

允许的父子组合：

| 新建机构类型                 | 上级要求                                  |
|------------------------|---------------------------------------|
| `PLATFORM`             | 必须无上级；普通账号不能创建，仅 `superAdmin` 全局旁路可创建 |
| `PARK`                 | 必须直属 `PLATFORM`                       |
| `ENTERPRISE`           | 必须直属 `PARK`                           |
| `TRAINING_INSTITUTION` | 必须直属 `PARK` 或 `ENTERPRISE`            |

上级机构还必须存在、启用、未删除且不能是 `DEFAULT`。机构类型继续创建后不可修改。当前没有修改上级的已实现
API；以后新增移动机构能力时必须复用相同组合规则并校验无环，不能另定口径。

`DEFAULT` 是历史占位记录，可不满足上述层级，但禁止作为新机构上级，也不能据此创建新业务归属。

## 2. 创建机构的权限边界

机构创建同时满足功能权限、数据范围和父子类型规则：

1. `superAdmin` 可创建无上级平台，也可在任意合法上级下创建合法子机构。
2. 普通用户必须具有 `org:organization:add`。
3. 操作者选择的上级机构必须位于当前权限解析出的机构集合内。
4. `PLATFORM` 范围可以在本平台子树中选择合法上级；`PARK` 范围可以在本园区子树中选择合法上级；`ORGANIZATION`
   只能以本人直接所属机构作为上级。
5. 因此园区可创建直属企业或培训机构，企业可创建直属培训机构，培训机构不能创建子机构；任何普通用户都不能创建另一个平台。
6. 父子类型不合法返回 HTTP 400 和稳定业务码；上级超出数据范围返回 HTTP 403，且不得泄露范围外机构详情。

## 3. 唯一所属机构

普通用户的数据权限起点为唯一有效 `sts_org_member.organization_id`：

- 一个未删除用户只能保留一个未删除机构成员档案。
- 成员所属机构必须是真实、启用、未删除且非 `DEFAULT` 的机构；`superAdmin` 和历史 `DEFAULT` 数据按既有兼容规则处理。
- 用户主部门必须属于同一机构。
- 用户绑定的普通角色必须与成员所属机构一致。
- 创建或迁移前如发现一人多机构、无机构、部门与机构不一致或角色跨机构，不允许自动选择，必须输出审计结果并暂停人工治理。

数据库将机构成员唯一约束从 `(organization_id, user_id, deleted)` 收敛为保证单一当前归属的 `(user_id, deleted)`
；逻辑删除后允许重新归属。

## 4. 三类角色数据范围

`us_sys_role.data_scope` 只允许：

| 值              | 展示名 | 解析根节点                     | 可见机构集合     |
|----------------|-----|---------------------------|------------|
| `PLATFORM`     | 本平台 | 当前所属机构自身或向上最近的 `PLATFORM` | 根平台及全部后代   |
| `PARK`         | 本园区 | 当前所属机构自身或向上最近的 `PARK`     | 根园区及全部后代   |
| `ORGANIZATION` | 本机构 | 当前用户直接所属机构                | 仅该机构，不包含后代 |

规则：

1. 仅对授予当前 `permissionCode` 的有效角色解析范围。
2. 多个角色取机构 ID 并集；在单一机构树内，较宽范围自然包含较窄范围。
3. 当前所属机构找不到所需 `PLATFORM` 或 `PARK` 祖先时配置无效，拒绝授权或解析，不能退化为其他范围。
4. 没有授予目标权限的角色时返回无权限，不得回退为本机构，防止空范围条件被错误省略后形成全量查询。
5. `superAdmin` 保留全局旁路，但该旁路不是普通 `dataScope` 枚举。
6. 机构后代必须从真实机构树解析；父子关系变化后权限缓存必须失效。

## 5. 存量迁移

迁移顺序：

1. 审计机构层级、一人多机构、无机构、部门/角色跨机构和未知 `data_scope`；异常时 migration 失败并输出可定位数据，不自动猜测修复。
2. `ALL → PLATFORM`。
3. `DEPT`、`DEPT_AND_CHILDREN`、`CUSTOM`、`SELF → ORGANIZATION`。
4. 删除 `us_sys_role_dept` 数据与表。
5. 更新 `data_scope` 字段注释、开发期 schema 和种子；服务层只接受三种值。
6. 调整成员唯一索引，保证一个用户只有一个未删除所属机构。

测试库 2026-08-06 只存在 `DEFAULT` 历史占位机构、一个 `ORGANIZATION` 角色、零条 `us_sys_role_dept`
，且没有一人多机构；该结果仅作为测试环境审计证据，不替代其他环境上线前审计。

## 6. API Contract

### 6.1 角色 API

`docs/api/system-admin.openapi.json`：

- 创建、修改和查询角色的 `dataScope` enum 改为 `PLATFORM/PARK/ORGANIZATION`。
- 默认值仍为 `ORGANIZATION`。
- 删除请求和响应中的 `customDepts` 及其 schema。
- 业务码 2030 保留为非法数据范围；CUSTOM 专用错误码 2031/2032 从当前契约删除。

### 6.2 机构 API

`docs/api/org.openapi.json`：

- 创建机构 operation 明确四类父子组合、上级可见范围和 `DEFAULT` 禁止规则。
- 请求 example 分别覆盖平台、园区、企业和两种培训机构上级。
- 新增或复用稳定错误码表达父子类型非法和上级超出权限范围。

### 6.3 业务 API

外部 API 不增加客户端可指定的数据范围或机构集合。当前机构和可见机构 ID 全部由服务端登录身份解析。若现有业务 Contract
描述了旧六类数据范围，必须同步改为三类机构树语义。

## 7. 全业务执行规则

- 直接带 `organization_id` 的资源和聚合按可见机构 ID 过滤。
- 明细事实没有 `organization_id` 时，通过其所属聚合的稳定机构字段过滤，不能依赖前端传入机构。
- 列表、详情、统计、导出、批量操作和异步任务使用同一范围。
- 写操作的目标机构必须位于可见集合内；创建数据默认归属当前直接所属机构，除非对应业务已明确允许在可见子树内代管创建。
- 学员本人执行链、教师任务归属、监管关系有效期、跨机构资源授权和发布快照继续作为附加条件；机构树范围不能绕过这些护栏。
- 统计必须先过滤明细事实，再汇总。

## 8. 测试策略

- 零 DB TDD：机构父子组合、创建权限边界、三类范围解析、多角色并集、缺失祖先、无权限不回退、`superAdmin` 旁路。
- Controller/WebSlice：角色 enum、删除 `customDepts` 后的请求响应、非法旧值返回 HTTP 400/业务码 2030；机构创建错误契约。
- MySQL IT：migration 映射与删表、成员唯一归属、机构递归子树、真实 SQL 过滤、跨机构详情/写入拒绝。
- 各业务域按实际接入点执行目标零 DB 与 IT；不得用仅验证 `DataScopeService` 代替业务查询回归。

## 9. 风险与取舍

- 这是破坏性 API 与数据库变更，前端旧请求必须以新 OpenAPI 另开适配。
- `PLATFORM` 不是全系统 `ALL`；多个平台根节点存在时只覆盖当前所属平台子树。
- 机构树成为基础数据权限边界后，错误上级会直接影响可见范围，因此创建时必须强校验，后续移动机构必须另行确认审计与缓存策略。
- 全业务接入范围较大，必须逐域列出证据；发现某业务缺少稳定机构归属时暂停，不得以创建人当前部门或临时默认机构猜测。
