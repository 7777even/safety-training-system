# Proposal：收敛机构层级与机构树数据权限

## 背景

现有机构主数据虽然区分 `PLATFORM`、`PARK`、`ENTERPRISE`、`TRAINING_INSTITUTION`
，但创建机构时只校验上级存在且启用，没有限制父子类型，因此可以形成不符合业务含义的任意层级。

现有角色数据范围同时支持 `ALL`、`ORGANIZATION`、`DEPT`、`DEPT_AND_CHILDREN`、`CUSTOM`、`SELF`
。这些范围混合了机构、部门和个人三个维度，业务查询难以统一执行；素材等机构归属资源也无法稳定解释“本部门”应过滤什么数据。

人工已确认新的统一口径：所有平台、园区、企业和培训机构都是机构主数据；机构按固定树形层级创建；每个普通用户具有唯一所属机构；数据权限只按机构树解析为“本平台、本园区、本机构”。

## 目标

1. 强制真实机构只能形成“平台 → 园区 → 企业/培训机构”层级，培训机构可直属园区或企业。
2. 强制普通用户只有一个当前所属机构，并以该机构作为数据权限解析起点。
3. 将角色数据范围收敛为 `PLATFORM`、`PARK`、`ORGANIZATION`。
4. 所有机构归属业务数据按解析出的机构子树统一过滤，同时继续叠加功能权限、本人执行链、任务归属和显式资源授权等业务护栏。
5. 删除部门、自定义部门和本人角色数据范围及其无用数据结构、API 字段和代码。

## 用户价值

- 平台人员可以在本平台范围内管理园区及其下属机构数据。
- 园区人员可以在本园区范围内管理园区、企业和培训机构数据。
- 企业或培训机构人员可以只管理本人直接所属机构的数据。
- 机构创建时即保证层级合法，不再依赖后续人工纠错。
- 数据权限只依赖稳定机构归属，不因人员部门调整改变历史业务数据的可见边界。

## 功能范围

- 机构创建的父子类型、上级状态和操作者可管理子树校验。
- 普通用户唯一所属机构约束及存量数据迁移前审计。
- 角色数据范围枚举、解析服务、角色 API 和数据库结构收敛。
- 机构树后代解析，以及所有后端机构归属业务查询、详情、写操作、统计、导出和异步任务的数据范围接入审计。
- OpenAPI、migration、开发期 schema、后端种子、自动化测试、QA 和进度记录同步。

## 非目标范围

- 不修改任何前端页面、Mock、联调代码或 UI；前端以 OpenAPI 为准另开。
- 不改变部门树、岗位、标签、参与范围中 `DEPT` 等与“角色数据范围”无关的业务枚举。
- 不新增多机构任职、机构切换或临时切换当前机构能力。
- 不把机构父子关系等同于监管关系；监管有效期、监管业务状态仍由 `sts_org_regulatory_relation` 表达。
- 不取消课程、考试、培训任务的本人执行链、教师任务归属或显式资源授权。
- 不删除 `DEFAULT` 历史占位机构，也不自动把其历史数据猜测迁移到真实机构。

## 影响范围

- `database/migration/`、`backend/sql/schema-system.sql`、`backend/sql/schema-org.sql`
- `backend/sts-service-admin` 机构、成员、角色、数据范围及各业务查询
- `backend/sts-service-admin-init` 角色种子
- `docs/api/system-admin.openapi.json`、`docs/api/org.openapi.json` 及受影响业务 Contract
- 相关 OpenSpec、QA、Retro 和进度记录

## 破坏性变化

- `dataScope` 不再接受 `ALL`、`DEPT`、`DEPT_AND_CHILDREN`、`CUSTOM`、`SELF`。
- 角色请求与响应删除 `customDepts`。
- 删除 `us_sys_role_dept`。
- 存量 `ALL` 迁移为 `PLATFORM`；其他被删除范围迁移为 `ORGANIZATION`。
- 不符合新层级的真实机构不得继续创建；存量异常机构必须在 migration 前完成人工治理，禁止自动猜测上级。
