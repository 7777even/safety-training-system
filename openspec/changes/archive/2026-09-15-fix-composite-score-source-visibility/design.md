# Design：综合成绩来源可见与空来源保护

## 已确认测试边界

1. `CalculationRunService.calculate`：课程未出分、考试 98 与线下 90 已正式产生并标记计分时，计算前刷新后必须使用 98、90，不能写入全 0 批次。
2. `CalculationRunService.calculate`：课程、考试、线下均无可计入的聚合成绩时，必须失败且不插入批次；真实 0 分来源仍允许计算。
3. PC 阶段编排与结果抽屉：题库练习固定不计分；其余三类可在草稿配置，抽屉能区分明细成绩、是否纳入与批次来源快照。

## 后端设计

在 `TrainingResultSyncService` 增加仅按当前参训人重建全部内容投影和聚合的服务入口，计算服务在读取参训人聚合分前调用该入口，再重新读取参训人。该写操作复用既有投影与聚合算法，不改变查询接口的只读边界。

`CalculationRunService` 保留来源的空值语义：只有存在至少一个非空课程、考试或线下聚合分时才转换空来源为展示用 0 并按既有规则计算；三类均为空时返回 409 / `8805`“暂无可计入综合成绩的正式成绩”，不插入计算批次。真实来源分数为 0 时因字段非空，仍可计算。

## 前端设计

计划为草稿时，课程、考试、线下内容在阶段表格中展示计分开关，默认值为 1；题库练习展示“题库练习不参与综合成绩”，并在内容类型切换时强制写入 0。发布后仍只读展示计分资格。

结果抽屉传入已加载的阶段内容快照，并按 `planContentId` 显示“计入综合成绩 / 不计入综合成绩”。综合成绩区域采用来源卡片展示当前聚合成绩，计算历史增加“本批采用来源”列或展开信息。仅当最新待确认批次有至少一个来源分时显示确认按钮；服务端失败消息原样展示。

## 数据与兼容性

无数据库结构变化。已发布/执行中计划的内容冻结，历史 0 分批次保留审计；管理员必须在受控的数据修复流程中处理该计划的计分资格，随后重新计算产生新批次。
