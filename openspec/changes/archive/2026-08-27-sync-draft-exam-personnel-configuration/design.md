# Design：草稿考试人员配置前端同步

## 契约依据

以 `docs/api/exam.openapi.json` 为唯一接口依据：

1. `GET /api/exam/exams/{examId}/reviewers` 对尚无执行对象的草稿考试返回 `200 + []`，页面按正常空态展示。
2. `PUT /api/exam/exams/{examId}/reviewers` 的 `reviewerUserIds` 必传但允许 `[]`，表示清空。
3. `7062` 仅表示非草稿（已发布）考试异常缺少执行对象；前端不得把它解释为“草稿需先发布”。

## 前端方案

- `ExamAssignmentPanel` 保留考生范围必选校验，删除批阅人至少一人的前置校验；保存时始终提交当前 `reviewerIds`，允许空数组。
- `mockReplaceExamReviewers` 仅校验考试存在，保存去重后的数组；空数组覆盖为无批阅人。
- 回归测试锁定上述页面和 Mock 行为，防止恢复旧的非空限制。

## 边界与取舍

- 发布页当前仍根据考生和批阅人数量提示并禁用发布；该发布业务规则不在本次“人员配置接口同步”范围内，除非后端另行更新发布契约。
- 不捕获或吞掉 `7062`：已发布异常仍由统一请求错误处理展示真实服务端错误，方便发现数据一致性问题。
