# Proposal：支持草稿考试配置考生与阅卷人

## Why

统一考核执行模型把考生和阅卷人归属切换为 `assessmentExecutionId`，但独立考试仍到发布时才创建执行对象，导致管理员无法按既有业务顺序在草稿期配置人员。
需要补齐草稿人员配置与发布冻结之间的生命周期，同时保持唯一执行归属。

## What Changes

- 草稿考试无执行对象时，阅卷人查询无副作用地返回空数组。
- 首次有效人员写入按需物化唯一执行对象。
- 发布时在原执行对象上冻结最终快照并保留人员关联。
- 删除草稿时清理尚未投入执行的人员归属。

## Capabilities

### New Capabilities

- `draft-exam-participant-configuration`：定义草稿人员空读、首次保存、发布冻结和草稿删除的一致生命周期。

### Modified Capabilities

- 无。现行统一人员选择、考试规则默认、课程与独立考试来源隔离规格保持有效。

## Impact

- 后端考试服务与统一执行服务的生命周期编排。
- `docs/api/exam.openapi.json` 的草稿空读、空阅卷人数组有效语义和 `7062` 适用条件说明。
- 现有考试、执行对象、考生和阅卷人数据；不改变数据库结构。

## 背景

独立考试的既有业务顺序是“创建考试 → 配置考试人员与阅卷人 → 发布考试”。统一考核执行模型落地后，Candidate 与 Reviewer
改为以 `assessmentExecutionId` 作为唯一执行归属，但独立考试执行对象仍只在发布时创建，导致草稿考试读取或保存人员配置时返回业务码
`7062`，发布前配置链路被阻断。

本问题属于执行对象生命周期与既有考试安排流程没有衔接完整，不是前端调用顺序错误。

## 功能项追溯

- **功能项 16**：考试管理模块能够实现管理员在线安排考试；安排考试时可以设置参与考试的人员，包括直接分配给班级或导入考试学员名单；
  设置阅卷人；设置考试有效时间段、有效时长、有效次数等考试信息。
- **功能项 17（相关语义）**：主观题部分由阅卷人进行在线手动阅卷。本 Change 不修改批阅流程，只保证发布前配置的阅卷人关系在发布后继续有效。

## 目标

1. 草稿独立考试尚无执行对象时，批阅人读取返回成功空列表，不产生数据库写入。
2. 草稿独立考试首次保存非空考生或阅卷人配置时，幂等建立唯一执行归属，并保存人员关系。
3. 人员配置后继续修改草稿，最终发布时必须在原执行对象上按最终考试、资源和策略数据冻结快照，不改变执行对象 ID，不丢失考生或阅卷人。
4. 删除已经配置人员的草稿考试时，完整清理其尚未投入使用的执行归属和人员关系，不留下孤立事实。
5. 保持发布后的编辑规则、接口路径、权限码、响应结构和数据库结构不变。

## 用户价值

- 管理员可以按既有工作流在发布前完成考试人员和阅卷人安排。
- 前端不需要通过提前发布、伪造执行对象或忽略错误绕过人员配置。
- 发布后的作答、批阅和成绩仍稳定归属于同一考核执行对象。

## 功能范围

- 草稿考试批阅人空读语义。
- 草稿考试考生绑定与批阅人整体替换的按需执行归属创建。
- 发布事务内的最终快照刷新、摘要重算和原有关联保留。
- 已物化执行归属的草稿考试删除清理。
- 对应 OpenAPI 错误语义说明、自动化测试、QA / Retro 与进度证据。

## 非目标范围

- 不新增或修改前端页面、Mock、UI 或前端联调；前端以 OpenAPI 为准另开。
- 不新增接口，不修改 URL、HTTP Method、请求/响应字段或权限码；`reviewerUserIds` 保持必传，但允许空数组表达清空。
- 不修改数据库表、字段、索引、约束或 migration。
- 不修改发布后是否允许调整考生/阅卷人的现有规则。
- 不修改课程考核执行对象生命周期、作答、判分、批阅或成绩发布规则。
- 不引入班级导入等尚未纳入当前接口的新增人员选择能力。
