# Proposal：优化试卷工作台并完成真实接口联调

## 背景

现有试卷编辑器已经在一个页面中提供基础信息、组卷、预览和发布能力，但采用连续卡片布局，创建后的下一步和当前所处阶段不够明确，与课程中心“阶段导航 + 单一工作区”的操作体验不一致。

同时，PC Web 已配置关闭试卷 Mock 并保留 `paper.openapi.json` 对应的真实请求分支，但尚未在可用、已授权的后端环境中完成试卷创建、组卷、预览和发布的真实链路验收。

## 目标

1. 将试卷创建/编辑工作流统一为“基础信息 → 组卷配置 → 发布”的单一工作台，并复用新增课程工作台的阶段导航和视觉层级。
2. 基础信息保存成功后自动进入组卷配置；未保存试卷不得进入后续阶段。
3. 在不改变既有 API Contract、权限和数据模型的前提下，使用真实接口完成试卷创建、组卷草稿、预览、发布和版本只读回读的联调与验收。

## 用户价值

管理员可以清楚地了解创建试卷的进度，并在同一工作台按顺序完成配置与发版；真实接口链路可替代 Mock 作为交付证据。

## 功能范围

- PC Web 试卷工作台的阶段导航、创建后跳转、阶段前置限制和“基础信息 / 组卷配置 / 发布”视图。
- 沿用 `docs/api/paper.openapi.json` 的试卷 CRUD、组卷、预览、发布及版本读取接口进行真实联调。
- 与试卷相关的定向自动化测试、目标构建、真实联调记录、双轴 Review 和进度回填。

## 非目标范围

- 不修改后端业务逻辑、数据库结构、权限语义或 `docs/api/paper.openapi.json`；如真实联调发现 Contract 缺口，暂停并另行确认。
- 不修改题库、考试、学员端或移动端流程。
- 不修改当前工作区中由其他人进行的试卷列表页变更。
- 不将 Mock 通过作为真实接口验收证据。

## 人工确认关卡

本 Change 涉及业务工作流和真实环境联调。确认后才进入代码与真实环境操作；真实联调还需要可访问的后端地址及具有 `paper:*` 所需权限的登录会话。
