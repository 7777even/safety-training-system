# 第五批统计设计（已确认）

- 考情按有效候选人去重，应考/参考/提交完成分开；finalScore/finalAttemptId 为成绩真相，未发布/待批阅单列。满分归一化分段 0/60/70/80/90/100，并列名次跳号。客户端按最近正式作答，空为未知；结束前未参考、结束后缺考。XLSX 导出与列表同一筛选及租户范围。
- 课程参与按真实学习/考核行为，时长来自有效学习秒，次数为有效会话；课程/开班/个人/分类分别去重。知识点复用冻结考核题目；新增答卷题目 knowledge_point_ids_snapshot_json，旧缺失保持未知，不回填当前关联。
- 线下课堂展示既有场次、内容、scoreName 和录分，无试卷关联不补上传/作答。统计已/未评分和百分制分布。
- 班级沿用部门，无部门单列；线上/线下按计划内容分别计入，混合人数不可相加。计划+部门+学员去重。
- 培训完成沿用 PASSED/COMPLETED。进行中读取事实并复用判定规则，结束后读取冻结结果；GET 不写库。
- 复用业务查询权限及现行 TenantLineInterceptor；当前代码已移除角色数据范围解析，不另建范围模型。汇总/列表/导出同一基础事实。按具体业务新增查询，不恢复 ops/stats。
- UI 使用清爽现代风、现有后台列表/详情、Element Plus、scoped Less。Figma 映射仅有 Admin Dashboard 通用状态，无第五批专属页面，按已确认本方案与现有规范实施。SVG 饼/条图，Canvas PNG 导出，不引依赖。
- 数据变更同步 init、不可变 migration、schema-version、Entity。新增属性/方法/组件中文注释。
- 零 DB Service/Controller 与前端目标运行测试，新增 SQL MySQL IT；Docker 阻塞如实保留，WorkBuddy 负责真实业务验收。

## 实施细节与 Review 收口

课程执行新增知识点快照写入既有完整执行 JSON 的 `rules.policy.knowledgePointSnapshots`，不复用来源计划内容必填的培训专用题池表。读侧先经现有 Codec 校验摘要、版本和投影，再读取 policy 非持久化视图。答卷冻结按实际题目版本匹配；版本未命中仅在本次冻结时记录关联。历史执行和历史答卷不回填。

全部课程记录保留 WITHDRAWN；有效参与汇总继续排除退课。草稿计划没有正式完成结论，统计为未完成；已结束/归档读取既有冻结结果路径，完整性失败保留既有错误。管理员开启补考不代表学员设备，空摘要归入未知。
